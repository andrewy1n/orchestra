## Problem

Orchestra stamps check-runs `runner: "aff"` and close-batch treats that string as runner-produced evidence. Skills (including phase-end) can hand-type the same stamp. Affidavit already owns real evidence via observation → bind → recheck (and verdict/attest), but Orchestra does not engine-enforce those verbs at close. The package split looks done; the trust boundary is not.

## Approach

**Honest stamp + Affidavit claim gate** (`evidence-authority-approach`).

- Stamp Orchestra-produced check-runs `runner: "orchestra"` (`runner-marker`); close-batch accepts only that marker and refuses legacy `aff` (`legacy-runner-stamp`).
- When an acceptance names a manifest claim, close-batch also requires `aff verdict` and `aff recheck` to succeed (`claim-gate-verbs`).
- Remove Affidavit Python imports from close-batch; assertion-level red via Affidavit CLI only (`oracle-red-surface`).
- Rewrite skills so they do not hand-type `runner: "aff"` for `tdd`/`check` evidence.

Does not add `aff run`. Does not seal check-runs with attest. Skills-only was rejected.

## Exit criteria

- R1–R9 in the phase specification hold under automated tests (and Affidavit CLI for assertion-level red is callable from Orchestra without imports).
- Skills no longer document forgeable `runner: "aff"` check-runs for `tdd`/`check`.
- close-batch refuses `done` for manifest-backed acceptances when verdict or recheck fails.

## Proof

kind: claims

A human reads failing/passing close-batch and skill-scanner tests that show `aff` stamps refused, `orchestra` stamps accepted for operational runs, and manifest closes blocked unless mocked `aff verdict` and `aff recheck` both succeed — plus no `import affidavit` from close-batch.
