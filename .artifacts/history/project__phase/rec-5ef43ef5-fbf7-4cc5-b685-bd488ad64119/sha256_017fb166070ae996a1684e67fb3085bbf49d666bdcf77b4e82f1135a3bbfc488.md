## Problem
Neither adaptive-artifacts nor affidavit ships a pyproject.toml. Install is plugin checkout + PATH symlinks. `uv tool install git+…@tag` needs a proper AA package layout first; PyPI waits until the format settles and outsiders use it.

## Approach
AA-first git+ tool install (`packaging-scope-aa-first`). Restructure adaptive-artifacts into an installable package with `pyproject.toml` and an `adaptive-artifacts` entry point; keep `bin/adaptive-artifacts` and `tools/artifacts.py` as thin shims (`aa-checkout-shims`) so plugin installs and affidavit's `ADAPTIVE_ARTIFACTS_ROOT` discovery keep working. Affidavit changes are README-only for the new install path. Do not publish to PyPI (`pypi-publish-deferred`). AA code changes follow the adaptive-artifacts extension gate.

## Exit criteria
- `uv tool install` from the AA git URL yields a working `adaptive-artifacts` CLI (`--help` plus one store-touching command on a temp store) without a sibling checkout — verified manually or by an integration script in the AA repo.
- Plugin `bin/adaptive-artifacts` and checkout `tools/artifacts.py` still run the CLI against a temp store.
- Affidavit README documents git+ install and states PyPI is deferred; no affidavit `pyproject.toml` added.
- AA packaging amendment is captured and approved in the adaptive-artifacts store before that repo merges.
