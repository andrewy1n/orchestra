## Problem

Phase Landing hardcodes a full local "tier-2" suite as a required merge gate. That policy is opaque and wrong for a plugin: suite cost and meaning vary by repository. Hours are wasted on full runs and flake retries the agent cannot lawfully skip.

## Approach

Decisions: `phase-gate-shape` (contract top-level `phase_gate.suite`), `suite-plugin-defaults` (`mode=none`; configured suites default `gate=required`), `se-workflow-suite-policy` (this repo `full`+`advisory`+README command), `red-first-scope` (tdd only), `suite-policy-authority` (human contract / agent enforce). Spec/design: `verification-policy`.

Replace hardcoded tier-2 with contracted suite policy. Skills/runner/dashboard use `mode|command|gate`; check-run subject `<phase>-suite`. Plugin default is no suite gate. This repo keeps the full suite as advisory (record + finding on fail; do not block Landing).

**Session shape:** more than one
**Executor:** wave 1–3 **subagent**; verification **subagent**
**Human stops:** plan review; Landing merge into `main` (no push)
**Collision notes:** wave 1 owns `contract/project-design.json` (+ live design/resolve). Wave 2: `suite-engine` owns `affidavit/` suite runner + `skills/execute-phase/`; `suite-dashboard` owns `dashboard/` only — do not both edit skills or runner. Wave 3 owns README + suite/gate tests after wave 2.

## Exit criteria

- Contract declares `phase_gate.suite`; plugin default `mode=none`; this repo pins `full`+`advisory`+README full command.
- execute-phase runs/skips/deferred and gates Landing per policy; subject is `<phase>-suite` (tier-2 vocabulary removed from skills/README/dashboard).
- Advisory fail records check-run + finding and does not block merge; required still blocks; `mode=none` skips suite.
- Red-first for `tdd` unchanged; skill↔contract consistency and suite/gate tests green.
