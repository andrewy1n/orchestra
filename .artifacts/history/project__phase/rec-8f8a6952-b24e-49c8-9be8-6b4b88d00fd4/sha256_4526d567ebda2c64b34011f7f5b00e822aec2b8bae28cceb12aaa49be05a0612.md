## Problem

`orchestra install` selects every provider by default, ignores the matrix's
`detect` data, and exposes project/global only as flags. Running it in a repo
with no host footprint writes eight host directories, as happened in the
orchestra checkout. A user cannot see which hosts are present or choose among
them interactively.

## Approach

Standard-library wizard plus host detection, per decisions
`installer-wizard-approach`, `installer-default-detected`,
`installer-detection-both-scopes`, `installer-python-runtime`, and
`installer-wizard-install-only`.

1. Add `installer/detect.py` to report project and global footprints for every
   provider, honoring `--home`.
2. Add `installer/wizard.py` for host multi-select, scope, mode, and plan
   confirmation using only the Python standard library.
3. Change the default: with no host flags, use detected hosts; refuse with
   guidance when none are detected. Keep `--all` explicit.
4. Add `--list`, `--scope {project,global}`, `--interactive`, and
   `--non-interactive`/`--yes`; keep `--global` as an alias.
5. Keep `--uninstall` flag-driven; the wizard is install-only in this phase.
6. Add wizard/detection tests and update README install docs.

Execution order: detection and model; wizard; runner and CLI; tests and docs;
verification last.

Session shape: **one sitting**. Executor: **inline** for every wave because the
installer, CLI, model, and tests are tightly coupled and share files.

Human stops: plan review; Landing merge plus store commit. Push is not a stop.

Collision notes: this phase owns `installer/`, `orchestra/cli.py`,
`orchestra/install.py`, `tests/test_installer.py` (plus new installer test
files), and the README install sections. No parallel tasks on those paths.

## Exit criteria

- On a TTY with no host flags, `orchestra install` shows the host wizard and
  writes nothing until confirmation.
- Detection shows project and global footprints; an empty detection refuses
  with guidance instead of writing eight host directories.
- `--list`, `--scope`, `--interactive`, and `--non-interactive`/`--yes` behave
  as specified; `--only` and `--all` still work.
- Installer tests pass, including new wizard and detection tests; README
  documents the new behavior.
- Landing complete: phase branch merged to `main`; store committed on the
  primary checkout.
