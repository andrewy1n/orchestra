## Problem

The web dashboard shows every phase in a flat stepper. Milestone data is already in the snapshot API, but the UI ignores it, so efforts with many phases are hard to scan.

## Approach

Port the spike Phases block into `dashboard/web/ui`: when the effort has milestones, group phase rows under milestone headers (title, state, done/total), put Ungrouped last, and keep the flat stepper only when there are no milestones. Finished milestones start collapsed; the milestone that contains the selected or default phase stays expanded. First activation of a phase selects and filters tasks; activating the selected phase again opens the phase overlay; All phases remains. Web UI only. Decisions: `web-calm-phase-split`, `milestone-nav-layout`, `milestone-nav-collapse`, `milestone-nav-click`, `milestone-nav-web-only`.

## Exit criteria

- With milestones present, the main pane groups phases under milestone headers; ungrouped phases are last.
- With no milestones, the prior flat phase control remains.
- Default / pin selection still drives the task table; All phases remains.
- Finished milestones are collapsed by default; the current phase's milestone stays expanded.
- `npm test` covers grouping, fallback, and collapse defaults; manual look on this repo's web dashboard confirms `web-calm` grouping.

## Proof

kind: demo

A human opens the web dashboard on this store, selects the `dashboard` effort, and sees phases under the `web-calm` milestone header with older finished milestones collapsed.
