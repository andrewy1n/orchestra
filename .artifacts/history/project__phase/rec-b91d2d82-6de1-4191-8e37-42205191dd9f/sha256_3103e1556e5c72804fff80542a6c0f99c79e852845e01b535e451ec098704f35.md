## Problem

Dashboard `d` clears Needs-you gates in one keypress without showing evidence, confirming, recording a rationale, or guarding the displayed revision. Plan review, manual checks, and accept-risk can be cleared against a record the agent changed after render, and Reject cannot keep the plan-review block while routing back to discuss/plan.

## Approach

Decisions: `dashboard-approvals-scope` (full #8), `approval-revision-guard` (displayed revision, never `@current`). Structured work: specification and design `dashboard-approvals`.

Make dismiss a two-step approval: list `d` opens Needs-you detail only; detail shows kind-specific evidence; confirm modal records Approve/Reject (questions and plan review), Sign (manual check), or Accept risk (finding) with note rules; CLI writes pass the displayed record revision; Reject leaves the continuity-question open and creates a finding (`needs: human`) that routes engage to discuss/plan; supersede the three `dashboard-read-only*` constraints with one allowed-write constraint; add optional contract note fields; update README keys.

Tasks (all `executor: subagent`):

1. `approval-contract` — add optional `answer` (continuity-question), `signed_note` (check-run), `resolution_note` (finding) to `contract/project-design.json` (+ mirror in store design if needed); keep skill↔contract consistency green.
2. `approval-constraints` — supersede `dashboard-read-only`, `dashboard-read-only-dashboard-bugfix`, and `dashboard-read-only-dashboard-features` with one active constraint: human gates only, via CLI, with a recorded decision/note.
3. `approval-dismiss` — extend `NeedsYouItem` with record `revision`; rewrite `dashboard/dismiss.py` for displayed `--expected-revision`, note payloads, Approve vs Reject (Reject creates finding, does not answer the question), Sign, Accept risk; cover with focused unit/pilot tests (`-k approval`).
4. `approval-confirm-ux` — app: list `d` → detail (no write); enrich detail evidence (R2); confirm modal + keys; cancel makes no CLI call; stale-revision message + refresh; README key table. Cover with `tests/test_dashboard_app.py` (`-k approval`).
5. `verify-dashboard-approvals` — phase gate: app entry-point pilots for detail/confirm/actions/revision, plus constraint/README/skill checks.

Collision notes: `contract/project-design.json` belongs to `approval-contract`. Constraint records belong to `approval-constraints`. `dashboard/dismiss.py` and `NeedsYouItem.revision` belong to `approval-dismiss`. `dashboard/app.py` Needs-you list/detail/confirm and README keys belong to `approval-confirm-ux`. Do not touch retry/reviewer/tiered-verification feature code.

Size: more than one sitting. Human stops: plan review; then landing after verification (merge phase branch, commit store on primary).

## Exit criteria

- `d` from list opens detail; no store write without detail + confirm (Textual app pilots).
- Plan-review Approve/Reject, manual Sign, and finding Accept risk record notes as specified; Reject keeps the plan-review block and writes a routing finding.
- Writes use the displayed revision; a stale revision shows a visible message and skips the write.
- Stale `dashboard-read-only*` constraints superseded; README keys updated; skill↔contract consistency green when skills mention the new fields.
