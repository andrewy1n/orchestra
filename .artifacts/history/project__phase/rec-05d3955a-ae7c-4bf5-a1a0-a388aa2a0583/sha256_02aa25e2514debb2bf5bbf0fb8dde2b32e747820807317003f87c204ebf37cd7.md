## Problem

The plugin installs in Claude Code and Cursor, but its skills are not portable
to the other agent harnesses. Every skill reaches outside its own directory:
`../ensure-store.md`, `../kinds-and-focus.md`, `<plugin>/contract/project-design.json`,
`<plugin>/orchestra/project_field.py`, `<plugin>/bin/orchestra`, and
`~/affidavit/bin/aff`. A host that installs a single skill directory — which is
what `npx skills add` and most hosts do — gets broken links. There is also no
installable `orchestra` runtime (no `pyproject.toml`, no console script), hooks
exist only for Claude/Cursor, and `agents/se-reviewer.md` uses Claude-shaped
frontmatter. OpenCode therefore needed a hand-written local install, and
Codex/Gemini/Copilot/Cline/Windsurf cannot install the plugin at all.

## Approach

Portable core plus a provider-matrix installer, per decisions
`portable-skill-references`, `installer-native-tail`,
`reviewer-agent-generation`, and `optional-native-hooks`.

1. Make skills self-contained. A build step compiles
   `shared/ensure-store.md` and `shared/kinds-and-focus.md` into each
   skill's `references/`; skill bodies use `references/...` instead of
   `../...`. A drift test keeps the copies identical to the source.
2. Package the runtime. Add `pyproject.toml` and an `orchestra` console
   script; expose `contract`, `project-field`, and `sessions` so skills
   stop naming `<plugin>/contract`, `<plugin>/orchestra`, and
   `<plugin>/scripts`. Keep `bin/orchestra` as a shim.
3. Replace `sync-plugin.sh` with one installer over a provider matrix:
   `--only`, `--all`, `--global`, `--copy`, `--dry-run`, `--uninstall`,
   idempotent, allowlist-only copying. Native adapters for Claude Code,
   Cursor, and OpenCode; `npx skills add` for every other host.
4. Generate the reviewer agent's frontmatter per host from one canonical
   prompt and restriction set.
5. Install native hook adapters where supported; keep `hook-start` in the
   skills so hosts without hooks stay correct.

Execution order: portable skill refs and CLI packaging run together;
the installer core follows both; native adapters and docs follow the
installer; the verification task runs last.

## Exit criteria

- Each advertised skill installs as a self-contained Agent Skills directory:
  it loads when only its own directory is copied, with no `../` or `<plugin>`
  path dependency (`tests/test_skill_portability.py`).
- `orchestra` resolves from PATH after the documented install; no skill names
  a checkout path, and `orchestra check --help` works from an unrelated cwd
  (integration check).
- One installer covers a provider matrix with `--only`, `--dry-run`, and an
  idempotent re-run, and installs Claude Code, Cursor, OpenCode, and one
  generic `npx skills add` host (`tests/test_installer.py`).
- README documents the host matrix and the install commands; a clean install
  into a temporary HOME loads the skills for at least two hosts (integration
  check).
