## Problem

Red-first is only an instruction today. Agents can close `tdd` acceptances with pass-only check-runs, so tests that never failed still green-close. Dogfood baseline: about 11% of active `tdd` acceptances recorded a fail before the first pass. Builds on check-runner so red and green are machine-recorded.

## Approach

Decisions: red-first-gate-locus (close-batch refusal), red-first-evidence-shape (request-carried), red-first-ordering (git ancestry). Structured work: specification and design `red-first`.

Extend `scripts/close_batch.py` so a `done` transition for `method: tdd` requires a request-carried `red_check_run_id` whose fail precedes the green under git ancestry (or dirty red with `diff_sha256`). Same `needs: human` finding escape as unmet criteria. Update `skills/verify-work/SKILL.md`. Leave `check`/`manual`, validate-strict, and dashboard badges out of scope.

Tasks:

1. `close-red-first` — subagent, 40m. Implement the red-first refusal in `close_batch.py` (request fields, runner checks, ancestry helper using close cwd, dirty-red digest rule, finding escape unchanged). Extend `tests/test_close_batch.py`.
2. `skills-red-first` — subagent, 20m, after `close-red-first`. Update verify-work so the close-request shape and refusal match the engine; drop "engine does not enforce" language. Keep `tests/test_skill_contract_consistency.py` green.
3. `verify-red-first` — subagent, 25m, after all. Prove the exit criteria via the phase checks below. Do not edit the tree.

Session shape: one sitting. Human stops: plan review; then landing after verification. Do not push.

Collision notes: wave 1 owns `scripts/close_batch.py` and `tests/test_close_batch.py`. Wave 2 owns `skills/verify-work/SKILL.md` (and only skill-consistency tests if they need a narrow assert). No parallel wave shares those paths.

## Exit criteria

- `close_batch.py` exits 2 for pass-only `tdd` without a finding, naming the criterion (`uv run --with pytest python -m pytest tests/test_close_batch.py -q -k red_first`).
- Fail→pass with valid ancestry (or dirty red + `diff_sha256`) is accepted; wrong order / non-ancestor is refused (same test file).
- Finding escape permits close and forces `needs: human` (same test file).
- `check`/`manual` close without `red_check_run_id` (same test file).
- verify-work skill matches enforcement; `uv run --with pytest python -m pytest tests/test_skill_contract_consistency.py -q` stays green.
