## Problem

Red-first is only an instruction today. Agents can close `tdd` acceptances with pass-only check-runs, so tests that never failed still green-close. Dogfood baseline: about 11% of active `tdd` acceptances recorded a fail before the first pass. Builds on check-runner so red and green are machine-recorded.

## Approach

decide at discuss — enforce red-first for `tdd` acceptances (likely via `close_batch.py` refusal plus escape hatch), update verify-work skill text.

## Exit criteria

- `close_batch.py` (or the chosen gate) refuses a `tdd` acceptance with only passing check-runs and names the criterion (`tests/test_close_batch.py` or successor).
- Fail→pass in order is accepted; pass-then-fail-at-older-revision is refused.
- Closing without red works only with a documented escape hatch (`needs: human` finding or chosen alternative).
- `check`/`manual` acceptances are unaffected.
- verify-work skill matches the enforced behavior; `tests/test_skill_contract_consistency.py` stays green.
