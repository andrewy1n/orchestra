## Problem

Confirm writes on the web dashboard return HTTP 422. `dashboard/web/app.py` postpones annotations, and `Request` is imported only inside `create_app`, so FastAPI never resolves it and requires a query parameter named `request`. The JSON body is ignored. The page then shows `POST /api/backlog failed: 422` because the validation body uses `detail`, not `error`. POST `/api/needs` fails the same way. Tests drive the stdlib server, which reads the body itself, so the suite stays green.

## Approach

Drop `from __future__ import annotations` in `dashboard/web/app.py` so `Request`, `JSONResponse`, and `HTMLResponse` evaluate inside `create_app`. POST `/api/backlog` and POST `/api/needs` keep `request: Request` and read the JSON body. `fastapi` stays imported inside `create_app`. The phase is ungrouped. Decisions: `web-write-annotation`, `web-write-body-grouping`.

## Exit criteria

A FastAPI TestClient test posts dismiss to `/api/backlog` and a Needs-you confirm to `/api/needs` with a JSON body and no query string, and both return success. GET `/openapi.json` returns 200.

## Proof

kind: demo

Restart the web server, open a backlog item, dismiss it, and confirm it leaves the open list. The same confirm path should clear a Needs-you item.
