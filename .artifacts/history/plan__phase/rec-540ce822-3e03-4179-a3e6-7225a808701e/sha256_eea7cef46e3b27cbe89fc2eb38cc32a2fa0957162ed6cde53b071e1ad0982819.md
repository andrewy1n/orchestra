## Problem

After marketplace install, skills and CLIs still guess where adaptive-artifacts and the se-workflow plugin live (often `~/adaptive-artifacts` or `~/.cursor/plugins/local/se-workflow`), and verify-work still shells out to `scripts/close_batch.py` instead of a se-workflow subcommand. That breaks install-from-plugin and leaves a third CLI surface.

## Approach

decide at discuss — options cover how to resolve plugin roots vs PATH, and how to fold close_batch into the se-workflow CLI.

## Exit criteria

1. Skills and runtime helpers resolve adaptive-artifacts / plugin roots via plugin-root env vars (or a single documented PATH contract) — no remaining `~/adaptive-artifacts` guess as the primary fallback in the three known resolvers — verified by targeted unit tests plus grep gates.
2. `se-workflow close-batch` is the documented entry for building the close NDJSON batch; skills call it (not `scripts/close_batch.py`) — verified by CLI tests and skill-doc / contract consistency checks.
3. Phase Landing merge + store commit completed on primary.
