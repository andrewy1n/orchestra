## Problem

Each package's own tests can pass while a real close still starts another process, or while one package opens a different store than the others.

## Approach

Decide the fixture and the commands at plan-phase. One fixture repo has a local store and a manifest claim. The check drives `adaptive-artifacts`, `aff`, and `orchestra close-batch` through their commands, and drives the same close through the Python functions.

## Exit criteria

Every acceptance on this phase passes. An integration check runs the real commands and the Python close against the fixture. The check fails if that Python close still starts `aff` or `adaptive-artifacts` as a subprocess.

- branch: `phase/library-e2e`
- worktree: `/home/andrewyin/orchestra/.worktrees/library-e2e`
- base: `main`
- close actions: commit code on the phase branch, merge that branch into `main`, then commit the store on the primary checkout. Push is not a human stop. This phase assumes `aa-library`, `affidavit-library`, and `orchestra-callers` are already on `main` in their repos.
