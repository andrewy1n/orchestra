## Description

R1: When an effort's snapshot includes one or more milestones, the main pane shows a Phases block that groups that effort's phases under those milestones instead of the flat phase stepper.
R2: Each milestone group header shows the milestone title (else subject), its state, and its done/total counts from the snapshot milestone row.
R4: When an effort has no milestones, the existing flat phase stepper remains the phase control.
R5: Selecting a phase in the Phases block filters the task table to that phase using the same scoping rules as today's stepper.
R6: An All phases control remains available and shows tasks across every phase of the effort.
R9: Activating the already-selected phase opens the phase detail overlay for that phase.
R10: Phase rows show title when present, otherwise subject, plus a done/total cue for that phase.

## Approach

In `App.svelte`, when `effort.milestones?.length`, replace the flat `.stepper` with a Phases block driven by `groupPhasesByMilestone` and `initialExpandedMilestones`. Milestone headers toggle expand; phase rows call existing `selectPhase` / `openPhase`; keep All phases. When there are no milestones, leave the current stepper path. Add CSS for milestone heads/rows from the spike. Vitest covers grouping markup, flat fallback, select/filter, All phases, and reselect→overlay.
