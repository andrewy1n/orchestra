## Description

R1: Close reads the claim id only from the acceptance payload field `claim`; `claim_id` and the subject are ignored.
R2: An acceptance whose `claim` is empty is not refused for a missing verdict or recheck.
R8: When the acceptance record cannot be loaded, close refuses.
R9: When `claim` is not listed in `.affidavit/manifest.json`, close refuses.

## Approach

In `orchestra/close_batch.py`, rewrite `_enforce_claim_gates`. Load every criterion's acceptance from the store loader; a `LookupError` raises `CloseRefused` naming the criterion. Read the id only from `payload.claim` (strip; no `claim_id` or subject fallback). An empty id skips the gate. A non-empty id not in `_manifest_claim_ids(cwd)` raises `CloseRefused` naming the claim and the manifest. Keep the existing green-revision resolution and call `_run_aff_claim_gate` for a known claim. Update the claim-gate fixtures in `tests/test_close_batch.py` so the id lives in `payload.claim`, and add tests for empty-claim-not-gated, missing acceptance, and unknown claim. Add one real-CLI test in `tests/test_close_batch.py` that seeds a store acceptance whose `payload.claim` is absent from the manifest and runs `bin/orchestra close-batch`, expecting exit 2 and no batch file. Do not edit `tests/test_claim_clocks.py`.
