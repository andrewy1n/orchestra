## Description

One shared adaptive-artifacts binary resolver used by `se_workflow.aa` and `dashboard.artifact_store`, with order env override → plugin-root/sibling → PATH, and no quiet `~/adaptive-artifacts` primary fallback.

## Approach

1. Extract shared `resolve_aa_command()` (keep in `se_workflow` or a tiny module both can import without cycles — prefer moving binding-free resolve out of aa.py so dashboard does not import store helpers circularly).
2. Implement discovery: `ADAPTIVE_ARTIFACTS_BIN`, `ADAPTIVE_ARTIFACTS_ROOT`, then look under `CLAUDE_PLUGIN_ROOT`/`CURSOR_PLUGIN_ROOT` and sibling `adaptive-artifacts` plugin dirs for `bin/adaptive-artifacts` or `tools/artifacts.py`, then `PATH`.
3. Point `dashboard.artifact_store.binary()` at the shared helper.
4. Add unit tests asserting order and that a home checkout is not preferred over PATH when both exist (or home is absent from the order).
