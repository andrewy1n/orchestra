## Description

Enforce red-first for `method: tdd` on `done` closes in `scripts/close_batch.py`, with request-carried red evidence and git-ancestry (or dirty red + diff digest).

## Approach

1. Extend the close-request criteria shape for `tdd` on `done`: require `red_check_run_id` plus copied red fields (`result` must be `fail`, `revision`, `diff_sha256` when dirty, runner marker consistent with check-runner), unless the request includes a finding escape.
2. Add an ancestry helper that uses the process cwd (document optional `--cwd` on the CLI if needed): green SHA equal to or descendant of red SHA via `git merge-base --is-ancestor`; dirty red skips SHA ancestry and requires non-empty `diff_sha256`.
3. Refuse with `CloseRefused` (exit 2) naming the criterion when red is missing, not runner-produced, wrong result, or fails ordering; do not query the store.
4. Leave `check`/`manual` paths unchanged (no `red_check_run_id`). Finding escape keeps forcing `needs: human`.
5. Extend `tests/test_close_batch.py` for pass-only refusal, fail→pass acceptance, wrong-order/non-ancestor refusal, dirty-red with digest, finding override, and check/manual unaffected.
