## Architecture

Replace the Overview branch of `detailView` / `App.svelte` phase overlay with a structured view model: chips, progress, next-action, requirements strip, wave summary. Keep markdown sections for other tabs via existing `detailView` paths. Optionally show a short collapsed "Phase notes" for `detail.body` so prose is not lost.

## Interfaces

- Extend `DetailViewModel` or add `PhaseOverviewModel` with typed blocks.
- Requirements strip reads `detail.evidence` (or equivalent) from GET /api/phase.
- Wave summary groups `detail.tasks` by `wave`.
- Requirement click uses `requirementHref(effort, phase, id)`.

## Decisions

- `phase-overview-layout`
- `phase-overview-requirements`

## Invariants

- Non-overview tabs unchanged in role.
- No JSON dump probe visible to users (sr-only probe may remain for tests).

## Assumptions

- Next-action text can reuse snapshot position / gates phrasing already available to the client, or a short static fallback.

## Tradeoffs

- Overview becomes denser with UI chrome; empty phases need careful empty states.

## Risks

- Next-action derivation may be weaker than the TUI until wired to the same rule list; acceptable to start with position text.
