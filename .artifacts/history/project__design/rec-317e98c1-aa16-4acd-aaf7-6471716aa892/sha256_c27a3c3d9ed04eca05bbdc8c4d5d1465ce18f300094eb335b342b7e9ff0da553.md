## Architecture

Phase-end proof is a stored observation plus skill discipline. Contract adds project:proof-packet. settle-phase and plan-phase require ## Proof on structured phase bodies. execute-phase assembles the packet after the existing phase gate (review + suite + acceptances) and before Landing merge or done language. Handoff gains latest-proof. Affidavit CLIs are optional inputs when a manifest exists.

## Interfaces

- adaptive-artifacts create/supersede project:proof-packet with subject = phase slug
- handoff role latest-proof reads proof-packet (phase, effort, revision, kind; body Look at minimum in the view)
- execute-phase may invoke `aff trail` and `aff audit --base <base> --head <revision>` in the work repo; it stores pointers only
- Chat prints Look and Attention before declaring phase done

## Decisions

proof-owner-orchestra, proof-packet-new-type, proof-gate-packet-not-signature

## Invariants

Machine holds ids and re-run commands only. Packet subject equals phase slug. Supersede when revision advances after fix. Do not invent verdict prose from audit/trail JSON.

## Assumptions

Handoff selection for observation types can filter by effort and prefer latest recorded. Work repos that use Landing already have a known base and phase-head SHA at gate time.

## Tradeoffs

A new record type costs contract + skill surface area; it avoids bending integration-report. Skipping mandatory signatures keeps flow fast; some phases may close without a human actually opening Look (mitigated by handoff surfacing and chat print).

## Risks

Agents may write vague Look sections; skill examples and verification smoke must require concrete commands or paths. Plugin install copies under ~/.cursor/plugins may lag the git repo until sync — land changes in the orchestra git root and sync as this repo already does.
