## Rationale

Closing a goal needs a done state in the runtime current-status pattern, which every current-claim type shares; contracts may not override it. The user chose to keep the change in the dashboard: an effort whose phases and counted tasks are all done is derived as finished, dimmed, and sorted last. Nothing tells you to close a goal you cannot close.

## Counter-argument

Finished goals stay active in the store forever, so handoff, the status line, and every effort list keep growing; a real done state would let views drop them.
