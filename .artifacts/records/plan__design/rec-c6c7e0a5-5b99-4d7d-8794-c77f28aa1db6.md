## Architecture

`_enforce_claim_gates` in `orchestra/close_batch.py` loads each acceptance and reads `payload.claim`. An empty claim skips the gate. A claim id missing from `.affidavit/manifest.json` raises `CloseRefused`. A failure to load the acceptance raises `CloseRefused`. Otherwise it calls `run_verdict` at the green revision and `recheck` for that claim. Each function's failure becomes a `CloseRefused` whose message contains `verdict`, `recheck`, or both. The subject and `claim_id` fallbacks are removed.

## Interfaces

Acceptance payload field `claim` is a manifest claim id string. `run_verdict` and `recheck` are the functions `orchestra-callers` already calls. No new record type is written.

## Decisions

- `claim-close-gate`: both checks must pass, the error names which failed, a missing acceptance refuses.
- `call-style`: the checks are function calls, not `aff` exit codes.

## Invariants

One field names the claim. Both clocks must pass. Missing inputs refuse.

## Assumptions

Authors set `payload.claim`. The manifest file remains the list of known claim ids. The green revision is present on the close, as the ancestry checks already require.

## Tradeoffs

Records that stored the id only on the subject, or on `claim_id`, stop matching and will not be gated. That is a silent loss of a gate unless those records are rewritten. The error text is the only place the two results are distinguished; nothing new is stored.

## Risks

A close that used to skip a dangling criterion id will now refuse. Callers that omitted an acceptance on purpose will see a failure.
