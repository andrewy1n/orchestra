## Evidence

expected (reviewer): `permission:` (singular) using OpenCode permission keys, where write/edit/apply_patch are gated by `edit`.

observed: `installer/agents.py:159-166` emits `permissions:` (plural), maps `edit`/`notebookedit` to `edit`, and also emits `write: deny`; the generated tests assert both `edit: deny` and `write: deny`.

**Correction:** OpenCode V2 docs at `/v2/docs/agents` use `permissions:` plural and explicitly list legacy `permission` (singular) among fields not to use. The key is correct, and `edit: deny` is present, so the reviewer agent is not running with default write permission. The actionable defect is only the unknown `write` action: write/apply_patch are gated by `edit`, so the extra `write: deny` is inert and host-incorrect.

## Consequence

Not a security hole as reported. Minor frontmatter cleanliness; tests currently pin the inert key.

## Follow-up

Drop `write` from the OpenCode rendering (map write/apply_patch to edit) and update the assertions, or accept it as harmless and clear this finding.
