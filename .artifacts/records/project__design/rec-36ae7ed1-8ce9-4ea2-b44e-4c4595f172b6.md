## Architecture

Add a plugin-local `se-workflow` CLI (bin entry + Python package under something like `cli/` or `se_workflow/`) that dispatches subcommands. This phase implements `check`; the dispatcher reserves space for later ops (e.g. close-batch) without migrating them yet.

`se-workflow check`:

1. Load the acceptance by id via `adaptive-artifacts` (or record read helpers).
2. Refuse `method=manual` (print how to sign instead).
3. Resolve `--cwd` (default: repo root / phase worktree).
4. Capture `git rev-parse HEAD` and dirty state; apply dirty-pass-policy.
5. Run `verify_command` with timeout; capture exit, duration, output digest, tail of output (body).
6. Map outcome → `result`; create `project:check-run` through `adaptive-artifacts create` with runner fields and `informed_by` the acceptance (and latest execution-report when supplied).

`verify-work` stops authoring binary check-runs for `tdd`/`check` and calls the CLI (or accepts only CLI-produced ids). Assessments stay in the skill. `close_batch.py` stops inventing pass/fail from a close-request judgment for those methods; it references runner-produced check-run ids (or gains a thin CLI wrapper later).

Contract: add `payload_enum` for `result` and `method`; add optional payload fields `exit_code`, `duration_s`, `output_sha256`, `runner`, `diff_sha256`. Update tests that asserted `result` is not an enum.

`execute-phase`: after each task's code lands, commit on the phase branch before verify so a pass has a SHA.

## Interfaces

- CLI: `se-workflow check --acceptance <id> [--cwd <path>] [--allow-dirty] [--execution-report <id>] [--timeout <s>]`
- Store: `adaptive-artifacts create --type project:check-run …` (only writer of records)
- Skills: `verify-work` documents the CLI invocation; `execute-phase` documents per-task commit
- Contract: `project-design.json` enums + optional runner fields; live store design updated when this phase lands

## Invariants

- Check-run = observation from a run; assessment = meaning and routing.
- Manual criteria never go through `check`.
- CLI is not a second store; it only shells to adaptive-artifacts.
- Parent session remains the authority that invokes the CLI and writes assessments.

## Assumptions

- `payload_enum` enforcement already rejects illegal enum values at create time.
- Plugin packaging can expose `bin/se-workflow` similarly to `dashboard/bin/dashboard`.
- Subagents return evidence; the parent (or human) runs `se-workflow check` against the worktree.

## Tradeoffs

- A second CLI brand (`se-workflow` vs `adaptive-artifacts`) costs install/docs attention; it avoids an AA extension gate and keeps verify policy in this plugin.
- Hard authority and per-task commits slow the happy path vs inventing a pass in chat; they make evidence trustworthy for later automation.
- Enum churn updates evidence-loop / assess-routing tests that currently forbid a `result` enum.

## Risks

- Packaging PATH for Cursor vs Claude plugin installs may differ; plan-phase must name one installable entry.
- `close_batch` and verify-work call sites may miss a path and leave a soft hole; tests must fail closed.
- Optional runner fields need contract optional_payload lists or creates fail on unknown fields depending on runtime strictness — verify against current adaptive-artifacts behavior in implementation.
