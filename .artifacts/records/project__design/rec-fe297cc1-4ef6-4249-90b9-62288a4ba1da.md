## Architecture

Add a small `links.ts` helper: detect reference tokens, resolve them against the current snapshot (and detail payload when open), and return href + label. Integrate into markdown rendering (`renderMarkdown` post-process or marked walk) and into detail/list meta that today prints raw ids.

## Interfaces

- `resolveRef(token, ctx) -> { href, label } | null`
- `ctx` carries selected effort, optional phase, and the snapshot.
- Markdown output wraps resolved tokens in `<a href="#/...">`.
- Milestone refs call into milestone-nav expand/select helpers when on home.

## Decisions

- `deep-links-surfaces`
- `deep-links-labels`

## Invariants

- Unresolved tokens unchanged.
- Overlay close/back behavior unchanged.

## Assumptions

- Requirement links need effort+phase context; without it they stay plain text (R8).

## Tradeoffs

- Conservative patterns may miss some prose references; false positives are worse than misses.

## Risks

- Requirement ids like `R1` are short; resolve only when context or an explicit prefix is present to avoid linkifying ordinary words.
