## Architecture

oracle-witnesses adds the third slice of the verification-direction stack: separate oracle author, freeze, and amendments. claim-witnesses (store-backed check-runs) and atomic-claims (atomic ids, thin acceptances) stay as-is. `evidence_kind` stays deferred.

1. **plan-phase — oracle author:** After deliver/repair work-items and thin `tdd` acceptances exist, dispatch **one** oracle-author subagent for the phase. Brief = original requirement/spec text + acceptance requirement ids/methods only. Subagent returns new/updated test files and node ids; it does not write the store.
2. **Parent — assertion red + freeze:** Parent applies the test files on the phase branch (or staging commit), runs `aff check` per oracle-backed acceptance at base, and refuses to freeze unless the red is assertion-level (fail + failing node with assert failure in output). On success, write freeze fields on each acceptance (`test_ids`, file hashes) and set `verify_command` derived from those ids.
3. **execute-phase:** Executor implements against frozen oracles; briefs forbid editing those files. Pushback → `project:oracle-amendment` request; parent approves (`amendment-approver`) and updates freeze fields.
4. **close / verify:** close-batch refuses `tdd` done on hash drift without approved amendment, or missing assertion-level red. Mechanical verify (R6) drives assessment for oracle-backed requirements.

## Interfaces

- **Contract `project:acceptance`:** optional/required payload fields for frozen `test_ids` (comma-separated node ids or equivalent) and oracle file hash map (stable string form plan-phase defines); `verify_command` remains but is derived from `test_ids` for oracle-backed tdd.
- **Contract `project:oracle-amendment`:** new type; payload includes acceptance id, effort/phase, approval state or lifecycle, and old/new hash material; body sections for reason and proposed change (exact section names fixed at plan-phase to match contract).
- **Skills:** `plan-phase` (oracle dispatch + freeze), `execute-phase` (no edit frozen files; amendment path), `verify-work` (mechanical oracle verify + close refuse wiring).
- **close-batch / aff check:** hash match at green revision; assertion-level red classification helper (shared, tested); no adaptive-artifacts extension API.
- **CLI:** reuse `aff check` / existing close path; no new top-level brand required unless plan-phase finds a thin helper necessary for hash compute.

## Invariants

- Oracle author ≠ executor for oracle-backed tdd.
- Frozen hashes are the close authority for oracle file contents; agent prose is not.
- Assertion-level red is required before freeze and before done close.
- Parent session alone writes freeze fields, amendments, and assessments.

## Assumptions

- Pytest (or the runner behind `aff check`) emits assertion failures in captured output in a form a small classifier can detect.
- One phase-scoped oracle author can cover multiple requirements without the executor feeding it implementation hints.
- Existing red-first ancestry rules remain for the red/green check-run pair; this phase adds freeze/assertion constraints on which reds qualify.

## Tradeoffs

- One author per phase is cheaper than per-requirement authors but allows shared fixtures; freeze remains per acceptance so close still names one requirement's tests.
- A new amendment type costs contract surface; it keeps close matching simple versus overloading decisions.
- Assertion classification can false-negative unusual failure formatting; tests pin the accepted patterns and plan-phase can widen the classifier without weakening the rule.

## Risks

- Interface guesses drive high amendment rates until executors and oracles share naming norms — amendment rate is an intentional signal, not a bug.
- Mis-tuned assertion classifier could reject valid reds or accept import failures; unit tests on real pytest tails are required.
- Legacy acceptances without freeze fields need a clear rule (exempt vs refuse) at plan-phase — default: only new oracle-backed tdd acceptances created under this phase's skills require freeze; closing old rows unchanged is out of band unless verify-work opts them in.
