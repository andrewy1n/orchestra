## Architecture

One integration test in the orchestra repo creates a temporary git repository, initializes a local store, writes a manifest with one claim, and writes the acceptance that names it. It runs `adaptive-artifacts create` and `orchestra close-batch` as subprocesses because those are the real commands. It then calls the close function in-process and asserts the subprocess list for that call does not include `aff` or `adaptive-artifacts`.

## Interfaces

The test is the only new surface. It uses `open_store` to read back the record the command wrote. It uses the public close function orchestra already exposes for `orchestra close-batch`.

## Decisions

- `e2e-temp-repo`: one generated repository, one orchestra test.
- `call-style`: the commands are what the test runs for the agent path; the Python close is what the test runs for the library path.

## Invariants

Command close and Python close both accept the fixture. The in-process close does not spawn the other commands.

## Assumptions

The three packages are installed in the test environment. Claim-gate behavior follows whatever `claim-clocks` has specified by the time this test is written; until then the test uses the gate `orchestra-callers` left in place.

## Tradeoffs

Failure output is a pytest traceback in a temp directory, not a repo you can reopen later. The test spends time creating a git repo and a store.

## Risks

This test fails if any earlier phase is not importable. It should not be required in CI until those phases are merged.
