## Architecture

- Shared AA binary resolution lives in one module used by `se_workflow.aa` and `dashboard.artifact_store` (dashboard imports the shared helper, or both call a single function in `se_workflow` / a tiny shared util under the package that dashboard already can import).
- Plugin-root resolution for skills is documented in `ensure-store.md` and applied wherever skills name `<plugin>` paths (verify-work close entry becomes the CLI, not a script under `<plugin>`).
- Close-batch logic moves from `scripts/close_batch.py` into `se_workflow` (e.g. `se_workflow/close_batch.py`); `se_workflow.cli` grows a `close-batch` subparser that preserves argv/stdin behavior. Optional thin shim at the old script path may remain for one release or be deleted — prefer delete or one-line redirect to reduce dual entry.

## Interfaces

- `se-workflow close-batch` — same inputs as today's script (close-request JSON path / flags); stdout NDJSON ops; exit 0 ok, 1 malformed, 2 policy refusal.
- Shared `resolve_aa_command()` (or equivalent) — returns argv for subprocess; order: `ADAPTIVE_ARTIFACTS_BIN`, `ADAPTIVE_ARTIFACTS_ROOT`, plugin-root/sibling discovery, `PATH`.
- Skill docs: `se-workflow close-batch …` instead of `python3 "<plugin>/scripts/close_batch.py" …`.

## Decisions

- plugin-root-skill-paths
- aa-resolve-order

## Invariants

- close-batch does not write the store; it only emits apply NDJSON.
- tdd/check results come from runner check-runs only.

## Assumptions

- Claude sets `CLAUDE_PLUGIN_ROOT`; Cursor sets `CURSOR_PLUGIN_ROOT` (or skills run from a tree where skill-relative plugin root works).
- Co-installed adaptive-artifacts is findable beside the se-workflow plugin root or on PATH after marketplace install.

## Tradeoffs

- Shared resolver + CLI fold-in touches more files than a docs-only change, but removes the install footguns this phase targets.
- Dropping home-checkout as quiet default may annoy local-only workflows; they keep env overrides and PATH.

## Risks

- Hosts may not set plugin-root vars in every agent context; skill-relative fallback must stay correct.
- Dashboard import path to shared resolver must not create a circular import with `se_workflow.aa` importing dashboard store binding.
- Existing tests that assume `~/adaptive-artifacts` default need updates via env or PATH fixtures.
