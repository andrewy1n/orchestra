## Architecture

Add two modules and keep `installer/runner.py` as the orchestrator.

### Detection

`installer/detect.py`:

- `HostStatus` is a frozen dataclass holding the provider, the project
  detection boolean, the global detection boolean, and whether each scope has
  an orchestra registration marker.
- `detect_hosts(providers, project_base, global_base, source_root)` builds an
  adapter at each base and calls `BaseAdapter.detect()`. It returns one
  `HostStatus` per provider in matrix order.
- `detected_ids(statuses)` returns the ids detected at either scope.
- `installed_ids(statuses)` returns the ids with a registration marker at
  either scope; this supports `--list` and future uninstall work.
- `--home` sets both bases to the redirect directory. Without it, the project
  base is the process cwd and the global base is `Path.home()`.

### Wizard

`installer/wizard.py`:

- `WizardCancelled` signals `q`/`quit`, EOF, or Ctrl-C.
- `WizardSelectionError` carries a prompt-level message for an invalid token.
- `wants_wizard(request)` is true when `--interactive` is set, or when stdin
  and stdout are TTYs and `--non-interactive`/`--yes` is absent. It is always
  false for `--list` and `--uninstall`.
- `prompt_hosts(statuses, default_ids, input_fn=input, output=sys.stdout)`
  renders the matrix and loops until it receives a valid selection. A blank
  answer returns `default_ids`.
- `parse_host_selection(text, statuses)` accepts numbers, ids, ranges,
  comma- or space-separated tokens, `a`/`all`, and `q`/`quit`.
- `prompt_scope(default="project")` returns `"project"` or `"global"`.
- `prompt_mode(default="symlink")` returns `"symlink"` or `"copy"`.
- `confirm(question, default=True)` returns a boolean.
- Every prompt writes to the injected output and reads through the injected
  input function, so tests can drive it without a PTY.

### Model

`installer/model.py` changes `InstallRequest`:

- add `scope: str | None = None` for `--scope` / `--global`; `None` means the
  flag was absent and the wizard may prompt.
- add `list_only: bool`, `interactive: bool`, and `non_interactive: bool`.
- remove `global_scope`; the effective scope is `request.scope or "project"`.

### Runner

`installer/runner.py`:

1. Load the matrix.
2. If `list_only`, render the matrix with project and global detection and
   return 0 before checking for `skills/`.
3. Validate `--only` and `--all`.
4. Resolve the source root and require `skills/`.
5. Resolve the scope: use `request.scope`; otherwise prompt when the wizard is
   active; otherwise use `"project"`.
6. Resolve the mode: `"copy"` when `--copy` is set; otherwise prompt when the
   wizard is active; otherwise `"symlink"`.
7. Detect every provider at both bases.
8. Resolve the host selection:
   - `--only`: exactly those providers, in request order.
   - `--all`: every provider.
   - `--uninstall`: keep the current flag-driven selection; no wizard.
   - wizard: `prompt_hosts` with the detected ids as the default.
   - no wizard: detected ids; if empty, print guidance and return 2.
9. Build one plan per selected provider.
10. Render the plans when `--dry-run` is set or the wizard is active.
11. When the wizard is active and this is not a dry run, ask for confirmation;
    a decline returns 0 without applying.
12. Apply or remove each plan and verify installs as today.

### CLI

`orchestra/cli.py` adds:

- `--list` / `-l` (`dest=list_only`) to print the matrix and exit.
- `--scope {project,global}` in a mutually exclusive group with `--global`.
- `--interactive` and `--non-interactive` / `--yes` / `-y` in a mutually
  exclusive group.
- Update `--only` help to say the default is detected hosts, not every
  provider.

`orchestra/install.py` maps `args.scope`, `args.global_`, `args.list_only`,
`args.interactive`, and `args.non_interactive` into `InstallRequest`.

## Interfaces

### CLI

```text
orchestra install                         # wizard on a TTY, detected hosts otherwise
orchestra install --list                  # matrix + project/global detection
orchestra install --only claude           # explicit host, no host prompt
orchestra install --all                   # explicit every-provider install
orchestra install --scope global          # user directories
orchestra install --global                # alias for --scope global
orchestra install --interactive           # force prompts without a TTY
orchestra install --non-interactive       # force non-interactive
orchestra install --yes                   # alias for --non-interactive
orchestra install --dry-run               # plan only, no writes, no confirm
orchestra install --uninstall --only claude
```

## Decisions

- `installer-wizard-approach`: standard-library wizard plus detection.
- `installer-default-detected`: detected hosts by default; explicit choice
  required when none are detected.
- `installer-detection-both-scopes`: detect project and global footprints and
  label them separately.
- `installer-python-runtime`: keep the installer in Python; no JS rewrite or
  JS wrapper.
- `installer-wizard-install-only`: the wizard covers installs; uninstall stays
  flag-driven.

## Invariants

- Detection, `--list`, `--dry-run`, and a declined confirmation write nothing.
- Planning happens before any apply; a declined plan leaves the tree
  untouched.
- The selected scope and mode are visible in the rendered plan.
- `--only` preserves request order and `--only` plus `--all` remains an error.
- A second install with the same inputs is idempotent.
- `--uninstall` removes only entries named by a registration.
- `--home` redirects both detection bases and prevents reads of the real HOME.
- Existing host adapters and payload layouts are unchanged.

## Assumptions

- `sys.stdin.isatty()` and `sys.stdout.isatty()` are the interactivity signal.
- `--interactive` is available for tests and demos without a PTY.
- The project base is the cwd, the global base is HOME, and `--home` replaces
  both.
- A host is detected when its marker exists or any provider `detect` path
  exists at the base.
- A prompt EOF or Ctrl-C is a cancel, not an install error.
- The provider matrix's `detect` paths remain relative to the install base.

## Tradeoffs

- A standard-library prompt avoids a dependency and works over SSH/CI, but it
  cannot offer arrow-key navigation or mouse selection. Textual remains the
  later upgrade path if the plain prompt proves too limited.
- Detecting both scopes is more useful for project installs, but it can show a
  host whose only footprint is an unrelated global config. The labels and the
  explicit selection step make that visible.
- Defaulting to detected hosts prevents accidental directories, but a clean
  checkout now requires `--all`, `--only`, or the wizard. That is the intended
  safety trade.
- Keeping uninstall flag-driven avoids a second destructive prompt flow, but
  the command is less symmetric than install.
- Keeping Python avoids a second runtime and duplicate tests, but forgoes an
  `npx` one-liner and the JS ecosystem's prompt libraries.

## Risks

- Prompt parsing can misread ids that contain digits or ranges; tests cover
  ids, numbers, ranges, duplicates, and invalid tokens.
- TTY detection differs across terminals and CI; `--interactive` and
  `--non-interactive` make the choice explicit.
- A host config directory can be a false positive; `--list` shows the source
  and the user still selects explicitly.
- Detection could read the real HOME when `--home` is used; the design makes
  `--home` replace both bases and tests assert it.
- Existing tests may assume the old default-all behavior; only default-behavior
  tests should change, while `--all` tests stay.
- Rendering the plan before confirmation prints absolute paths; that is
  intended, but tests should not assume a fixed home directory.
