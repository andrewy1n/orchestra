## Architecture

Tier-1 remains today's per-task and phase verification acceptances (`verify_command` scoped with `-k` as under verify-budget). No affected-test engine in this phase.

Tier-2: after last implementation wave, closing verification, and phase-end reviewer pass, parent starts in the phase worktree a detached tmux window running the README full suite (`uv run … pytest tests -q -n 4 -m "not tmux"`, then serial `-m tmux`). On completion, record one runner check-run at the phase head SHA (pass/fail, duration, digest, failing node IDs). Dashboard phase header shows running/passed/failed@SHA.

Gate: merge/close only when every active phase acceptance has a passing runner check-run at head SHA and tier-2 at that SHA passes. On tier-2 fail, parent creates fix work-items (cluster by failing file/module) via retry-loop; no inline fix in the verifier; rerun tier-2 at new head after fixes.

Flakes: may surface in output; no required auto-retry marker policy this phase. CI takeover is explicitly future.

## Interfaces

- execute-phase: trigger background tier-2; poll/record result; gate; fix-task handoff.
- se-workflow check / runner: record the tier-2 check-run (evidence kind per contract: integration or agreed regression value already allowed).
- Dashboard model/UI: tier-2 status on phase header.
- Skills/README/`tests/test_verify_budget.py`: document phase-level full run vs scoped per-task.
- Tests for gate, fix-task on failure, skill↔contract consistency.

## Decisions

- tiered-verification-scope: tier-2 first; defer affected-test selection and flaky auto-retry polish
- tier2-execution: background tmux in phase worktree (not blocking in-process)

## Invariants

- Per-task verification stays scoped.
- Tier-2 is required at head before merge.
- Failures become fix tasks under retry budget.

## Assumptions

- tmux and phase worktrees remain part of the operator setup.
- Head SHA is a real commit (task-commit-evidence); dirty-only tier-2 is refused or recorded consistently with dirty-pass policy.

## Tradeoffs

- Defer affected tests: slower/more blind inner loop vs faster gate delivery.
- Background vs blocking: operational complexity vs agent idle time.

## Risks

- Background job orphaned or missed — dashboard status + execute-phase must poll/reattach; document recovery.
- Flaky tmux leg flakes the phase — list and escalate to human when unstable; full flake policy later.
