## Architecture

Delete `orchestra/aa_resolve.py` and `dashboard/artifact_store.py`. Call sites that resolved a store or started `adaptive-artifacts` call `open_store` and `Project.get`, `Project.create`, or `Project.apply`. `close_batch` imports `is_assertion_level_red`, `run_verdict`, and `recheck` inside the close command. `pyproject.toml` gains a dependency on adaptive-artifacts. Affidavit is not a required dependency.

## Interfaces

Orchestra and the dashboard call `open_store(directory)` from `adaptive_artifacts.project`. Close calls `is_assertion_level_red(check_run)`, `run_verdict(...)`, and `recheck(...)`. A missing affidavit import becomes an error whose message names affidavit, raised from close only.

## Decisions

- `orchestra-imports`: direct imports of `Project` and lazy affidavit from close.
- `call-style`: skills keep the commands.
- `dependency-direction`: adaptive-artifacts is required; affidavit is loaded only for close.
- `store-resolution`: callers use `open_store` and do not reimplement binding.

## Invariants

Help does not import affidavit. No orchestra or dashboard module resolves `SE_WORKFLOW_STORE` or a private binding file.

## Assumptions

The dashboard process runs with the orchestra environment, so one dependency covers both trees.

## Tradeoffs

Dashboard code names `adaptive_artifacts.project`. A Project change touches those call sites directly. There is no adapter module to edit instead.

## Risks

Tests that monkeypatch `aa_resolve` or `artifact_store` fail until they patch `open_store`. Hidden imports of affidavit at package import time would break R8.
