## Architecture

Dismiss/`d` becomes a two-step human approval path on Needs-you items.

1. List: `d` navigates to detail (or no-ops with a hint) — no CLI write.
2. Detail: show kind-specific evidence. User confirms via modal (Approve/Reject/Cancel, Sign/Cancel, or Accept risk/Cancel) with note rules.
3. On confirm: build CLI args using the **displayed** record revision as `--expected-revision`. On stale revision, show error and refresh; do not retry with `@current`.
4. Plan review Reject: leave question open; create finding (`needs: human`) or feedback so engage routes to discuss/plan-phase.
5. Supersede `dashboard-read-only`, `dashboard-read-only-dashboard-bugfix`, and `dashboard-read-only-dashboard-features` with one active constraint stating allowed writes: human gates only, via CLI, with recorded decision/note.
6. Contract optional fields for notes/answers as needed; README key table; tests.

## Interfaces

- `dashboard/dismiss.py` / `dashboard/app.py`: detail gate, modal, revision plumbing, approve vs reject keys.
- Contract: optional `answer`, `signed_note`, `resolution_note` (or documented equivalents on continuity-question / check-run / finding).
- Constraints: supersede the three read-only constraints.
- Tests: `tests/test_dashboard_gates.py` / `test_dashboard_app.py` (and related).
- README key bindings.

## Decisions

- dashboard-approvals-scope: full #8
- approval-revision-guard: displayed revision, never `@current` for these writes

## Invariants

- No write without detail + confirm.
- Reject keeps plan-review blocking.
- Allowed dashboard writes are exactly the human-gate set described by the new constraint.

## Assumptions

- Textual modals/pilots can express confirm + note without a new framework.
- Existing dismiss CLI shapes can gain note fields without breaking unsigned flows.

## Tradeoffs

- Full UX vs minimal confirm: more tests and payload fields; auditable gates.
- Strict revision guard vs `@current`: more "changed since opened" friction; correct approvals.

## Risks

- Note fields need contract + skill mentions — keep skill↔contract tests green.
- Users habitually mash `d` — detail-first may annoy; document keys in README.
