## Architecture

Work lands primarily in the **adaptive-artifacts** repo under its extension gate. Move the runtime from `tools/runtime` + `tools/artifacts.py` sys.path hacks into an installable package (recommended layout: `src/adaptive_artifacts/` with CLI module and runtime subpackage). Add root `pyproject.toml` with project metadata and a `[project.scripts]` entry `adaptive-artifacts = …:main`.

Keep **compatibility shims** at the historical paths:
- `bin/adaptive-artifacts` — plugin PATH entry; delegates to the package CLI.
- `tools/artifacts.py` — checkout/`ADAPTIVE_ARTIFACTS_ROOT` entry; same delegation.

Affidavit changes in this phase are **docs-only** (README install section for git+ `uv tool install`). No affidavit `pyproject.toml`. No PyPI upload.

## Interfaces

- **User/tool install:** `uv tool install "git+https://github.com/andrewy1n/adaptive-artifacts.git@<ref>"` → `adaptive-artifacts` on PATH.
- **Plugin install:** unchanged marketplace/plugin sync; `bin/adaptive-artifacts` remains the entry.
- **Dev/test checkout:** `ADAPTIVE_ARTIFACTS_ROOT=<clone>` still resolves via `tools/artifacts.py` shim.
- **Affidavit boundary:** continues to subprocess the CLI; does not import the AA package.

## Decisions

- packaging-scope-aa-first → aa-first-git-tool-install
- pypi-publish-deferred → defer-pypi-publish
- aa-checkout-shims → keep-bin-and-tools-shims

## Invariants

- Public contract is the CLI, not Python import stability for third parties.
- Shim paths remain runnable after the package move.
- Record/store formats unchanged.
- Affidavit product code does not gain a dependency on importing `adaptive_artifacts`.

## Assumptions

- Hatchling or setuptools is fine for the build backend; pick one at plan/execute without a new discuss decision unless it forces layout changes.
- Distribution name can be `adaptive-artifacts` (PyPI-style) with import package `adaptive_artifacts`; final names confirmed at plan if tooling objects.
- Human approval in the AA store happens before AA code merges.

## Tradeoffs

- AA-first delays affidavit tool-install convenience but avoids a dual Landing.
- Shims add a few permanent files in exchange for zero affidavit resolve churn this phase.
- Deferring PyPI avoids release ceremony but leaves git+ as the non-plugin install path.

## Risks

- Import rewrites inside AA tests/runtime miss a relative import and break plugin or shim modes.
- Affidavit docs drift if AA entry point name differs from `adaptive-artifacts`.
- Extension-gate delay: affidavit phase cannot claim AA done until AA approval lands.
- Thin shims that still mutate `sys.path` reintroduce the old layout smell—shims must call the package entry, not re-open `tools/runtime` on path.
