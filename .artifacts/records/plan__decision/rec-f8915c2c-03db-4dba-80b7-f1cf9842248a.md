## Rationale

Uninstall is rare and destructive, and the current flag-driven path already removes only what a registration names. Keeping the wizard install-only keeps the phase focused and avoids adding a confirmation path whose failure mode is deleting host state.

## Counter-argument

An interactive uninstall would make the command feel consistent and would let a user see what is installed before removing it. The cost is a second destructive flow to design, test, and document in the same phase; `--list` plus `--uninstall --only` covers the need for now.
