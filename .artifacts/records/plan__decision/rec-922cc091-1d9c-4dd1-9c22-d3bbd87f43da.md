## Rationale

Parallel phases need separate checkouts, and a worktree keeps each phase branch off the shared `main` checkout. The path sits beside the repo, `<repo-parent>/<repo-name>--<phase-slug>`, so the worktree is not a directory inside the primary checkout. The branch name is `phase/<phase-slug>` and it starts from `main`.

## Counter-argument

A branch in the shared checkout is enough when only one phase runs. It cannot cover two phases at once, which this loop already allows.
