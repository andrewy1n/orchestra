## Rationale

The phase overlay is still a single vertical stack (chrome then body). A fixed left summary (status, next, requirements, waves, mini task list) with the active tab’s content on the right uses width, keeps orientation while switching tabs, and matches what we want from “better UI everywhere” without inventing a different layout per tab (option C) or staying one-column (option A).

## Counter-argument

Option C (tab-as-workspace) could be richer for Spec/Tasks specifically. Rejected for now because one stable split is easier to ship and learn; tab-specific panes can layer on later if needed.
