## Rationale

Hooks are an optimization, not a correctness requirement: `engage`, `plan-phase`, `execute-phase`, and `settle-phase` already run `adaptive-artifacts hook-start` when views were not injected. Installing native hook adapters where the host supports them — Claude, Cursor, and OpenCode via `plugin.js` — gives automatic view injection on those hosts and keeps correctness on hosts that have no lifecycle hook. Installation succeeds either way, which is what keeps the matrix broad.

## Counter-argument

Skills-only hooks are simpler and uniform: one code path, no per-host hook files, no plugin runtime to maintain. The cost is that every session pays a manual `hook-start` and can forget `hook-stop`, so views go stale and validation runs late. Requiring hooks would make behavior consistent, but it excludes most harnesses and turns a convenience into an install gate.
