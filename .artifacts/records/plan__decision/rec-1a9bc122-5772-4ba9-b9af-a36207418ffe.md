## Rationale

Own adapters only where a host has capabilities the generic path cannot express: Claude and Cursor plugin manifests plus hooks, and OpenCode's `skills` config, `agents/`, and `plugin.js`. Everything else is a uniform Agent Skills directory, which `npx skills add` already installs for 79 agents with update, remove, and symlink-or-copy handling. This matches what caveman, Atlas, and the AWS / Firecrawl skill packs do, and keeps orchestra's adapter surface at three instead of thirty.

## Counter-argument

Owning a provider adapter for every harness gives a consistent UX and full control over detection and layout, and it avoids depending on a third-party CLI's profile names and behavior. If `npx skills` changes or disappears, the delegated half of the matrix breaks at once. The cost is real: thirty-plus adapters to maintain, each lagging host changes.
