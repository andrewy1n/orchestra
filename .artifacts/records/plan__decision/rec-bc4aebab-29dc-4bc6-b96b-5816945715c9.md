## Rationale

`se_workflow.aa` and `dashboard.artifact_store` currently disagree on order and both quietly prefer `~/adaptive-artifacts`. That made local checkouts work and marketplace installs look broken. One shared order — env override, then plugin-root / sibling discovery, then PATH — keeps overrides for tests, finds the co-installed runtime, and uses PATH when present. Dropping the home checkout as a quiet primary fallback stops masking missing installs.

## Counter-argument

Keeping `~/adaptive-artifacts` as a last-resort default preserves today's developer ergonomics with zero PATH setup. The cost is divergent resolvers and false confidence that an install worked when only a personal checkout is visible.
