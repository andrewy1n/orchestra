## Rationale

`dashboard/web/app.py` postpones annotations, and `Request` is imported only inside `create_app`. FastAPI resolves annotations from the module globals, misses `Request`, and requires a query parameter named `request`. Deleting `from __future__ import annotations` evaluates `Request`, `JSONResponse`, and `HTMLResponse` when the routes are defined, so both POST handlers and OpenAPI see the real types. `fastapi` stays imported inside `create_app`.

## Counter-argument

Binding the JSON object with `Body(...)` would make the write contract explicit and would not depend on when annotations are evaluated. That fixes only the two POST parameters. The exception handlers and the index route use `JSONResponse` and `HTMLResponse` the same way, and OpenAPI already returns 500 on those unresolved names. One annotation change covers every symbol in the file.
