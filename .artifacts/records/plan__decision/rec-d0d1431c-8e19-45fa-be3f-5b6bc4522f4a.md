## Rationale

The page opens in the light theme, matching the spike. A control sets the `dark` class on the document and clears it again, so rail, main pane, side column, and overlays all switch together. The dark colors follow the spike's dark tokens, expressed as Tailwind `dark:` variants. The choice lasts for the visit. A new load starts light again.

## Counter-argument

Shipping light only would keep the first Tailwind pass smaller and avoid a second palette before the API and writes are in place. The mock already proved a dark theme, and leaving it out means the restyle drops a switch the spike already has.
