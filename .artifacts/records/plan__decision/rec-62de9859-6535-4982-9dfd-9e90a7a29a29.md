## Rationale

Today's web UI already uses first activation to select a phase (filter tasks) and a second activation on the selected phase to open detail. Keeping that for phase rows under milestone groups avoids a new gesture vocabulary.

## Counter-argument

Every click opening the phase overlay would make detail faster to reach. That was rejected because the home screen's job is filtering the task table; opening overlays on every click would interrupt scanning.
