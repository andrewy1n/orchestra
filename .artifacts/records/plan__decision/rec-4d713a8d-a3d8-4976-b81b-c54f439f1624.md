## Rationale

The user chose that both checks must pass. The acceptance names the claim in `payload.claim`. Close runs verdict at the green revision and recheck on the live binding. Either failure refuses, and the error names which check failed. A missing acceptance refuses instead of being skipped. An id that is not in the manifest refuses instead of being ignored.

## Counter-argument

Letting verdict alone block done would tie the close to the revision being merged, and would treat a drifted live binding as information rather than a failure. The cost is closing a task whose recorded binding no longer holds.
