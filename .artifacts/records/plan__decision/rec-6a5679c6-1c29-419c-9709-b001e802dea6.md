## Rationale

Users install se-workflow (the product). Hosting the shared catalog in the se-workflow repo makes that repo the single `marketplace add` front door. adaptive-artifacts stays its own git repo and plugin; it appears as a github-sourced entry. A later rename to agent-affidavit renames one marketplace rather than a third catalog.

## Counter-argument

Hosting in adaptive-artifacts (or a dedicated catalog repo) keeps the runtime as the "platform" front door and avoids se-workflow owning a listing for a sibling repo. That inverts the usual install path—people come for the workflow plugin—and a third repo adds another place to keep in sync for little gain while both plugins are still small.
