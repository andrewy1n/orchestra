## Rationale

The spike is already a client that fetches JSON and draws whole screens. Svelte components replace the two hand-built DOM-string files, and Vite supplies the dev server and the production build. The Python process keeps the spike's JSON API over `dashboard.model`. In development Vite proxies `/api` to that process. When the dashboard is opened for use, the same process serves the built files on localhost. TypeScript and npm live under the web UI directory, not in the installed `orchestra` package.

## Counter-argument

Jinja and htmx would keep a single Python process and no Node toolchain, which matches a repo whose only dashboard dependency today is Textual. Preact would keep JSX close to the spike's HTML with a smaller runtime. Svelte adds a compiler and a second language for a localhost viewer whose interaction set is filters, overlays, and hash routes.
