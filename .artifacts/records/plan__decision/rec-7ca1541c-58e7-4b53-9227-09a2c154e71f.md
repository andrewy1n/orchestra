## Rationale

Most dogfood passes already say `revision: dirty`, so the SHA does not name the code that landed. Refusing a dirty `pass` by default forces a commit (or an explicit override that records `diff_sha256`). Fails may stay dirty for TDD red.

## Counter-argument

Allowing dirty passes by default matches how subagents work today (edit, test, report before commit). That preserves speed and keeps the 67% dirty-pass pattern.
