## Rationale

Dogfood (`status-tabs`) lost behavior when acceptance `criterion` re-summarized the work-item. Thin acceptances keep method, verify_command, and a single requirement id; done meaning stays on the requirement (or description-as-ids). Moving `criterion` to optional_payload and dropping it from brief/plan/verification `requires_payload` stops derived views from privileging a duplicate claim. Empty string alone would still tempt agents to fill prose that the views then surface.

## Counter-argument

Keeping `criterion` required (even as `""`) preserves a stable create shape and older dashboard copy that expects the field. The cost is continued pressure to write prose into the one field views still treat as the summary.
