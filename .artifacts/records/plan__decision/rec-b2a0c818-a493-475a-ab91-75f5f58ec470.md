## Rationale

The missing stages need records a later skill can query: a specification acceptance can point at, an integration result that is not a git merge, a check-run that can be insufficient, and release and feedback states with no runtime behind them. The six skills already own intent, design, plan, execute, and verify. New skills would duplicate `discuss` and `verify-work` and force every small change through extra entry points. Design stays a decision. Diagnosis stays a finding. Incidental work and a light specification skip the heavy records.

## Counter-argument

Conventions on the current records would avoid a contract upgrade. Extra payload keys are already legal, phase Exit criteria and acceptance already state what done means, and Landing already merges the branch. A store created before these types would keep working with no human-approved design replace. Querying "which criteria lack evidence" can be a procedure over acceptance and check-run without a specification type.
