## Rationale

The packaging goal asks for a single CLI surface for skills. `se-workflow check` already exists; folding close-batch into the same package removes the third entry (`python3 scripts/close_batch.py`) and lets skills call only `se-workflow` or `adaptive-artifacts`. Moving the module into `se_workflow` (not a thin wrapper around the script) keeps policy and CLI in one place and avoids dual maintenance.

## Counter-argument

A thin `se-workflow close-batch` that shells to `scripts/close_batch.py` is a smaller diff and preserves import paths tests already use. It leaves the script as a second real entry and invites skills to keep calling it directly.
