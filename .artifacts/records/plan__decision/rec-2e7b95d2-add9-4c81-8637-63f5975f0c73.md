## Rationale

The installer already has a Python engine, provider matrix, adapters, and tests. A standard-library prompt adds the missing selection, scope, mode, and confirmation UX without a new runtime dependency, and it works over SSH and in CI. It also matches the caveman installer's actual interactive surface: a numbered prompt, not a full-screen TUI.

## Counter-argument

A Textual TUI is more discoverable and supports arrow keys and checkboxes, and this repo already uses Textual for the dashboard. A flags-only change is smaller still. Both are rejected because the first adds a dependency and a larger test surface for a one-time install command, while the second leaves the accidental default-all behavior and the undocumented choices in place.
