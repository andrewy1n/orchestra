## Rationale

Capture is an explicit parent-session write when the user parks work (engage may offer to create the record). That matches single-writer store rules and avoids a collector that scrapes chat or GitHub. Listing and promoting stay skill-documented CLI operations.

## Counter-argument

Scraping GitHub issues into the store would meet users where issues already live and reduce double entry. The cost is sync drift, auth surface, and treating GitHub as authority alongside records — out of scope for this phase and hostile to "records are the authority."
