## Requirements

R1: Close reads the claim id only from the acceptance payload field `claim`.
R2: An acceptance whose `claim` is empty is not refused for a missing verdict.
R3: For a non-empty `claim`, close invokes verdict at the green revision.
R4: For a non-empty `claim`, close invokes recheck for that claim.
R5: When verdict fails and recheck passes, close refuses and the error names verdict.
R6: When recheck fails and verdict passes, close refuses and the error names recheck.
R7: When verdict and recheck both fail, close refuses and the error names verdict and recheck.
R8: When the acceptance record cannot be loaded, close refuses.
R9: When `claim` is not listed in `.affidavit/manifest.json`, close refuses.

## Acceptance criteria

R1–R9: close-batch tests on a temporary repository with a manifest. Each test sets one combination and asserts the refusal text or the accept.

## Constraints

Both checks are required for done. Close calls the affidavit functions from `orchestra-callers`. The manifest remains the oracle authority. The live binding remains the recheck authority.

## Non-goals

Close does not write a separate stored result for verdict or recheck. Recheck does not become advisory. Verdict does not gain a new execution mode.

## Invariants

A named claim is closed only when verdict at the green revision passes and recheck passes. A missing acceptance is a refusal. The claim id has one field.

## Assumptions

The green revision is the revision already required on the close request. `payload.claim` is the field authors set. Older records that put the id only in `claim_id` or in the subject are not matched.
