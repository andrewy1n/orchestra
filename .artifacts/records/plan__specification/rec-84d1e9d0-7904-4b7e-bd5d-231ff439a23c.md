## Requirements

R1: Running `orchestra install` with no host flags on an interactive TTY launches the host-selection wizard instead of selecting every provider.
R2: The host prompt lists every provider in the matrix with its id, name, project detection status, and global detection status.
R3: The host selection accepts provider numbers, provider ids, numeric ranges, comma- or space-separated values, `a` or `all`, and `q` or `quit`.
R4: A blank host selection selects the detected hosts when at least one host is detected.
R5: A blank host selection with no detected hosts refuses to proceed.
R6: The wizard prompts for project or global scope, defaults to project, and prints the resolved base directory.
R7: The wizard prompts for symlink or copy mode, defaults to symlink, and prints the chosen mode.
R8: The wizard prints the full plan and asks for confirmation before writing.
R9: Declining confirmation exits without writing a host payload.
R10: `--list` prints the provider matrix with project and global detection and exits without writing.
R11: `--scope {project,global}` selects the install scope and conflicts with `--global`.
R12: `--interactive` forces the wizard when standard input is not a TTY.
R13: `--non-interactive` or `--yes` suppresses prompts; host selection uses `--only` or `--all` when given, otherwise detected hosts.
R14: With no host flags and no TTY, or with `--yes`, the installer selects detected hosts; if none are detected it exits 2 with guidance and writes nothing.
R15: Explicit `--only` and `--all` select exactly those providers and skip the host prompt.
R16: `--dry-run` with the wizard prints the plan and writes nothing without asking for confirmation.
R17: `--uninstall` remains flag-driven and never launches the wizard.
R18: README documents the wizard, detection, the new default, and the new flags.

## Acceptance criteria

- A clean project with no host footprints and no flags prints guidance and writes no host directories.
- A project with `.claude` and a global `~/.config/opencode` shows both hosts as detected; selecting them installs only those hosts.
- `--list` prints the matrix and exits without writing.
- `--scope global` writes under HOME; `--scope project` writes under the current directory.
- `--yes` on a clean project exits 2 and writes nothing.
- The installer test suite passes, including the new wizard and detection tests.

## Constraints

- Use the Python standard library only; add no runtime dependency.
- Preserve the existing flags and idempotent registration behavior.
- Do not write during detection, `--list`, `--dry-run`, or before confirmation.
- Preserve the request order of repeated `--only` flags.
- Keep `--home` as the test and throwaway-home redirect; detection must honor it and must not read the real HOME.
- Do not change the provider matrix, adapters, or host payload layout.

## Non-goals

- A full-screen Textual or arrow-key TUI.
- A JavaScript or Node rewrite, or an npx wrapper.
- JSON output.
- Interactive uninstall.
- Per-skill or per-agent selection.
- Changing which files each host adapter installs.

## Invariants

- One registration per host per install scope.
- A second install with the same inputs changes nothing.
- `--only` and `--all` remain mutually exclusive.
- `--dry-run` writes nothing.
- `--list` writes nothing.
- `--uninstall` removes only entries named by a registration.
- Existing flag combinations continue to work.
- Detection never reads the real HOME when `--home` is set.

## Assumptions

- Interactivity is `sys.stdin.isatty()` and `sys.stdout.isatty()`.
- `--interactive` provides a prompt path for tests and demos without a PTY.
- The project base is the current directory; the global base is HOME; `--home` overrides both.
- Provider `detect` paths are relative to the install base and may name files or directories.
- A host is detected when its registration marker exists or any `detect` path exists.
- `--global` remains an alias for `--scope global`.
