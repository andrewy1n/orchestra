## Requirements

R1: Inside a git repository, `open_store` uses `git rev-parse --show-toplevel` of the given directory as the project root.
R2: Outside a git repository, `open_store` uses the given directory as the project root.
R3: A store path passed to `open_store` selects that directory, and binding files are not read.
R4: With no store path argument, `ARTIFACTS_STORE` selects the directory, and binding files are not read.
R5: With no store path argument and no `ARTIFACTS_STORE`, `.artifacts/store-binding.local.json` at the project root selects `local` or `global`.
R6: With no store path argument, no `ARTIFACTS_STORE`, and no local binding file, `.artifacts/store-binding.json` selects `local` or `global`.
R7: With no store path argument, no `ARTIFACTS_STORE`, and no binding file, `open_store` opens `<root>/.artifacts` when that directory contains `meta.json`.
R8: With no store path argument, no `ARTIFACTS_STORE`, and no binding file, `open_store` opens `~/.artifacts/<root name>` when `<root>/.artifacts` has no `meta.json` and the home directory contains `meta.json`.
R9: A store path argument whose directory has no `meta.json` raises, and the home store is not opened.
R10: `ARTIFACTS_STORE` set to a directory with no `meta.json` raises, and binding files are not read.
R11: A binding file whose selected directory has no `meta.json` raises, and the other location is not opened.
R12: A binding value other than `local` or `global` raises.
R13: With no store path argument, no `ARTIFACTS_STORE`, no binding file, and no `meta.json` in either location, `open_store` raises.
R14: The adaptive-artifacts package does not read `SE_WORKFLOW_STORE`.
R15: `Project.get` returns the record for an id present in the opened store.
R16: `Project.get` raises when that id is not in the opened store.
R17: `Project.list` returns every record of the given type in the opened store.
R18: `Project.create` persists one record in the opened store and returns the stored record.
R19: `Project.apply` persists each operation in the given sequence and returns each result.
R20: `adaptive-artifacts create` without `--store` writes into the store `open_store` would open for the process working directory.
R21: `adaptive-artifacts get` without `--store` reads from that same store.

## Acceptance criteria

R1–R13: tests call `open_store` on temporary directories and assert the opened path or the raised error.
R14: a test scans the adaptive-artifacts package and fails if the source reads `SE_WORKFLOW_STORE`.
R15–R19: tests call the `Project` methods on a temporary initialized store.
R20–R21: tests run the `adaptive-artifacts` command in a temporary repository and compare the store with `open_store` for that working directory.

## Constraints

This phase edits adaptive-artifacts only. Orchestra and affidavit keep their current callers until their own phases. Agents keep calling the `adaptive-artifacts` command. The resolution order is the `store-resolution` decision.

## Non-goals

Update, supersede, correct, hooks, watch, views, lock, and resolve stay implemented in the command module. List query flags (`--where`, `--order-by`, `--fields`) stay in the command. The `tools/` shim stays. The contract-format check belongs to `declared-install`.

## Invariants

For one directory and environment, `open_store` and the command select the same store. A path, `ARTIFACTS_STORE`, or a binding file that names a store never falls through to another store. One call opens one store.

## Assumptions

`local` is `<project root>/.artifacts`. `global` is `~/.artifacts/<project root directory name>`. `meta.json` marks an initialized store. The git toplevel of a worktree is that worktree, so a worktree does not inherit the main checkout's `.artifacts` unless the worktree itself has `meta.json` or a binding file.
