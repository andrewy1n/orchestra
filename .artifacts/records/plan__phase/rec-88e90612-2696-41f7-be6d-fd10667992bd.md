## Problem

`dashboard-status` reads the contract's dashboard view while the app reads the record snapshot. The two disagree: the status line listed an effort with no goal that has no tab in the app.

## Approach

- Rebuild `dashboard-status` on `dashboard_model.load_snapshot`: one line per effort the app shows, with the same running, ready, and needs-you counts. Drop the markdown view parser. Measured: the snapshot takes about 0.25 s, same as today and well inside the 2 s timeout; `dashboard_model` does not import Textual, so plain python3 runs it.
- Keep printing nothing when the directory has no store or the CLI fails.

## Exit criteria

- Status tests: for a seeded store, every status line names an effort the app snapshot has, with the same counts; an effort with no goal prints nothing.
- The tmux status segment test and the e2e test pass; the full suite passes.
