## Problem

Failed tasks stay `in_progress` with assessment `next: execute`, but execute-phase only selects `planned` ready work. Closing verification can fail after siblings are already `done`, with no path to create a fix task. Evidence escalation never leaves `implementation` in dogfood, so the loop can stall or spin without a hard stop.

## Approach

Decisions: retry-loop-scope (full #7), retry-budget (hard backstop; defaults 2 re-dispatches or 2× estimate_minutes, 3 fix tasks/phase), fix-task-shape (new work-item + depends_on; never reopen `done`), next-plan-consume (plan-phase handles `next: plan`). Structured work: specification and design `retry-loop`.

Parent execute-phase re-dispatches retryable `in_progress` tasks with assignment-amendments and `attempts`; creates fix work-items when closing verification fails; enforces the budget into Needs you; plan-phase consumes `next: plan`; dashboard shows attempt/budget. Evidence ladder stays for routing. Out of scope: reviewer, tiered verification, dashboard approval UX.

Tasks:

1. `retry-engine` — subagent, 55m. Add optional `attempts` on work-item in `contract/project-design.json` (keep `.artifacts/project-design.json` in sync if required by resolve). Update `skills/execute-phase/SKILL.md` for re-dispatch before planned selection, assignment-amendments, attempts, fix-task creation, budget + run-fact overrides, and Needs-you escalation. Update `skills/plan-phase/SKILL.md` for `next: plan`. Note parent re-dispatch/fix-task behavior in `skills/verify-work/SKILL.md` without changing evidence-ladder routing. Add `tests/test_retry_loop.py` covering selection/amendment, fix-task + depends_on re-gate, budget exhaustion, no reopen of `done`, and `next: plan` skill/contract asserts. Keep `tests/test_skill_contract_consistency.py` green.
2. `retry-dashboard` — subagent, 30m, parallel with `retry-engine`. Show `attempt n/budget` on retried task rows (model + UI). Defaults when run facts omit overrides. Tests under dashboard suites with a `-k` filter for this phase.
3. `verify-retry-loop` — subagent, 30m, after both. Prove exit criteria via the phase checks below. Do not edit the tree.

Session shape: one sitting. Human stops: plan review; then landing after verification. Do not push.

Collision notes: wave 1 `retry-engine` owns `contract/`, `skills/execute-phase/`, `skills/plan-phase/`, `skills/verify-work/`, `tests/test_retry_loop.py`, and skill-contract consistency touches. Wave 1 `retry-dashboard` owns `dashboard/` and dashboard tests with the phase `-k` filter. No shared paths in the parallel wave.
