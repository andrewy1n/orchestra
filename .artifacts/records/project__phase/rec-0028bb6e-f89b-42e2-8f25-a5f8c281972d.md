## Problem

The dashboard and CLI prefer `~/.artifacts/<repo>` whenever that path has `meta.json`, so an empty or contract-drifted home store can shadow the real repo store and break every list/view.

## Approach

Decisions: store-modes (local or global exclusive), binding-layers (env → local override → committed → default), se-workflow-binding (local). Structured work: specification and design `store-binding`.

Exclusive store binding shared by `dashboard.artifact_store` and `se_workflow.aa`. Resolution: `SE_WORKFLOW_STORE` → `.artifacts/store-binding.local.json` → `.artifacts/store-binding.json` → default (repo meta else home meta). Bound-but-missing fails; no fallthrough. This repo commits `{"store":"local"}`.

**Size:** one sitting
**Human stops:** plan review (approved via execute request)
**Parallel:** none — one implementer

## Exit criteria

Binding resolution picks exactly one store; this repo's committed binding is local; dashboard `--once` and `se_workflow.aa.run_aa` use the bound store; tests for precedence and exclusive failure pass; README and ensure-store document the binding. Verify with `uv run --with textual --with pytest python -m pytest tests/test_artifact_store.py tests/test_dashboard_launcher.py tests/test_se_workflow_aa.py -q` and `uv run --with textual python -m dashboard --once`.
