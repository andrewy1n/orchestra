## Requirements

R1: Store binding is exactly `local` (repo `<root>/.artifacts`) or `global` (`~/.artifacts/<root.name>`); never both or a merge when a binding is set.
R2: Resolution order is `SE_WORKFLOW_STORE`, then `.artifacts/store-binding.local.json`, then `.artifacts/store-binding.json`, then default (local if repo meta exists, else global if home meta exists, else none).
R3: A set binding that points at a path without `meta.json` fails with a message naming the binding source and path; it does not fall through to the other store.
R4: Invalid binding JSON or `store` value fails clearly (no silent ignore).
R5: Dashboard launcher and `se_workflow.aa.run_aa` use the same resolve and pass `--store` / `--contract` for the chosen store.
R6: This repository commits `{"store":"local"}` in `.artifacts/store-binding.json`; `.artifacts/store-binding.local.json` is gitignored.

## Acceptance criteria

- Unit tests cover precedence and exclusive failure for a missing bound store.
- With a home store present and committed binding `local`, dashboard `--once` reads the repo store.
- `run_aa` invocations include `--store` for the bound path.
- README and ensure-store document binding, env, and the shell-wrapper footgun.

## Constraints

- No adaptive-artifacts runtime dual-store change.
- Binding files use `{"store":"local"|"global"}` only.

## Non-goals

- Merging records from home and repo stores.
- Auto-repinning a drifted home `meta.json`.
- Changing the adaptive-artifacts shell function in the user's personal zshrc (document only).

## Invariants

- At most one store path is chosen per resolve call.
- Committed and local override files share the same schema.

## Assumptions

- Repo name (`Path.name` of git toplevel) keys the global store path, unchanged from today.
