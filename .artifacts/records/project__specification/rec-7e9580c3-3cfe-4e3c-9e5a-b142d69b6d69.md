## Requirements

R1: The affidavit package declares a dependency on adaptive-artifacts.
R2: The orchestra package declares a dependency on adaptive-artifacts.
R3: The orchestra package does not declare affidavit as a required dependency.
R4: The orchestra `evidence` extra declares a dependency on affidavit.
R5: `orchestra install` into a clean environment leaves that environment able to import `adaptive_artifacts`.
R6: `orchestra install` into a clean environment without the evidence extra does not install affidavit.
R7: With `ADAPTIVE_ARTIFACTS_BIN` unset, orchestra opens the store by importing the library.
R8: `open_store` raises when the contract `format` is not a format this build lists as supported.

## Acceptance criteria

R1–R4: a test reads the three `pyproject.toml` files.
R5–R6: an integration test runs `orchestra install` into a temporary environment and asserts the imports.
R7: a test opens a store with the discovery variables unset and asserts the import path is used.
R8: a test points `open_store` at a store whose contract format is `adaptive-artifacts/project-design@0.0.0` and asserts it raises.

## Constraints

Version compatibility is a dependency plus the contract format (`version-check`). Plugin install and `uv` install the same dependency graph. Command lookup does not search plugin roots or sibling checkouts.

## Non-goals

Publishing version tags stays on the packaging backlog item `version-tag-releases`. This phase does not vendor package source into the plugin payload.

## Invariants

A clean orchestra install can import adaptive-artifacts. It cannot import affidavit unless the evidence extra was requested. An unknown contract format fails at open time.

## Assumptions

The supported contract format today is `adaptive-artifacts/project-design@0.3.0`. Cursor plugin install can run a package install into the environment that provides the `orchestra` command.
