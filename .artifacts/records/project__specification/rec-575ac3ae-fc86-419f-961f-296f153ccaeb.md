## Requirements

R1: Skills resolve the se-workflow plugin root via `${CLAUDE_PLUGIN_ROOT}` or `${CURSOR_PLUGIN_ROOT}` (then skill-relative layout), not by hardcoding `~/.cursor/plugins/local/se-workflow` as the primary path.

R2: `se_workflow.aa` and `dashboard.artifact_store` share one adaptive-artifacts binary resolution order: explicit env override (`ADAPTIVE_ARTIFACTS_BIN` / `ADAPTIVE_ARTIFACTS_ROOT`), then plugin-root / sibling plugin discovery, then PATH. `~/adaptive-artifacts` is not a quiet primary fallback.

R3: `se-workflow close-batch` builds the close NDJSON batch with the same behavior as today's `scripts/close_batch.py` (including red-first refusal). Skills (`verify-work`) call that subcommand, not `python3 …/scripts/close_batch.py`.

R4: ensure-store and related skill docs describe the plugin-root order; skill/contract consistency remains green for every documented `adaptive-artifacts` / `se-workflow` invocation.

## Acceptance criteria

- Unit tests cover the shared AA resolver order (env, plugin-root/sibling, PATH) and assert home-checkout is not preferred over PATH when both exist (or is absent from the order).
- CLI test: `se-workflow close-batch` accepts a fixture close-request and emits the same NDJSON shape / exit codes as the former script entry.
- Grep / skill tests: verify-work and ensure-store do not document `scripts/close_batch.py` as the entry; they document `se-workflow close-batch` and plugin-root env vars.
- `python3 -m pytest tests/test_skill_contract_consistency.py -q` passes after skill edits.

## Constraints

- Do not change adaptive-artifacts runtime code in this phase (extension change gate).
- Do not rename se-workflow → agent-affidavit; that stays backlog.
- Store writes still go through `adaptive-artifacts`; close-batch only builds the apply batch.

## Non-goals

- Version tagging, version compat checks, or PyPI packaging.
- Making Claude/Cursor auto-inject PATH for installed plugins beyond documenting plugin-root env vars.
- Expanding close-batch to apply the batch itself.

## Invariants

- Runner-produced check-runs remain the authority for tdd/check pass/fail; close-batch does not invent results.
- Parent session remains the only store writer; close-batch still emits NDJSON for `adaptive-artifacts apply`.

## Assumptions

- Hosts set `CLAUDE_PLUGIN_ROOT` / `CURSOR_PLUGIN_ROOT` (or skill-relative paths still work when skills run from the plugin tree).
- After marketplace install, `adaptive-artifacts` is discoverable via plugin-root sibling or PATH for normal use.
