## Requirements

R1: Per-task verification stays the existing scoped `verify_command` (and phase verification acceptances); this phase does not require affected-test selection (testmon or path map).
R2: Once per phase, after closing verification and the phase-end reviewer have passed, and before merge to `main`, the parent starts the full non-tmux suite (README fast form) plus the serial tmux leg in a background tmux window in the phase worktree, without blocking the agent session on the run.
R3: The runner records one `project:check-run` for the tier-2 run with integration/regression evidence kind as designed, `revision` = phase head SHA, exit code, duration, output digest, and failing node IDs when failed.
R4: The phase gate requires (a) every active phase acceptance has a passing runner check-run at the phase head SHA and (b) a passing tier-2 check-run at that same SHA before close/merge.
R5: A tier-2 failure produces fix work-item(s) under the retry-loop budget (clustered by failing test file/module); there is no inline fix-and-rerun inside the verification step. After fixes, tier-2 reruns at the new head.
R6: The dashboard shows tier-2 status on the phase header (running / passed / failed at SHA).
R7: Skills and verify-budget tests are updated so per-task verification stays scoped while the phase-level full run is required.
R8: Affected-test selection and a polished flaky-marker auto-retry policy are out of scope; flakes may be listed when observed but need not auto-retry in this phase. CI owning tier-2 is future work.

## Acceptance criteria

- Background tmux full-suite run at phase head is documented and invocable; agent is not blocked for the duration.
- One tier-2 check-run is recorded at the head SHA with runner metadata.
- Phase gate requires head-SHA acceptance passes and passing tier-2 before merge.
- Tier-2 failure creates fix work-item(s) under retry budget; no inline verifier fix loop.
- Dashboard shows tier-2 status per phase.
- Skills/README/`test_verify_budget.py` adjusted; skill↔contract consistency green.
- Follow-up for CI-owned tier-2 noted as future (issue or non-goal), not implemented here.

## Constraints

- Reuses check-runner for recording runs and retry-loop for fix tasks.
- verify-budget's per-task time discipline remains; full suite is phase-level only.
- No `.github/` CI in this phase.

## Non-goals

- pytest-testmon or path-map affected-test selection
- Full flaky-marker auto-retry policy (minimal listing ok)
- CI taking over tier-2
- Changing dashboard human-approval dismiss UX

## Invariants

- Tier-2 never silently skipped when the phase claims ready to merge.
- Failures become tasks; `done` items are not reopened.
- Per-task checks stay narrowly scoped.

## Assumptions

- Phase worktree and tmux are available in the dogfood environment (existing dashboard/tmux support).
- Phase-end reviewer runs before tier-2 when both are deployed (ordinal order).
