## Requirements

R1: Ship `agents/se-reviewer.md` (or Cursor-equivalent) configured without Write/Edit tools; execute-phase invokes it once at phase end after the closing verification task and before merge (and before tier-2 when that phase exists).
R2: The reviewer receives only task descriptions (including Approach goals), acceptance criteria, requirement/invariant text for structured work, and the phase diff/tree at phase head — not execution reports, check-runs, assessments, or builder notes. A test asserts the brief/prompt excludes those.
R3: The reviewer itself writes nothing to the store. The parent records one `project:check-run` with `method: review`, `evidence_kind: review`, `revision` = phase head, `result` pass|fail from the verdict, and one `project:finding` per NEEDS_WORK item.
R4: NEEDS_WORK findings of kinds that are fixable (spec-gap, behavior-bug, missing-test, invariant-violation as applicable) become fix work-items via the retry-loop fix-task mechanism and budget; the reviewer re-runs once on the new diff; budget exhaustion escalates to the user.
R5: The phase gate requires a passing review check-run at the phase head SHA before merge (and before tier-2 when present).
R6: The phase integration report content is produced from the reviewer's structured output (parent still writes the record).
R7: A regression fixture replays the `status-tabs` scenario (description lists more UI than acceptance/diff deliver) and the reviewer returns NEEDS_WORK with a spec-gap finding.
R8: Per-task review and pre-dispatch coverage checks are out of scope for this phase.

## Acceptance criteria

- `agents/se-reviewer.md` (or documented Cursor equivalent) exists with restricted tools; execute-phase documents the phase-end invocation order.
- A test asserts the reviewer brief excludes execution-report, check-run, and assessment content.
- Parent records `method: review` / `evidence_kind: review` check-run at head and findings for NEEDS_WORK; reviewer writes no store records.
- Fixable NEEDS_WORK items create fix work-items under the retry budget; one re-run after fixes; exhausted budget escalates.
- Phase gate requires passing review at head before merge.
- Integration report is filled from reviewer output.
- `status-tabs` fixture yields NEEDS_WORK / spec-gap.
- Skill↔contract consistency stays green.

## Constraints

- Single-writer store; reviewer is read-only by configuration where the host supports it.
- Reuses retry-loop fix-task and budget machinery; does not redefine it.
- `method: review` / `evidence_kind: review` already allowed by the contract where declared.

## Non-goals

- Optional `review: per-task` during task close
- Pre-dispatch description-vs-acceptance coverage check at plan review
- Tier-2 full suite (tiered-verification phase)
- Dashboard approval UX

## Invariants

- Reviewer never calls `adaptive-artifacts`.
- Reviewer is not given builder self-grades as inputs.
- Gaps become new fix tasks; `done` work-items are not reopened.

## Assumptions

- Claude Code `agents/` tool restriction is available; Cursor gets the best equivalent documented in the skill if weaker.
- Closing verification has already run once before the first reviewer pass (order: last wave → verification → reviewer → tier-2 → merge).
