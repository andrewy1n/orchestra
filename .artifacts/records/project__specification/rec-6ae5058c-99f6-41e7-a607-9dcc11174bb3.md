## Requirements

R1: `contract/project-design.json` declares a top-level `phase_gate.suite` object with `mode` (`none|smoke|full|external`), `command` (string), and `gate` (`required|advisory|deferred`).

R2: Plugin/bundled default is `mode=none` (empty command). When `mode` is not `none` and `command` is non-empty, omitted `gate` means `required`.

R3: For structured deliver/repair phases, `execute-phase` reads `phase_gate.suite` from the project design: skips the suite when `mode=none`; otherwise runs the configured command (background worktree runner) and records one check-run at phase head with subject `<phase>-suite` (not `-tier2`).

R4: Landing gate: `gate=required` blocks merge on missing/failing suite check-run at head; `advisory` records pass/fail and opens a finding on fail but does not block merge; `deferred` does not run locally and lists a Landing human stop to await external/CI evidence.

R5: Skills, README, dashboard, and `se_workflow` runner rename tier-2 vocabulary to suite/regression; dashboard phase header shows suite status from the new subject convention.

R6: This repository's design sets `mode=full`, `gate=advisory`, and the README full-suite command.

R7: Red-first close-batch behavior for `method: tdd` is unchanged; the phase suite is never red-first.

R8: Agents do not waive or weaken suite policy; changing mode/command/gate requires a contract edit. Skill↔contract consistency and suite/gate tests stay green.

## Acceptance criteria

- A project design with `mode=none` never starts a phase-end suite and does not require a suite check-run to merge.
- A design with `mode=full` (or smoke) and `gate=required` blocks Landing without a passing `<phase>-suite` check-run at head.
- A design with `gate=advisory` records a failing suite check-run and still allows Landing when other gate bullets pass.
- se-workflow's own design pins full+advisory; execute-phase and dashboard no longer require the literal subject suffix `-tier2`.
- `tests/test_tiered_verification.py` (or successor), verify-budget, skill-contract consistency, and dashboard suite-status tests pass for the new policy.

## Constraints

- Do not put whole-suite commands on per-task `verify_command` (verify-budget still holds).
- Do not extend red-first to the phase suite.
- Do not patch adaptive-artifacts runtime for this phase unless the top-level `phase_gate` key is rejected; prefer the same pattern as existing `assessment` on the design.

## Non-goals

- Affected-test / testmon selection.
- CI webhook automation for `external`/`deferred` (document the human stop only).
- Flake auto-retry policy.
- Changing acceptance methods or evidence_kind enums beyond using them correctly on suite check-runs.
- Fixing `journal-detail-xdist-flake` (separate backlog).

## Invariants

- Task acceptances at phase head and phase-end review remain required for structured Landing.
- Suite policy is contracted; agents enforce only.
- Per-task verification stays scoped.

## Assumptions

- Skills can read `phase_gate` from the project design JSON the same way other project metadata is read today.
- Background tmux / worktree runner remains available when a suite command is configured.
- Incidental work continues to skip reviewer and suite.
