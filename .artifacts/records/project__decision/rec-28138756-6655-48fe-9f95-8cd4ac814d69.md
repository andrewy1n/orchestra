## Rationale

`git add -A` is safe only in a worktree that contains one task's edits. Parallel tasks on `<repo>/.worktrees/<phase-slug>` share that index, so one task's commit can record another task's unfinished files. An orientation warning does not stop the command the skill already gives them. Giving every non-verification task its own branch and worktree makes that command local. Verifying before the merge keeps the check-run SHA equal to that task's commit. Merging passing branches into the phase branch at wave end leaves the phase worktree as the integration checkout for the verification task and the phase-end suite. The same rule for a wave of one and for inline work removes a second path that could still pick up leftovers.

## Counter-argument

Isolating only waves of two or more tasks avoids a worktree and a merge for the common solo task. A clean phase worktree can take that one commit directly. That leaves crashed leftovers, and any later overlap, on the shared tree this phase is closing.
