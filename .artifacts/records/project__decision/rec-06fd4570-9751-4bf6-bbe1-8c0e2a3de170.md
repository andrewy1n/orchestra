## Rationale

Compound requirement ids let one acceptance "cover" a bundle while only testing part of it. Atomic ids (one observable behavior each) plus one acceptance per id make coverage by id meaningful. Deliver and repair must carry ids even without a specification: for light work the description is the id'd list. Incidental stays exempt so one-chat fixes are not forced through a fake requirements chain. Lint and plan-review catch compounds; the owner approves splits.

## Counter-argument

Requiring a light specification for every deliver/repair would put all ids in one place and simplify briefs. That collapses the two-modes simple path and makes typo-sized phases pay specify/design overhead the evidence-loop decision already rejected.
