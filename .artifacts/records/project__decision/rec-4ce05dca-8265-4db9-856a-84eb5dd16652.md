## Rationale

The page polls `GET /api/token` and fetches the snapshot only when `dashboard.model.change_token` changes. That is the same check the terminal uses on an interval, and it is what the live spike already does. Detail views refetch after a token change. No long-lived connection is required.

## Counter-argument

Server-sent events would push a new token as soon as the store changes, which is a better fit for a page that can approve and reject: the operator should see a stale item immediately. Polling leaves a gap of one interval where the page can submit a revision that has already moved.
