## Description

Third-round reviewer findings:

1. `tests/test_library_e2e.py` is the only real-affidavit claim-gated close oracle, but its acceptance payload had no `claim`, so after R1 its close ran neither verdict nor recheck and its docstring was false. Add `payload.claim` and assert it on the stored acceptance.
2. `_manifest_claim_ids` returns an empty set for both an absent manifest and a present manifest with no claims, so a non-empty `claim` is accepted against an empty manifest. R9 requires refusal. Distinguish absence (skip) from an empty/malformed manifest (refuse). Add a test.
3. Making the e2e oracle non-vacuous exposed an import-order test-isolation bug: `test_claim_clocks` imports `affidavit.binding` while `affidavit.verdict.run_verdict` is patched, so binding permanently captures the patched function. Preimport `affidavit.binding` in `tests/conftest.py` before any patch.

## Approach

Add `"claim": CLAIM_ID` to the e2e acceptance and assert it. Make `_manifest_claim_ids` return `None` only when the manifest file is absent, and have `_enforce_claim_gates` skip only on `None`. Add an empty-claims manifest refusal test to `tests/test_close_batch.py`. Add a session autouse conftest fixture that inserts `$HOME/affidavit` on `sys.path` and imports `affidavit.binding`. Do not edit `tests/test_claim_clocks.py`.
