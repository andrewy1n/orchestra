## Description

R1: Modules under `orchestra/` open the store by calling `adaptive_artifacts.project.open_store`.
R2: Modules under `dashboard/` open the store by calling `adaptive_artifacts.project.open_store`.
R3: `orchestra/aa_resolve.py` is not in the tree.
R4: `dashboard/artifact_store.py` is not in the tree.
R10: `pyproject.toml` declares a dependency on adaptive-artifacts.

## Approach

Delete `orchestra/aa_resolve.py` and `dashboard/artifact_store.py`. Point `orchestra/aa.py`, `orchestra/cli.py`, `orchestra/suite.py`, `orchestra/check.py`, and every dashboard module that imported `artifact_store` at `adaptive_artifacts.project.open_store` and `Project.get`, `Project.create`, or `Project.apply`. Do not reimplement binding and do not start `adaptive-artifacts`. Add adaptive-artifacts to `pyproject.toml`. Update tests that imported the deleted modules so they use `open_store`. You may edit `orchestra/close_batch.py` only so store access still works. Do not replace its `aff` subprocess calls.
