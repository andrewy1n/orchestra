## Rationale

One `web` job on one runner is simple. Steps run in the order lint, check, test, build. The job always runs, so a required check never stays pending.

## Counter-argument

One job per step gives faster feedback and a clear failing name in the pull request. It costs four runners that each run `npm ci`. A path filter saves runner time but can leave a required check stuck as pending.
