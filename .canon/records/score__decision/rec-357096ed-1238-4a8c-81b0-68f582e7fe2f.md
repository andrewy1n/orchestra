## Rationale

Phase 2 of the monorepo plan puts each component's tests in `tests/<component>/`. Canon and tuner already have those trees and their own conftests. Score, conductor, composer, stage, and the top-level `installer` package still have tests directly in `tests/`. The directory name matches the import root, so `installer` stays `tests/installer/` rather than `tests/stage/`, for the same reason the package stays top-level. The new trees keep the root `tests/conftest.py` and are collected by the existing orchestra pytest invocation. Canon and tuner stay isolated because their conftests must not mix. Dashboard, CLI, and packaging tests stay put because `dashboard-split` and `wheel-contents` name those paths.

## Counter-argument

Giving each new tree its own conftest and a separate `scripts/test.sh` process would match canon and tuner, and would make a component suite runnable without the product fixtures. Most of these tests import the root `conftest` fixtures today. A private conftest would duplicate that setup or break the imports.
