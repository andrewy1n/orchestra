## Rationale

`dashboard/web/ui/dist` is gitignored build output. The wheel never ships it, and `dashboard.web.app` reports "No web build" without it. Shipping it needs a Node build in CI, package-data for `dist`, and a larger wheel. That is a packaging change, not a smoke check, and it belongs in its own phase. This phase stays on the Python surface. A `composer:idea` records the gap so it does not get lost. The user chose this.

## Counter-argument

A smoke job that passes while the web dashboard cannot start from the installed wheel gives false confidence. The gap is a user-visible break, and the smoke job is the natural place to find it. Asserting the absence in the smoke check, or fixing it now, would make the gap loud instead of leaving it in the backlog.
