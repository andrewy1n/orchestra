## Rationale

The snapshot is already polled and carries `area` on each effort. Grouping it in the browser keeps one source of truth for effort state, and the pages update on each poll with no new API fields. Only the promoted-idea lines need the backend, because the store drops an idea's area when it is promoted, so the join through the effort's placement must happen where the records are read.

## Counter-argument

A backend that returns the area tree gives the frontend one call and one shape to render. It can also compute rollups once and test them in Python. The client-side join spreads grouping rules over the frontend and the backend.
