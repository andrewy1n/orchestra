## Rationale

`aff verdict` is already a function of the repo and two revisions. `aff check` and `aff close-batch` exist to write workflow records, so they leave this binary. Their command names become `orchestra check` and `orchestra close-batch`, which makes the store client look like orchestra. The assertion-level rule stays one function, `affidavit.oracle_red.is_assertion_level_red`, and the moved close path imports it. Orchestra does not import `run_verdict` or the store modules that used to live here. A gate answer is still the exit code of `aff verdict`. Orchestra already needs this checkout on PATH to run that command, so the import does not add a new runtime dependency.

## Counter-argument

An orchestra-fronted `aff` would keep the skill strings `aff check` and `aff close-batch` and exec this repo only for `verdict`. The skills, the boundary tests, and the README already lock those strings in, and this phase's exit only requires a standalone checkout to produce a verdict. A wrapper avoids a skill migration. It also leaves two programs named `aff`, and a session with the wrong one first on PATH loses `check` or hides the split this phase is making.
