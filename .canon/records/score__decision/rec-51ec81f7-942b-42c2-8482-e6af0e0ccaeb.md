## Rationale

Today pass/fail is an agent claim. Hard authority makes the CLI the only producer of binary check-runs for `tdd`/`check`, so `result` comes from an exit code and runner metadata is always present. Agents still write assessments (`level`, `next`). That is the trust boundary red-first, tiered verify, and a phase-end reviewer need.

## Counter-argument

Preferring the runner while still allowing agent-authored check-runs would avoid breaking close_batch and legacy verify-work paths. The cost is keeping the path that produced dirty and malformed evidence in the dogfood store.
