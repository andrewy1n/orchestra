## Rationale

The records for `dashboard`, `workflow-loop`, `packaging`, `session-analysis`, and `test-suite-speed` move to the orchestra store, with the code that continues those efforts. This repo's store keeps `evidence-layer`. The next session in orchestra can read the decisions and phase history that shaped the skills and the dashboard.

## Counter-argument

The store is revision-chained, and a record on one side can reference an id that belongs on the other. Leaving the orchestration records here as history needs no split. Orchestra could start with an empty store and point back at this repo when it needs the old efforts.
