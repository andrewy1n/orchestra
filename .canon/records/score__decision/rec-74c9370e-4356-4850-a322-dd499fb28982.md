## Rationale

Default `suite.mode=none` means a fresh project has no phase-end suite gate until a human sets a command and mode. When mode is not `none` and a command is set, default hardness is `required` so configured suites still mean something. Modes are `none|smoke|full|external`; gates are `required|advisory|deferred`.

## Counter-argument

Defaulting to today's full+required would preserve safety for se-workflow-like repos out of the box, but it reintroduces the hours problem for any consumer whose suite is long or flaky, which is exactly the failure mode this phase exists to stop.
