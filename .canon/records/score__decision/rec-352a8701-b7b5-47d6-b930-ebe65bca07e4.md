## Rationale

Unit tests already build ephemeral subject repos the same way. Tracking templates plus a CI setup step keeps the workflow path stable, avoids committing a nested `.git`, and matches the incomplete handoff note that "fixture setup must provide" the directory.

## Counter-argument

A checked-in nested git history would leave the workflow YAML almost untouched and freeze a known SHA. Nested repos and submodules are harder to clone and review than plain templates plus `git init` in the job.
