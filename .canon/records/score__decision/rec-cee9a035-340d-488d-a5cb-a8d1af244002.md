## Rationale

A backend interface lets the file store keep running while the SQLite backend and the importer are built and tested against a copy of the live store. The live store never moves until cutover, and the old code path is removed in the same phase.

## Counter-argument

Replacing the engine in place avoids a second code path and an interface sized only for two implementations. The interface costs work in `access-layer` and a parametrized test suite. The benefit depends on the importer being risky enough to need a rehearsal, and a single failed import is recoverable from the pre-cutover export.
