## Rationale

A passing check-run still needs a real commit SHA, and that SHA has to be the task's own commit. The commit now happens on `task/<phase-slug>/<task-slug>` before verify. The parent merges that branch into `phase/<phase-slug>` only after the check passes, so a failed check does not land and the passing SHA stays reachable from the phase branch. Rebase is refused because it would move the SHA the check-run already cited.

## Counter-argument

Committing on the shared phase branch, with a path-limited `git add` instead of `git add -A`, keeps one line of history and no merge step. A complete path list would leave other tasks' files unstaged. It does not stop two writers from racing on one index, and two worktrees cannot check out that same phase branch.
