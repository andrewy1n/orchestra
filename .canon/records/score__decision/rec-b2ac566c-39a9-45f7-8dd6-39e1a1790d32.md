## Rationale

The installer, provider matrix, adapters, and tests are Python. A standard-library prompt keeps one runtime and no Node prerequisite, and the caveman installer shows that a numbered prompt is enough for this decision surface. The JS comparison was useful for behavior, not for the language.

## Counter-argument

A JS TUI wrapper would make an `npx` one-liner possible and could reuse a richer prompt library. A full JS rewrite would align with the JS-first host ecosystem. Both add a second runtime, duplicate the matrix and adapter logic, and split the release and test surface for a command that is not performance-sensitive.
