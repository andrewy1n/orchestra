## Rationale

CI calls the `uv run pytest` commands directly as parallel jobs, one per pass: canon, tuner, orchestra tree, and tmux. Each pass gets its own job name and log. `-n auto` uses the runner cores. `scripts/test.sh` is untouched and stays the local entry point. The user said `scripts/test.sh` is expected to give way to plain pytest commands. The records show `wheel-contents` rewrites it to four `uv run pytest` lines, so the YAML mirrors those lines.

## Counter-argument

A pass selector in `scripts/test.sh` (`test.sh canon`) keeps one source of truth for the pytest arguments. Copying them into YAML lets local and CI drift when a pass changes, for example when `component-tests` adds ignores. The drift risk is real, and the mitigation here is only that the commands are short.
