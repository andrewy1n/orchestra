## Rationale

Snapshot `TaskRow` today exposes `waits_on` subjects, not stable depends_on ids. Enriching phase/snapshot task JSON with depends_on ids (from the model relationship already consulted when building rows) lets the client draw edges without N+1 task detail fetches.

## Counter-argument

Fetching each task's detail for edges would avoid model changes. That was rejected as too chatty for a phase overview poll.
