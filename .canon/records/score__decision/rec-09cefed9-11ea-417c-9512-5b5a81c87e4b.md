## Rationale

The DB is outside git, so git no longer backs it up. `canon backup` uses the SQLite online backup API to write a consistent copy to `~/.canon/<repo>/backups/` and keeps the 14 newest. The SessionStart hook runs it when the newest copy is over 24 hours old. A disk loss then costs at most about a day.

## Counter-argument

A manual `canon export` adds no hook and no retention rule. It also depends on the user remembering, and a backup that depends on memory is usually missing when needed. Backups on the same disk as the DB also do not protect against disk loss, only against corruption and mistakes.
