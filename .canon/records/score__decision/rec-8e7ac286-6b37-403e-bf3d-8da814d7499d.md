## Rationale

`tests/test_boundaries.py` lets every component import `orchestra.canon` and lets none of them be imported by canon. A git runner and a record-payload function belong there, and every copied caller can use them. `parse_failing_node_ids` and the output hash already exist in `orchestra.conductor.check`; `suite` calls those instead of keeping a second copy. ssh-keygen stays in `orchestra.tuner` because signing is tuner's. The eleven API paths are one table in `dashboard`, and both servers dispatch through it. The helper returns a process result. `dashboard.landing` still turns failure into `None`, and `check.git_head` still raises.

## Counter-argument

Moving only the byte-identical functions would avoid treating different git calls as one wrapper. `check` raises, landing returns `None`, and tuner worktree commands are not the same operation as `rev-parse`. Leaving those at the call site is a smaller diff and keeps each error policy next to the command that needs it. The copies the phase names would mostly remain.
