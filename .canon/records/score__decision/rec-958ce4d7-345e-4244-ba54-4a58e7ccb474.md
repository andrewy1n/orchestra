## Rationale

`<failure>` is `assertion_failed` and `<error>` is `errored`. `<skipped>`, and a requested id with no case, are `not_run`. A case with both a failure and an error is `errored`. Collection and setup failures stay non-assertions, which is the red `test_verdict_refuses_not_assertion` already checks. A fixture runner and a later vitest or `go test` template can emit those two tags. They do not have to emit the text `AssertionError`.

## Counter-argument

Requiring `AssertionError` in the failure message would keep today's rule for an exception raised inside the test. A test that raises `ModuleNotFoundError` in the body is not evidence that the behavior was absent. The tag rule accepts that red. Orchestra's close path still uses `oracle_red` for that stricter check.
