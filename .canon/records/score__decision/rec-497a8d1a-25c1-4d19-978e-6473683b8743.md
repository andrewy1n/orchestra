## Rationale

The user chose a facade. `open_store` plus get, list, create, and apply is the surface the next two phases import. The command resolves its store through that opener, so the command and the library cannot pick different directories. The other commands stay in the command module, so this phase does not rewrite hooks, watch, or view generation.

## Counter-argument

Moving every command body into the library in this phase would leave one implementation for the whole command surface, so a later flag could not be added only on the command side. The cost is rewriting lock, resolve, hooks, and watch before any caller needs them.
