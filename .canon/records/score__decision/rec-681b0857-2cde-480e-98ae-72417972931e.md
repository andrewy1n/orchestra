## Rationale

The data phase touches the composer schema, the CLI, a skill and the API. The UI phase touches only the frontend. Each phase can be verified alone. The UI starts from a stable, tested data contract.

## Counter-argument

One phase avoids a stretch where the data exists and no page shows it. One review sees the whole change. Two phases add a second settle, plan and close for work that the user sees as one feature.
