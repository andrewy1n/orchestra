## Rationale

CI builds temporary DB stores in tests and checks the schema snapshots. The live store is not an input to CI, because it is no longer in git. This keeps CI independent of one machine's data.

## Counter-argument

A committed deterministic export lets CI run `canon validate` on the real records and catch a bad one before merge. It changes on every write, so a large generated file returns to every PR diff. That is the noise this effort removes.
