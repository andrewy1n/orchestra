## Rationale

The reviewer's value is one canonical prompt plus one restriction set: read-only tools, no store writes, structured PASS/NEEDS_WORK. Compiling that into Claude's `tools:`, OpenCode's `permissions:` plus `mode: subagent`, and Cursor's closest read-only configuration keeps the reviewer available on every host without three hand-edited copies. Generation is testable, and a change to the prompt reaches every host at once.

## Counter-argument

Inlining the reviewer prompt into `execute-phase` is maximally portable: no agent file, no frontmatter differences, and no host can fail to discover it. The parent must then enforce the read-only rule itself, and the reviewer loses the isolated subagent context that keeps builder self-reports out of the review. A Claude-only agent file is the least work, but leaves other hosts with a generic subagent and no hard read-only guard.
