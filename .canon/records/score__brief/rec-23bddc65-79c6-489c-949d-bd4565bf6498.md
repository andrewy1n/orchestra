## Problem

The canon store is about 27,000 tracked files. One record write touches two or three of them, so git diffs are unreadable. Worktrees hold stale copies of the store. A multi-record write is not atomic.

## Users

The user, and the parallel agent sessions that read and write the store.

## Success measure

`.canon/` holds no tracked record files. Parallel writers lose no writes. Importing the current store and folding every chain reproduces every revision hash.

## Non-goals

Multi-machine sync. Dolt-style cell merge. Support for adaptive-artifacts or affidavit, which are retired.
