## Evidence

expected: the phase specification says a temporary-HOME install for Claude and OpenCode loads the generated skill dirs, and `npx skills add --list` resolves a generic profile (R11, R12).

observed: no test, README text, or installer code mentions `--list`. `tests/integration/test_temp_home_install.py:test_temp_home_install_uses_skills_cli_for_a_generic_host` stubs `npx` and only asserts the `skills add -a codex` invocation and marker profile; `tests/test_installer.py` does the same. The clause is unbacked.

The `skills` CLI does support `add --list` (`-l`): "List available skills in the repository without installing." That is a discovery command, not the installer's delegate path, so the clause may be a drafting error rather than an installer defect.

## Consequence

The specification's acceptance is not demonstrated. R11's actual requirement (delegate at least one non-native host to `npx skills add` and report the profile) is covered by the stubbed test.

## Follow-up

Add a stubbed `--list` test if the intent is to prove skill discovery, or amend the specification to remove the clause and clear this finding.
