## Evidence

expected: OpenCode auto-loads local plugins from `.opencode/plugins/<file>` (project) or `~/.config/opencode/plugins/<file>` (global), or from a `plugins` entry in `opencode.json(c)`.

observed: `hosts/opencode/plugin.js` is merged at the install root by `NativeAdapter.desired_entries`, so the installer writes `<project>/.opencode/plugin.js` or `~/.config/opencode/plugin.js`. The OpenCode V2 docs say plugins under `.opencode/plugins/` are loaded automatically; the root file is not discovered. `tests/test_installer.py:549,593` and `tests/integration/test_temp_home_install.py:99` pin the root path, so no test catches the host-shape error.

## Consequence

OpenCode `hook-start`/`hook-stop` are inert. Hooks are optional and skills self-start, so the impact is limited to losing the automatic reminder, but R12's "installed where the host reads it" is not met.

## Follow-up

One more fix task: move the payload to `<root>/plugins/plugin.js` (or register it in `opencode.json`), update the installer tests and README to the documented path, and confirm OpenCode still installs when plugin support is absent.
