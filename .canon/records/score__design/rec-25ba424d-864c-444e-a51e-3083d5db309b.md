## Architecture

The phase runs as a short runbook, then a cleanup.

1. Commit the pending store changes in the working tree.
2. Freeze: no other session writes to the store.
3. Run `canon export` to `~/.canon/<repo-name>/backups/pre-cutover.jsonl`, then `scripts/verify_import.py` on the live store.
4. Create the DB with `canon import`, and run `canon validate` and the count comparison.
5. Flip `config.json` to `"backend": "sqlite"` and `store-binding.json` to `{"store": "global"}`. `git rm -r` the `log/`, `records/` and `history/` trees and add them to `.gitignore`.
6. Check `orchestra handoff`, the dashboard server and a worktree read.
7. Delete the file backend, `Store`, `record_file.py` and the file-layout part of `oplog.py`. Collapse the parametrized suite to the SQLite backend.
8. Wire `canon backup` into the SessionStart hook in `orchestra/stage/hooks.py`.
9. Rewrite `AGENTS.md` and `skills/ensure-store.md`, regenerate the skill copies, and replace the `canon validate` step in `ci.yml` with the schema and fixture checks that `test-canon` already runs.

The phase's own task and closing records write to the file store until step 5, and to the DB after. The export in step 3 is taken last, so no record is lost.

Rollback before step 7: check out the commit before the switch, whose file backend and files are intact. After step 7: check out the pre-cutover commit and import the pre-cutover export into a file store.

## Interfaces

- SessionStart hook calls `canon backup` when the newest file in `backups/` is older than 24 hours.
- `.canon/config.json` key `backend`.
- `.canon/store-binding.json` value `global`.

## Decisions

canon-ci-store-check, canon-old-history.

## Invariants

The switch changes no record id or revision. Exactly one store takes writes at any time.

## Assumptions

- No other session writes to the store during steps 2 to 5.
- `~/.canon/<repo-name>/` does not already hold another project's data.

## Tradeoffs

CI no longer checks live records, in return for a CI that does not depend on one machine's data. Deleting the file backend removes the second code path, at the cost of an easy rollback after step 7. The pre-cutover export and the pre-cutover commit cover that.

## Risks

- A writer slips in after the export. The freeze in step 2 and a diff of record counts in step 7 catch it.
- The cleanup in step 7 is large. Plan-phase can move it to its own task group or split the phase.
- Git history keeps the old files, so clones stay as large as today.
