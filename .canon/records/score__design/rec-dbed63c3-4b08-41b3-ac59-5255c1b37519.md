## Architecture

`standalone-aff` makes `aff` the verdict command and moves the store client into orchestra (`store-commands-home`, `aff-orchestra-seam`). The product remains an audit of one change from git (`affidavit-product`). This phase ships the verdict half. The hunk, mutant, and differential commands wait.

1. Move `affidavit/check.py`, `affidavit/close_batch.py`, `affidavit/aa.py`, `affidavit/aa_resolve.py`, and `affidavit/policy.py` into the `orchestra` package as `orchestra.check`, `orchestra.close_batch`, `orchestra.aa`, `orchestra.aa_resolve`, and `orchestra.policy`. Move `affidavit.tmux` to the orchestra repo root and point it at that repo's `dashboard/bin`. Move `tests/test_affidavit_check.py`, `tests/test_close_batch.py`, `tests/test_affidavit_aa.py`, and `tests/test_aa_resolve.py` with them, retargeted at the new modules.
2. Add `~/orchestra/bin/orchestra` with `check` and `close-batch`. Arguments match today's `aff` subcommands. The script inserts the orchestra checkout on `sys.path` the way `bin/aff` inserts this repo.
3. Retarget in-tree imports. `orchestra.suite` imports `orchestra.aa`, `orchestra.check`, and `orchestra.policy`. `dashboard/artifact_store.py` imports `orchestra.aa_resolve`. Orchestra tests that import `affidavit.aa`, `affidavit.aa_resolve`, `affidavit.check`, `affidavit.policy`, or `affidavit.close_batch` import the `orchestra` modules instead.
4. `orchestra.close_batch` imports `is_assertion_level_red` from `affidavit.oracle_red`. `orchestra/__init__.py` still puts the affidavit checkout on `sys.path` so that import works when the working directory is not this repo. Nothing in orchestra imports `affidavit.verdict`, `affidavit.aa`, `affidavit.aa_resolve`, `affidavit.check`, or `affidavit.policy`.
5. Strip `affidavit/cli.py` to `verdict`. Delete the moved modules from this repo. Rewrite the `affidavit` package docstrings so no module under `affidavit/` contains `project:`, `SE_WORKFLOW_STORE`, `store-binding.json`, or `adaptive-artifacts`. `verdict.py`'s module doc says it does not read a record store, without naming that runtime.
6. Add a test here that fails when a fixture module under `affidavit/` contains any of those four strings, and passes on the package as shipped. Update `tests/test_evidence_layout.py`, `README.md`, `AGENTS.md`, and `CLAUDE.md` so they describe a verdict-only `aff` and send check, close-batch, and the store client to orchestra.
7. In orchestra skills, replace `aff check` with `orchestra check` and `aff close-batch` with `orchestra close-batch`. Leave `aff verdict` as the gate. Update the skill boundary tests that assert those command strings.

## Interfaces

- `aff verdict --cwd <repo> --at <sha> [--base <sha>] <claim-id>` stays the gate. Same arguments, same JSON on stdout, same exit: 0 when `result` is `pass`, 1 otherwise. `aff check` and `aff close-batch` are not commands.
- `orchestra check` and `orchestra close-batch` take the arguments `aff check` and `aff close-batch` take today, including `--cwd`.
- Python: `orchestra.close_batch` imports `affidavit.oracle_red.is_assertion_level_red`. `affidavit.verdict` imports `affidavit.oracle_red.is_assertion_level_failure`. No other orchestra module imports affidavit.
- `~/affidavit` provides `bin/aff`. `~/orchestra` provides `bin/orchestra`. A skill session has both on PATH.
- Forbidden strings in `affidavit/**/*.py`: `project:`, `SE_WORKFLOW_STORE`, `store-binding.json`, `adaptive-artifacts`.

## Decisions

- `affidavit-product`: affidavit audits a code change from git. This phase is the verdict command. The other audit commands are later phases.
- `store-commands-home`: check, close-batch, and the store client move to orchestra.
- `aff-orchestra-seam`: `aff` is verdict-only. The store commands are `orchestra check` and `orchestra close-batch`. Orchestra imports `affidavit.oracle_red` and does not import `run_verdict`.
- `verb-home` still says `aff check` and `aff close-batch` stay on this binary. `store-commands-home` and `aff-orchestra-seam` are the later choice for those two commands. Reviewer, suite, and the deleted `tier2` shim stay as `verb-home` recorded them.

## Invariants

- `aff verdict` does not read the artifact store. A stored check-run does not change its result.
- One assertion-level implementation lives in `affidavit.oracle_red`. Verdict and the moved close path both call it.
- Affidavit does not import orchestra. Orchestra's store client does not import affidavit, except the close path's import of `affidavit.oracle_red`.
- A `tdd` or `check` result is written by `orchestra check`.

## Assumptions

- Both checkouts exist at `~/affidavit` and `~/orchestra`. This phase edits both. The affidavit worktree does not contain the orchestra tree.
- `aff` and `orchestra` are on PATH for a skill session.
- `evidence-kind` will edit orchestra's close path, because that is where a close refusal lives after this phase.
- The rewrite of skill command strings is in scope for this phase. Leaving `aff check` in a skill fails R5.

## Tradeoffs

- Orchestra cannot import `run_verdict`, so a gate pays for a process and a PATH lookup. That is the boundary a stored check-run cannot cross.
- `ensure_affidavit_importable` remains. Orchestra's close path needs the affidavit package on `sys.path`.
- Every skill line that says `aff check` or `aff close-batch` changes. The boundary tests that lock those strings change with them.
- `evidence-kind` can no longer extend `aff close-batch` in this repo. Its refusal lands in `orchestra close-batch`.

## Risks

- A missed `from affidavit.check` or `from affidavit.aa` import in orchestra fails at runtime only when that path runs. The R4 import ban belongs in an orchestra test, not only in review.
- `bin/orchestra` and the Python package `orchestra` share a name. The launcher must insert the checkout on `sys.path` before importing, as `bin/aff` does, or it imports the wrong module.
- A skill session with `orchestra` missing from PATH still has `aff verdict` and has lost `check` and `close-batch`. The session scripts that put `aff` on PATH must put `orchestra` there too.
- Grep for `adaptive-artifacts` will fail until `verdict.py` and `affidavit/__init__.py` drop that word, even though those lines describe an absence.
