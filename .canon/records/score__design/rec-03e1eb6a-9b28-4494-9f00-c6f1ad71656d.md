## Architecture

Two layers, one source of truth.

```
orchestra/
  skills/<name>/SKILL.md        # authored instructions
  shared/                       # ensure-store.md, kinds-and-focus.md (one copy)
  agents/reviewer.prompt.md     # canonical prompt + restriction block
  hosts/
    claude/                     # plugin.json, marketplace.json, hooks/
    cursor/                     # plugin.json, marketplace.json, hooks/
    opencode/                   # plugin.js, agent frontmatter
  installer/                    # provider matrix + adapters
  src/orchestra/                # runtime package
  pyproject.toml                # console script: orchestra
```

A build step (`scripts/build_skills.py`) emits `dist/skills/<name>/`:
`SKILL.md` plus `references/ensure-store.md` and `references/kinds-and-focus.md`.
Authored skills reference `references/...`; the build copies from `shared/`
and rewrites the path. `dist/skills` is what the installer and `npx skills add`
consume. The repo-authored `skills/` tree may keep the build-time form or the
generated form, but only one is authoritative and the drift test names it.

The runtime layer is a normal Python package with a `pyproject.toml` console
script. It owns every capability skills currently reach for by file path:
contract emission, project-field rewrite, session reports, check, and
close-batch. `bin/orchestra` remains a thin shim so checkout and plugin
installs keep working.

The installer layer is one entry point with a provider matrix. Each adapter
implements `detect()`, `plan()`, `apply()`, `verify()`, and `remove()`.
Native adapters exist for Claude Code, Cursor, and OpenCode. Every other host
maps to `npx skills add -a <profile>`; an unknown host falls back to a plain
skills-directory install and prints the path it used.

## Interfaces

```text
orchestra install [--only <host>]... [--all] [--global] [--copy]
                  [--dry-run] [--uninstall] [--home <dir>]
orchestra contract [--write <path>]
orchestra project-field rewrite <design.json>
orchestra sessions report|aggregate [args]
orchestra check ...              # unchanged
orchestra close-batch ...        # unchanged
```

- `--only` may repeat; `--all` selects every detected native host and the
  generic tail; `--dry-run` prints the plan and writes nothing; `--uninstall`
  removes exactly what the adapter registered.
- `--global` installs to user directories; the default is project-local.
- `--copy` copies instead of symlinking to the canonical install.
- `--home` redirects the whole install for tests.
- The host matrix lives in one data file (`installer/providers.toml` or
  `.json`) so README, tests, and the report read the same rows.

## Decisions

- `portable-skill-references`
- `installer-native-tail`
- `reviewer-agent-generation`
- `optional-native-hooks`

## Invariants

- Generated reference copies are byte-identical to their source.
- Skills call `orchestra`, `adaptive-artifacts`, and `aff` by name only.
- No adapter copies `.artifacts/`, `.worktrees/`, or dashboard state.
- The installer is idempotent: one registration per host per install scope.
- Store writes stay parent-only; subagents never write records.
- Existing checkout and plugin installs keep working.

## Assumptions

- `npx skills add` keeps its `-a <profile>` interface and profile ids.
- Hosts read `SKILL.md` from the paths in the provider matrix.
- `uv` is available wherever the CLI install is documented.
- OpenCode accepts a `skills` config source and `agents/*.md`.
- Claude and Cursor manifest schemas stay compatible.

## Tradeoffs

- Generated references duplicate text and add a build step, in exchange for
  single-directory portability.
- Delegating the tail to `npx skills` trades control for coverage and update
  handling.
- Native hook adapters add three small host modules; without them, every
  session depends on the skill remembering `hook-start`.
- Keeping `bin/orchestra` as a shim leaves two entry points, but avoids a
  flag day for existing installs.

## Risks

- Reference drift if a source edit bypasses the build. Mitigation: drift test
  and a build check in the suite.
- `npx skills` profile names or flags change. Mitigation: one matrix row per
  host, a single invocation point, and a test that stubs the CLI.
- Host skills paths move. Mitigation: paths live in the matrix, not in code.
- A hook adapter breaks a host's startup. Mitigation: hooks are optional and
  installation succeeds without them; skills self-start.
- Installer writes over user edits. Mitigation: compare before write, offer
  `--copy`, and make `--dry-run` the documented first step.
