## Architecture

`pyproject.toml` keeps setuptools and the explicit `packages` list. Add `dashboard`, `dashboard.web`, `installer`, and `installer.adapters`. Add `installer = ["providers.json"]` to package-data so `installer.matrix` reads the file next to the installed module.

`[project].dependencies` lists `textual>=0.80`, `rich`, `fastapi`, and `uvicorn`.

`[dependency-groups] dev` lists `pytest`, `pytest-xdist`, `httpx`, `pip`, `setuptools`, and `wheel`.

`orchestra/sessions.py` becomes the package `orchestra/sessions/`. `report` and `aggregate` import their submodules. The moved modules are `session_report`, `session_aggregate`, `record_join`, `record_reader`, `session_fields`, `session_metrics`, `session_outliers`, `session_tools`, and `tool_skill_rollup`. Their cross-imports become package imports. `session_aggregate` imports `effort_rollup` from `orchestra.score`.

`scripts/effort_rollup.py` moves to `orchestra/score/effort_rollup.py`. `scripts/build_skills.py`, `scripts/check_orchestra_plugin_names.py`, and `scripts/test.sh` stay.

Delete the `orchestra/_scripts` symlink. `orchestra.sessions` no longer reads `ORCHESTRA_SCRIPTS` or inserts a directory on `sys.path`. The `ModuleNotFoundError` handlers in `orchestra.cli` for canon, suite, and check go away so the import error propagates. The sessions command no longer catches `ModuleNotFoundError`.

`scripts/test.sh` calls `uv run -q pytest` with the same pytest arguments it passes today. It does not pass `--no-project` or `--with`. README, AGENTS.md, and `FAST_SUITE_CMD` / `TMUX_SUITE_CMD` in `orchestra.conductor.suite` use that form.

## Interfaces

- Editable install: `uv tool install --editable` of this repository, or the equivalent `pip install -e` used by `tests/test_cli_packaging.py`.
- `import dashboard`, `import dashboard.web`, `import installer`, `import installer.adapters`.
- `orchestra.sessions.report` and `orchestra.sessions.aggregate`.
- `orchestra.score.effort_rollup.effort_rollup`.
- `scripts/test.sh` as the phase-gate command already set in `.canon/config.json`.

## Decisions

- `top-level-dashboard-installer`: `dashboard` and `installer` stay top-level packages.
- `explicit-wheel`: extend the explicit package list, require the dashboard libraries, and move session modules and `effort_rollup` into the packages.
- `suite-project-env`: test tools live in the `dev` group, and `scripts/test.sh` runs `uv run pytest`.

## Invariants

- The installer payload root remains the parent of the `installer` package.
- `dashboard` and `installer` are not `orchestra.*` packages.
- Runtime dependencies and the `dev` group stay separate lists.

## Assumptions

- `uv run` includes the `dev` group unless `--no-dev` is passed.
- `httpx` imports under `fastapi.testclient`.

## Tradeoffs

- Every orchestra install gains Textual, Rich, FastAPI, and uvicorn. A canon-only install is no longer dependency-free.
- An explicit package list misses a new subpackage until someone adds a line. `find_packages` would hide that miss and could also pick up stray directories.

## Risks

- FastAPI tests that `importorskip("fastapi")` will run once the dependency exists. They need `httpx` in the dev group or collection fails.
- `tests/test_cli_packaging.py` shells out to `pip`. The dev group has to put `pip` on `PATH` for `uv run`.
- Tests that insert `scripts/` on `sys.path` fail until they import the new modules.
