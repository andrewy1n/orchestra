## Architecture

New package `orchestra/composer/` with `__init__.py`, `AGENTS.md` and `schemas/` (`__init__.py`, `composer.json`). It holds no Python logic in this phase. `pyproject.toml` adds the package, its `schemas/*.json` package data, and the entry point `composer = "orchestra.composer.schemas"`. `tests/test_boundaries.py` adds `composer` to `COMPONENTS` with allowed imports `canon`, `score`, `composer`, and lets `stage` import composer. The test conftests add `composer.json` to `CANON_SCHEMA_PATH`. The live store gets composer through `canon schemas add composer`.

## Interfaces

`composer.json`, version `1.0.0`:

- `composer:area` — lifecycle `current`; fields `title` (string); sections `Scope`.
- `composer:idea` — lifecycle `current`; fields `status` (enum `open`, `promoted`, `dismissed`), `area` (ref `composer:area`, optional), `effort` (ref `score:effort`, optional), `phase` (ref `score:phase`, optional), `source` (string, optional); no required sections.

## Decisions

- `composer-area-meaning`: an area is a product area.
- `composer-score-direction`: composer sits above score.
- `composer-idea-lifecycle`: ideas use `current` with a status enum.

## Invariants

- `score.json`, `conductor.json` and `tuner.json` are unchanged.
- composer imports only canon and score.

## Assumptions

- The editable install regenerates `orchestra.egg-info` with the new entry point after `uv tool install --editable`.

## Tradeoffs

- No required idea body section keeps conversion of backlog items simple, but an idea may have no description.
- Optional `effort` allows product-level ideas, but the roadmap must handle ideas with no effort.

## Risks

- A stale `orchestra.egg-info` without the composer entry point hides the module from the CLI until reinstall.
- Adding composer to the live store changes `config.json`; a tool that hardcodes three namespaces may break.
