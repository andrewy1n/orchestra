## Architecture

1. New `affidavit/audit.py` (+ CLI) porting hunk-revert flow and capped mutant planting.
2. Use verdict-style worktrees and `run_tests` with frozen claims at head/base as appropriate.
3. Emit advisory JSON; labels match spike vocabulary.
4. Cap mutant count; read proposals from LLM/tool optional path but judge only via tests.

## Interfaces

- `aff audit --base <sha> --head <sha>` → JSON
- Block labels: noticed | not_noticed | inconclusive (plus untested if kept)
- Survivor list in JSON

## Decisions

- `audit-hunk-mutants`: productize spikes; not mutmut-only; not hunk-only.

## Invariants

- Never target test-file blocks.
- Advisory only for verdict.

## Assumptions

- frozen claims and runner path are stable.

## Tradeoffs

- Porting spikes costs more than shelling out to mutmut; keeps label semantics.
- Advisory means agents can ignore output unless orchestra wires it.

## Risks

- Runtime cost of many reverts. Mitigation: caps, skip tiny hunks, cache.
