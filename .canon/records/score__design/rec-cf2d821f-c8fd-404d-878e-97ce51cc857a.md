## Architecture

A new `adaptive_artifacts.project` module owns project-root and store resolution. `Store` remains the filesystem kernel. The command module parses arguments and prints JSON. Path selection in the command calls `open_store`. Get, list, create, and apply have one implementation on `Project`. The command's create, get, and apply call that implementation. The command's list keeps its query flags and runs them against the store `open_store` returned. Every other command keeps its current body and only changes how the store path and contract path are chosen.

## Interfaces

`open_store(directory, *, store=None) -> Project`

`Project` carries the project root, the store path, the contract path, and the binding that won (`local` or `global`, and the source: argument, `ARTIFACTS_STORE`, a binding file, or default).

`Project.get(record_id, record_type=None) -> dict` returns the stored record. It raises when the id is absent.

`Project.list(record_type) -> list[dict]` returns every record of that type.

`Project.create(*, record_type, subject, payload, body=None, rels=None) -> dict` writes one record and returns the stored record, including its id and revision.

`Project.apply(operations) -> list[dict]` takes a sequence of operation objects, the same objects the command reads from NDJSON, writes them, and returns each result.

Resolution failures raise `StoreBindingError`. A missing record raises an error that names the id. Write failures use the existing store errors.

## Decisions

- `library-facade`: project facade with four operations; other commands stay in the command module.
- `store-resolution`: opener lives here; `SE_WORKFLOW_STORE` is not read; explicit path, then binding files, then repo meta, then home meta.
- `call-style`: Python imports this module; agents keep the command.
- `three-repos`: this phase does not edit orchestra or affidavit.

## Invariants

The command and `open_store` select the same store for the same directory and environment. A selected store with no `meta.json` does not fall through. One `open_store` call opens one store.

## Assumptions

`local` is `<project root>/.artifacts`. `global` is `~/.artifacts/<project root directory name>`. `meta.json` marks an initialized store. A worktree's git toplevel is the worktree.

## Tradeoffs

Callers of get, list, create, and apply do not learn the oplog. Callers who need `--where` or update still use the command until a later phase moves those operations. Two list paths exist for this phase: unfiltered `Project.list`, and the command's query flags over the same store.

## Risks

A worktree with no `.artifacts/meta.json` and no binding file used to fall through to the main checkout's store. It now tries `~/.artifacts/<worktree name>` and raises when that has no `meta.json`. Existing command tests that depended on the git-common-dir fallback need a binding file or a meta.json in the worktree.
