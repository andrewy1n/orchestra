## Architecture

The release workflow runs `npm ci` and `npm run build` in `dashboard/frontend`, then builds the wheel. `pyproject.toml` lists `dashboard/frontend/dist/**` as package data. The `ci:wheel-smoke` job gains a check that `GET /` returns the index. A Playwright test in `dashboard/frontend/e2e` starts the server through a small Python launcher on a seeded store, opens the page, and asserts that a seeded effort name shows.

## Interfaces

- The server serves `dist` from the package directory when it exists, and otherwise returns the "No web build" message with the build command.
- `npm run e2e` runs the Playwright test.
- A launcher script starts the server on a free port with a seeded store and prints the URL.

## Decisions

- `wheel-smoke-ownership`: depend on `ci:wheel-smoke`.
- `dist-packaging`: CI builds `dist`, and package data ships it.
- `e2e-browser-tool`: a Playwright browser test.

## Invariants

- `dist` is not committed.
- Python development works without Node.

## Assumptions

- `ci:wheel-smoke` exists and installs the wheel in a clean environment.
- The path of `dist` inside the package is the same in the source tree and in the wheel.

## Tradeoffs

- The browser install adds CI time. One small test keeps it short.

## Risks

- The Playwright test is flaky. Mitigation: wait on a visible element, not on time, and use one test.
- The package-data glob misses files. Mitigation: R1 checks the wheel contents.
