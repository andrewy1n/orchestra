## Architecture

- `orchestra/composer/schemas/composer.json` gains a `placement` type. Lifecycle `current`. Required field `area`, a ref to `composer:area`. The schema version moves to 1.1.0.
- `orchestra/composer/placement.py` adds `place(project, effort, area)`. It resolves the effort as `score:effort` and the area as `composer:area`, and raises `PlacementError` when either is missing. It creates the placement, or supersedes the active one with its current revision.
- `orchestra/cli.py` adds `orchestra place <effort> <area>`, written like `_cmd_idea`.
- `dashboard/backend/snapshot.py` reads `composer:placement` records by type string, as `areas.py` does, and sets `EffortView.area`.
- `dashboard/backend/server/schemas.py` adds `area: str` to the effort model. `dashboard/frontend/openapi.json` and `src/api-types.ts` are regenerated with `npm run api-types`.
- `skills/engage/SKILL.md` gains a step: after a new effort exists, run `orchestra place <effort> <area>`.
- The backfill runs `orchestra place` once per effort in the confirmed mapping.

## Interfaces

- CLI: `orchestra place <effort> <area>`. Exit 0 on success. Exit nonzero with a message on `stderr` when the effort or area is missing.
- Library: `orchestra.composer.placement.place(project, effort, area) -> dict`.
- API: `GET /api/snapshot`, each effort row gains `area: string`.
- Record: `composer:placement`, subject = effort slug, payload `{"area": "<area-slug>"}`.

## Decisions

- `placement-record-link`: a placement record per effort.
- `area-phase-split`: two phases, data then UI.
- `backfill-confirm`: the agent proposes a mapping and the user confirms it.

## Invariants

- One active placement per effort.
- The placement subject equals the effort slug.
- `composer` imports only `canon` and `score`.
- The snapshot `area` field is always present.

## Assumptions

- Canon rejects a second active record with the same type and subject.
- `canon schemas sync` refreshes the store snapshot of the composer schema.
- `skills/engage/SKILL.md` has one place where a new effort is created.

## Tradeoffs

- A new record type and command add surface. In return, the link has one owner, one lookup and no layering break.
- A placement is read with a second query per snapshot. The cost is one `canon list` over a small set.

## Risks

- The schema snapshot in `.canon/schemas/` goes stale. Mitigation: run `canon schemas sync` and commit it. CI already checks the snapshot.
- The Python 3.10 CI runner differs from local runs. Mitigation: run the new tests on 3.10 before the push.
- An effort is renamed or merged and its placement points to a missing effort. Mitigation: the snapshot ignores placements with no matching effort.
