## Architecture

Three changes land in order.

1. Consumers switch to `composer:idea`: `orchestra/views.py` (backlog role), `dashboard/model.py` (`BacklogItem`, panel query), `dashboard/backlog.py` (promote and dismiss), `skills/engage/SKILL.md`, the docs, and the tests.
2. `orchestra/score/schemas/score.json` loses `backlog-item` and `feedback`.
3. On the primary checkout, a one-shot script renames every `score:backlog-item` record and history snapshot to `composer:idea` with `apply_steps`. Commit the store. Run `canon schemas sync`, then commit again.

The script lives in the scratchpad and is not shipped. A test proves the same rename on a temporary store.

## Interfaces

- `composer:idea` payload: `status` (open | promoted | dismissed), `effort`, `phase`, `source`.
- `canon list --type composer:idea --where payload.effort=<focus> --where payload.status=open --state active` replaces the backlog list in `engage`.
- `dashboard.backlog.BACKLOG_TYPE` becomes `composer:idea`. Function names and signatures stay.
- The handoff backlog role reads `composer:idea` with fields `effort` and `status`.

## Decisions

- `backlog-conversion-method`: rename in place, no version bump.
- `idea-panel-scope`: effort-linked ideas only on the dashboard.
- Earlier, from `composer-schema`: `composer-idea-lifecycle`, `composer-score-direction`.

## Invariants

- Ids, subjects, bodies and history of converted records do not change.
- score does not import composer.
- Promote and dismiss keep `effort`, `source` and `phase`.

## Assumptions

- `composer-schema` is merged to `main` before this phase starts.
- No other chat writes the store during the conversion.
- Nothing outside this repo reads `score:backlog-item`.

## Tradeoffs

- No version bump means no replayable migration. A clone with an old score snapshot needs the same rename run by hand.
- Dashboard behavior stays the same, so effortless ideas have no dashboard view until phase `idea-triage`.

## Risks

- Run the rename before the consumers switch and the dashboard shows an empty backlog. Land the code first, convert second.
- Run `canon schemas sync` before the rename commit and validate reports immutability violations. Commit the rename first.
- The primary checkout has uncommitted edits in `tests/test_dashboard_app.py`, `tests/test_dashboard_model.py`, `tests/test_assess_routing.py` and `dashboard/model.py`. The phase branch starts from `main` and does not see them. Merging back may conflict.
