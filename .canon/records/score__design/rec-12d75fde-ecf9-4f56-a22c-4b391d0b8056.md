## Architecture

Add `depends_on: list[str]` (task ids) to the serialized task row used by web snapshot/phase detail (model `TaskRow` or web `jsonable` adapter). On Overview, a `TaskGraph` view groups tasks by wave into columns and draws edges from those ids. Skip rendering when `tasks.length <= 2`.

## Interfaces

- Model/web: include depends_on ids on task JSON.
- UI: `buildWaveGraph(tasks) -> { lanes, edges }`; SVG or HTML/CSS columns.
- Node click → `taskHref(id)`.
- Tests: pure graph builder + render smoke test.

## Decisions

- `task-graph-layout`
- `task-graph-edge-data`
- `task-graph-tiny-skip`

## Invariants

- List/strip remains available (R5).
- No cross-phase edges.

## Assumptions

- Wave is already on task rows; missing wave treats the task as its own lane key (existing estimate/wave conventions).

## Tradeoffs

- Slightly larger snapshot payloads vs N+1 fetches.
- Simple lane layout may cross edges visually on dense DAGs; acceptable for typical phase sizes.

## Risks

- If `phase-overview` is not merged first, this phase must either depend on it or embed a minimal Overview mount point for the graph.
