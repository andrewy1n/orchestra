## Architecture

The Textual app stays the tmux dashboard. The web dashboard is a second viewer and writer on the same model.

`dashboard/web/` holds a FastAPI app. Its PEP 723 dependencies are fastapi and uvicorn, launched with uv the way `dashboard/__main__.py` launches Textual. `dashboard/bin/web` is the launcher and uses `dashboard.artifact_store.resolve` for the current directory.

`dashboard/web/ui/` is a Vite project: Svelte 5, TypeScript, Tailwind, npm. It is not part of the orchestra wheel.

In development, Vite serves the UI and proxies `/api` to FastAPI. In use, FastAPI serves `ui/dist` at `/` and the JSON API on the same origin. There is no CORS middleware.

The app caches a `dashboard.model` snapshot keyed by `change_token`, including lazy detail loads, as the spike's `Cache` does. Writes call `dismiss_item`, `backlog.dismiss_item`, and `backlog.promote_item` and then drop the cache.

The Svelte app keeps the spike's screen map. Effort rail, main pane, and side column are components. Phase, task, requirement, record, Needs you, and backlog open as overlays. Routes stay hash URLs, matching the live spike, so static serving needs no client-side fallback.

The page polls `/api/token` about every two seconds, the terminal's default interval. On a new token it reloads the snapshot and the open detail.

## Interfaces

GET `/api/token` → `{token}`.

GET `/api/snapshot` → `{token, generated_at, store, efforts}`, efforts shaped as the spike's `effort_summary`.

GET `/api/phase?effort&phase` → phase detail, `tabs_for` tabs, and the decision log.

GET `/api/task?id` → task detail.

GET `/api/journal?effort` → `{open, rest}` from `dashboard.journal`.

GET `/api/record?id` → one journal record.

GET `/api/requirement?effort&phase&id` → requirement detail.

GET `/api/needs?effort&id` → one Needs you item, including `revision` and `approval.confirm_choices`.

GET `/api/backlog?effort&id` → one open backlog item.

POST `/api/needs` JSON `{effort, id, action, note?}`. The server reloads the item, sets the revision the client sent onto that item, and calls `dismiss_item`. `action` is `approve`, `reject`, `sign`, or `accept`. Signer comes from `default_signer()`. 409 when `dismiss_item` reports a stale revision. 400 when the kind or action is refused, or a required note is missing.

POST `/api/backlog` JSON `{effort, id, action}` where `action` is `dismiss` or `promote`. The server calls `backlog.dismiss_item` or `backlog.promote_item`.

GET `/` serves `ui/dist` when the build exists. A missing build returns a short message naming `npm run build`.

Vite `server.proxy` sends `/api` to the FastAPI port. The dev server does not talk to the store itself.

## Decisions

- `web-dashboard-shape`: a frontend toolchain beside Textual, sharing `dashboard.model`.
- `web-dashboard-toolchain`: Vite and Svelte over the spike's JSON API.
- `web-dashboard-writes`: the page performs the terminal's Needs you and backlog writes.
- `web-dashboard-server`: FastAPI.
- `web-dashboard-freshness`: poll the change token.
- `web-dashboard-styling`: Tailwind, keeping the spike's screen map.

## Invariants

- Store reads go through `dashboard.model`. Store writes go through `dashboard.dismiss` and `dashboard.backlog`.
- The listen address is 127.0.0.1.
- The write API does not accept a signer.
- The API does not send `Access-Control-Allow-Origin`.

## Assumptions

- `dashboard-package-layout` still holds: this code lives under `dashboard/`, not a new top-level app and not in `orchestra/`.
- `dashboard-deps` still holds for the terminal. The web launcher has its own PEP 723 header.
- The spike's GET shapes are the contract the Svelte app codes against.

## Tradeoffs

- FastAPI adds uvicorn and a schema layer the stdlib spike did not need, and it gives one place to test writes.
- Polling is a short stale window in exchange for a stateless GET.
- Tailwind rebuilds the mock's look. The screen map stays.
- Writes in the browser duplicate the terminal's confirm rules so the page is usable without tmux. The terminal keeps its own controls.

## Risks

- The two UIs can drift on labels, confirm rules, and which kinds are actionable.
- Any process on the machine can POST to the loopback port.
- A poll interval can approve a revision that changed after the page rendered. The dismiss path rejects that case; the page has to show it.
- The first Tailwind pass can spend time on appearance before the API is covered.
- Node is a new build dependency for a Python repo. The use path fails closed when `ui/dist` is missing.
