## Architecture

A new module `orchestra/canon/backend.py` holds the `Backend` protocol and `open_backend(store_root, config)`. The factory reads `config.get("backend", "files")` and returns `Store` (the file backend) or, from phase `db-backend`, `SqliteBackend`.

The protocol covers what callers use today:

- config and schema snapshots: `load_config`, `write_config`, `write_snapshot`
- lifecycle: `init`, `is_absent`
- records: `read_record`, `iter_records`, `record_exists`, `create_record`, `write_record` with `expected_revision`, `new_id`
- chains: `read_ops`, and `iter_history` for `merge` and `sync`
- one write unit: `transaction()`, a context manager. The file backend implements it with its `fcntl` lock. The SQLite backend implements it with `BEGIN IMMEDIATE`.
- `check_integrity(errors)`, which holds the checks that depend on the layout.

`validation.py` splits in two. Checks that need only records (schema, references, lineage) stay in `validation.py` and use `iter_records`. Layout checks (path tamper, the `git diff HEAD` immutability check) move into the file backend's `check_integrity`.

The six external touches move to the API. `orchestra init` calls the factory. The dashboard lists through `Project.list`. The view reference renders the record id without a link, so no code outside canon needs a file path.

## Interfaces

- `Backend` protocol in `orchestra/canon/backend.py`
- `open_backend(store_root: Path, config: dict) -> Backend`
- `Backend.transaction() -> ContextManager[None]`
- `Backend.check_integrity(errors: list[str]) -> None`
- A boundary test in `tests/canon` that scans imports and path building outside `orchestra/canon/`.

## Decisions

canon-backend-coexist.

## Invariants

Behaviour of the file backend does not change. The protocol never exposes a path. A store with no `backend` key opens as files.

## Assumptions

Plan-phase confirms the exact method list by reading every caller. The protocol is the union of what they call.

## Tradeoffs

An interface sized for two implementations adds indirection that disappears after cutover, when the file backend is deleted. The alternative, replacing the engine in place, has no rehearsal path for the importer.

## Risks

- The protocol grows to mirror `Store` and keeps file-shaped methods. The "no path in a signature" invariant and the boundary test limit this.
- The view change in R7 alters derived output that tests and humans read. The change is small and covered by `tests/test_views.py`.
