## Architecture

A new `web` job in `.github/workflows/ci.yml` checks out the repo, sets up Node, runs `npm ci` in `dashboard/web/ui`, then runs lint, check, test, and build. The npm cache keys on `package-lock.json`. Biome is configured by `dashboard/web/ui/biome.json`. `AGENTS.md` gains a TypeScript and Svelte section.

## Interfaces

- `npm run lint` runs `biome check` with warnings counted as errors.
- The existing scripts `check`, `test`, and `build` stay as they are.
- The section in `AGENTS.md` lists: strict types, no `any` or `@ts-ignore` without a one-line reason, the repo comment rule, one component per `.svelte` file, tests beside the source as `*.test.ts`, no hand formatting, and the three commands to run before closing a task.

## Decisions

- `ts-lint-tool`: Biome with full Svelte support.
- `web-ci-job-shape`: one `web` job that always runs.
- `lint-findings-policy`: fix the findings and keep zero.

## Invariants

- The lint gate allows zero findings.
- The `web` job has no path filter and no dependency on other jobs.

## Assumptions

- A Node version exists that Vite 8 and the pinned Biome both support.
- The Biome rule set can be tuned (for example `noNonNullAssertion`) in `biome.json` without per-line suppressions.

## Tradeoffs

- Experimental Svelte support is accepted for one tool and fast runs.
- Cleaning code that phase `ui-structure` will move is accepted for a clean gate from the start.

## Risks

- A Biome minor release changes the experimental behavior. Mitigation: an exact version pin and a deliberate upgrade.
- Biome formats Svelte markup in a way that disagrees with shadcn-svelte generated files. Mitigation: decide in phase `ui-structure` whether generated component paths are excluded from the formatter.
