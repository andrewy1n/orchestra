## Architecture

`orchestration-split` separates the evidence CLI from the orchestration plugin. This repo keeps `aff check`, `aff close-batch`, and `aff verdict` (`verb-home`, `repo-split`). A new repo at `~/orchestra` becomes the plugin `orchestra` (`orchestra-name`). Its contract id is `orchestra`, and existing `affidavit` project fields are rewritten to that (`contract-project`). Orchestration effort records move with the code; `evidence-layer` stays here (`effort-records`).

1. Create `~/orchestra` as a new git repository. Its first commit is the moved tree: `skills/`, `dashboard/`, `scripts/`, `agents/`, the plugin manifests, the bundled contract, and the tests that cover those trees. Copy `affidavit/reviewer.py` and `affidavit/suite.py` into an `orchestra` package (`orchestra.reviewer`, `orchestra.suite`). Delete the `tier2_*` aliases at the bottom of `suite.py` as part of that move. Delete `affidavit/tier2.py`. Do not add `orchestra.tier2`. Update skill text that imported `affidavit.reviewer` or `affidavit.suite`.
2. Before deleting `dashboard/` from this repo, move the store-binding resolver that `affidavit.aa` imports out of `dashboard.artifact_store` and into `affidavit/aa_resolve.py`. `affidavit.aa` imports that. The dashboard keeps its own `artifact_store.py`.
3. Delete the moved paths from this repo. This repo's pytest suite is what remains: the `aff` verbs, the manifest, amendments, and the oracle-red classifier.
4. Set the bundled contract's `"project"` to `orchestra`. Teach ensure-store: `orchestra` is current; `affidavit` is rewritten to `orchestra`; any other value stops the overlay. Apply that rewrite to this repo's store and to the orchestra store.
5. Copy this store into `~/orchestra/.artifacts`. Relocate whole record directories (record file, log, and history) so the five orchestration efforts are present only in the orchestra store and `evidence-layer` is present only here. Do not edit the bytes of a record that stays. When a kept record references a moved id, keep that referenced record in both stores. Run `adaptive-artifacts resolve` and `adaptive-artifacts validate` in each checkout.
6. Point orchestra skills at `aff` on `PATH` for `check`, `close-batch`, and `verdict`. For an acceptance whose claim is in `.affidavit/manifest.json`, the skill runs `aff verdict` and treats a non-zero exit as not done. Skill text no longer creates or corrects a `project:check-run` with method `tdd` or `check`, and no longer creates or supersedes `project:oracle-amendment`. Oracle hash and test-id changes are signed manifest amendments.
7. Replace the one-line `git commit -m "<task-slug>"`, `git commit -m "<phase-slug>"`, and `git commit -m "<phase-slug> store"` snippets. Each message uses a Conventional Commits subject, `type(scope): summary`, and a body of one or two sentences on why (`commit-message`). `type` is `feat`, `fix`, `docs`, `refactor`, `test`, or `chore`. A task commit names the task slug in the body. The same shape applies to the `records:` commit in `ensure-store`.

## Interfaces

- `aff check`, `aff close-batch`, and `aff verdict` stay the evidence CLI. Their arguments are unchanged in this phase.
- Orchestra skills resolve `aff` from `PATH`. `~/affidavit` is the checkout that installs that binary.
- Python imports after the move: `orchestra.reviewer` and `orchestra.suite`. Those modules may import `affidavit`. `affidavit` does not import `orchestra` or `dashboard`. There is no `tier2` module on either side. The dashboard may still display a historical check-run subject that ends in `-tier2`.
- Bundled contract path: `~/orchestra/contract/project-design.json`, with `"project": "orchestra"`.
- ensure-store migration: rewrite `"project": "affidavit"` to `"project": "orchestra"` on the work repo's `.artifacts/project-design.json`, then resolve. Leave any other project value untouched and stop.
- Forbidden skill writes, matched as text in `skills/`: `create` or `correct` of `project:check-run` with method `tdd` or `check`; `create` or `supersede` of `project:oracle-amendment`.
- Store cut: efforts `dashboard`, `workflow-loop`, `packaging`, `session-analysis`, `test-suite-speed` in the orchestra store; effort `evidence-layer` in this store.
- Commit message: subject is `type(scope): summary`. A blank line, then one or two sentences on why. A task commit names the task slug in that body. Passed with a heredoc so the body is part of the message.

## Decisions

- `repo-split` (already recorded): this repo stays the evidence layer; skills, dashboard, and session scripts move to a new repo.
- `verb-home`: `aff check`, `aff close-batch`, and `aff verdict` stay here. Reviewer and suite move with the plugin. The `tier2` shim is deleted.
- `orchestra-name`: the repo and plugin are `orchestra`. Skill slugs stay.
- `contract-project`: the contract project field becomes `orchestra`, and `affidavit` is migrated to that.
- `effort-records`: the five orchestration efforts' records move to the orchestra store. This store keeps `evidence-layer`.
- `commit-message`: Conventional Commits subject, `type(scope): summary`, plus a body on why. A task commit names the task slug in the body.

## Invariants

- `aff verdict` does not read the artifact store. A stored check-run does not change its result.
- A `tdd` or `check` check-run is produced by `aff check`.
- Import direction is orchestra to affidavit. The affidavit package has no import of `dashboard` or `orchestra`.
- Neither package defines a `tier2` module. Suite is `orchestra.suite`.
- A record file that remains in a store keeps the bytes that hash to its revision.

## Assumptions

- `~/orchestra` is a new repository. Its first commit contains the moved tree. This repo's git history is unchanged except for the deletions on its branch.
- `aff` is on `PATH` for an orchestra session.
- Record directories for one effort can be relocated when no surviving record on the other side references them. A cross-reference is duplicated into both stores.
- The rewrite of project `affidavit` to `orchestra` is already approved.

## Tradeoffs

- `check` and `close-batch` still shell out to adaptive-artifacts, so this repo is standalone for `aff verdict` and still store-backed for the other two verbs.
- The dashboard's store resolver and the copy inside `affidavit/aa_resolve.py` can drift.
- Two stores share a contract id and a duplicated contract file. Later contract edits belong in the orchestra repo, then get copied here so this store still resolves.
- Orchestra's git history starts at the split. Blame for the skills and the dashboard stops at that commit.

## Risks

- A dangling `relationships` or payload id after the record move fails validate. The recovery is to duplicate the referenced record into both stores, not to edit either copy.
- ensure-store's rewrite touches every work repo still marked `affidavit`, including this one. A repo that used `affidavit` as a foreign project name would be rewritten too. The stop rule for every other name is what contains that.
- Skills that still tell an agent to import `affidavit.reviewer` or to create a `tdd` check-run fail the boundary test until the text is updated.
- `evidence-kind` expects to extend close. Moving `close-batch` later would reopen `verb-home`.
