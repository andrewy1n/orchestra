## Architecture

Replace `dashboard/model.py` with the package `dashboard/model/`. `__init__.py` re-exports the names that `dashboard/` and `tests/` import today. The implementation modules are:

- `store.py` for catalog, list, and the canon reads.
- `snapshot.py` for `load_snapshot` and the effort, phase, task, needs, and backlog rows used by the main view.
- `task.py` for `load_task_detail` and its row types.
- `phase.py` for `load_phase_detail`, `load_decision_log`, and the phase evidence types.
- `requirement.py` for `load_requirement_detail`.

Those modules import each other only downward: `store` imports canon, and the feature modules import `store` and the row types they need. None of them import Textual or Rich.

Screen classes leave `dashboard/app.py`, except `DashboardApp`. `NeedsYouDetailScreen` and `NeedsConfirmModal` go to a needs screen module. `BacklogDetailScreen` goes to a backlog screen module. `PhasePickerScreen` and `KeyHelpScreen` go to a picker module. Widgets used only by a moved screen move with it. `DashboardApp` and the main-pane widgets stay in `app.py`.

`dashboard/web/` is unchanged except for imports that follow a moved model name. The route table from `shared-helpers` stays in `dashboard/web/`.

## Interfaces

- `import dashboard.model` and `from dashboard.model import <name>` for every name imported today.
- `load_snapshot`, `load_task_detail`, `load_phase_detail`, `load_decision_log`, and `load_requirement_detail` keep their signatures.
- `DashboardApp` remains in `dashboard.app`.

## Decisions

- `dashboard-feature-modules`: feature modules for the model, screens out of `app.py`, and a `dashboard.model` facade.

## Invariants

- Nothing under `dashboard/model/` imports `textual` or `rich`.
- There is no `dashboard/model.py` file beside the `dashboard/model/` package.
- The Textual screens and the web JSON keep their current behavior.

## Assumptions

- The names imported from `dashboard.model` at the start of this phase are the facade's public surface.
- `shared-helpers` may already have removed `dashboard.model`'s local payload getter. The facade re-exports whatever the feature modules define after that.

## Tradeoffs

- A phase change touches `dashboard/model/phase.py` and `dashboard/phase_screen.py`. A vertical slice would have been one file and would have pulled Textual into the model.
- The facade hides which module owns a name. A reader follows the re-export to find the definition.

## Risks

- A cycle between `snapshot` and `task` if both need each other's row types. Row types that both need go in a module neither feature module owns, or in the module that defines them, and the other imports that type only.
- `dashboard/model.py` and `dashboard/model/` cannot coexist. The switch is one change, and imports of `dashboard.model` have to resolve to the package on the first commit of the split.
