## Architecture

`claims-manifest` adds `aff verdict` beside the existing check and close commands. The committed manifest is the authority (`claims-authority`). The command re-executes frozen pytest oracles at `--at` and at `--base` (`verdict-authority`). A change to test ids or hashes between those manifests is accepted only with a signed amendment (`amendment-approval`).

1. Resolve `--at` and `--base` in `--cwd`. `--base` defaults to the merge-base of `--at` and `main`. Refuse a revision that is not a commit.
2. Read `.affidavit/manifest.json` and `.affidavit/allowed_signers` from each revision with `git show`. Do not read the worktree copies.
3. For each named claim, compare test ids and oracle hashes between the two manifests. When they differ, require a chain of amendment entries in the `--at` manifest that connects the base values to the head values. Verify each signature with `ssh-keygen -Y verify` against the allowlist file from `--base`. The allowlist blobs at the two revisions must be identical.
4. Hash the oracle files at each revision and require those hashes to equal the claim's `oracle_hashes` in that revision's manifest.
5. Check out `--base` in a temporary `git worktree` and run pytest on the claim's test ids. Classify the output with `is_assertion_level_failure` in `affidavit/oracle_red.py`. Require an assertion-level failure.
6. Run the same pytest command at `--at` in a temporary worktree. Require exit 0.
7. Print a JSON object on stdout. Exit 0 only when every named claim passes. Do not write the artifact store.

## Interfaces

- **Manifest** `.affidavit/manifest.json`, committed at the work-repo root:

  ```json
  {
    "claims": [
      {
        "id": "R1",
        "text": "observable behavior",
        "tests": ["tests/test_mod.py::test_name"],
        "oracle_hashes": {"tests/test_mod.py": "sha256:<hex>"}
      }
    ],
    "amendments": [
      {
        "claim": "R1",
        "old_tests": ["tests/test_mod.py::test_name"],
        "new_tests": ["tests/test_mod.py::test_name"],
        "old_hashes": {"tests/test_mod.py": "sha256:<old>"},
        "new_hashes": {"tests/test_mod.py": "sha256:<new>"},
        "signature": "<openssh signature>"
      }
    ]
  }
  ```

- **Allowlist** `.affidavit/allowed_signers`, OpenSSH allowed_signers format. Principals listed there may sign amendments.

- **Signed payload** (UTF-8, signed with `ssh-keygen -Y sign -n affidavit-amendment`). The signature field is not part of the payload.

  ```
  affidavit-amendment v1
  claim: <id>
  old_tests: <comma-separated ids in manifest order>
  new_tests: <comma-separated ids in manifest order>
  old_hashes:
  <relpath> <sha256:hex>
  new_hashes:
  <relpath> <sha256:hex>
  ```

  Hash lines are sorted by relpath. `old_*` of the first amendment equals the claim at `--base`. `new_*` of the last amendment equals the claim at `--at`. Each later amendment's `old_*` equals the previous amendment's `new_*`.

- **CLI:** `aff verdict [--cwd DIR] --at REV [--base REV] CLAIM [CLAIM ...]`
  - `--cwd` defaults to the process cwd and is the git repository and the pytest cwd for the `--at` worktree's repo.
  - `--base` defaults to `git merge-base <at> main`.
  - Stdout is JSON: `{"result":"pass"|"fail","claims":[{"id","result","reason"}]}`. `reason` is present when `result` is `fail`.
  - Exit 0 when top-level `result` is `pass`. Exit 1 when it is `fail`.

- **Pytest invocation:** `python3 -m pytest <test ids>` in the temporary worktree, with the worktree as cwd.

- **Store:** no reads and no writes.

## Decisions

- claims-authority
- verdict-authority
- amendment-approval

## Invariants

- Verdict inputs are the git objects at `--base` and `--at` plus the processes those checkouts run.
- An amendment verifies only against the allowlist blob at `--base`.
- Allowlist bytes at `--at` equal allowlist bytes at `--base` whenever the command accepts a hash or test-id change.
- Oracle file bytes at a revision hash to the `oracle_hashes` on that revision's claim.
- A base result counts only when `is_assertion_level_failure` is true for the pytest output.

## Assumptions

- `main` exists when `--base` is omitted, and `--at` is a descendant of the oracle-freeze commit.
- The signing key that matches `.affidavit/allowed_signers` is available to the owner and is not loaded in the agent session. This phase checks signatures; it does not provision keys.
- Temporary worktrees can be created from `--cwd` and removed after the run.
- Pytest is the runner for every claim in this phase.

## Tradeoffs

- Signing the amendment entry, rather than the whole commit, lets an unsigned implementation commit sit beside a signed oracle change. The verdict looks at the entry, so an unrelated unsigned commit still passes.
- Requiring the allowlist to be byte-identical at both revisions makes key rotation a later phase. It also makes "add my key and self-sign" fail closed without a second signature type.
- Re-executing in a temporary worktree costs a checkout and a pytest run per claim per revision. Stored check-runs stay unused so a forged pass cannot move the result.
- Pytest is hard-coded. A command string on the claim would admit the verify_command weakening this manifest exists to remove.

## Risks

- An agent session that can use the owner's ssh-agent can produce a valid signature. The check is cryptographic only when that key is absent from the session.
- `is_assertion_level_failure` can misread unusual pytest output. The verdict uses that classifier as it stands; widening it is a change to `oracle_red.py` and its tests.
- A claim id that exists at `--at` and not at `--base` has no base hashes to connect. The verdict fails that claim until both revisions contain it. First introduction of a claim is outside the happy path this phase tests.
- `git worktree add` fails when the revision is already checked out at the same path. The temporary path must be unique and removed even when pytest fails.
