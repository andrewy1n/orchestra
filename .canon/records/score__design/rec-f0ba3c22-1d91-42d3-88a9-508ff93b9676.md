## Architecture

First extract the Textual-free logic from `journal.py`, then delete the Textual modules and the tmux plugin. Then `git mv` the survivors into `dashboard/backend/` and the server into `dashboard/backend/server/`. Add `orchestra status` to the orchestra CLI, built on the snapshot loader and `gates.landings_for_snapshot`.

## Interfaces

- `orchestra status [DIR]` prints one line per effort.
- `orchestra status --count` prints the merged needs-you count.
- The server's `DIST` path points at `dashboard/web/ui/dist`.

## Decisions

- `status-cli`: an `orchestra status` command with a `--count` flag.
- `backend-move-timing`: move the surviving modules in this phase.

## Invariants

- The server starts and serves a snapshot after each task.
- Files move without content change, other than imports.

## Assumptions

- Nothing outside the `dashboard` package imports the deleted modules.
- The tmux tests are the only tests that need the tmux marker.

## Tradeoffs

- A larger diff in this phase buys one import rewrite instead of two.
- `dashboard/web/` holds only `ui/` until phase `ui-structure`.

## Risks

- The extraction of `journal.py` misses a function the server uses. Mitigation: run the web API tests after the extraction, before any deletion.
- The `DIST` path breaks after the server moves. Mitigation: `test_r30_serves_build` runs in this phase.
