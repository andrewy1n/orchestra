## Architecture

Move a test module when its primary import root is `orchestra.score`, `orchestra.conductor`, `orchestra.composer`, `orchestra.stage`, or `installer`. The destination is `tests/<root>/`, where `<root>` is `score`, `conductor`, `composer`, `stage`, or `installer`.

Leave these in place:

- `tests/canon/` and `tests/tuner/`, including their `confcutdir` lines in `scripts/test.sh`.
- Product tests: CLI, dashboard, web, sessions, views, skills, and repo-wide scans (`tests/test_boundaries.py`, `tests/test_names.py`).
- Any path named by the `wheel-contents` or `dashboard-split` specifications, including `tests/test_cli_packaging.py` and the dashboard and web test modules.

`scripts/test.sh` keeps three pytest processes. The orchestra process already runs `tests` while ignoring only `tests/canon` and `tests/tuner`, so the new directories are collected without a new process and without `confcutdir`.

A moved test that imports `conftest` or `helpers` as a sibling module keeps that import working against `tests/conftest.py` and `tests/helpers.py`. The root conftest stays the fixture source. The new directories do not grow a conftest that replaces it.

## Interfaces

- `tests/score/`, `tests/conductor/`, `tests/composer/`, `tests/stage/`, `tests/installer/`.
- `scripts/test.sh`, unchanged in shape apart from still not ignoring those directories.
- Root fixtures in `tests/conftest.py`.

## Decisions

- `tests-follow-import-root`: component and installer tests move under `tests/<import-root>` and keep the root conftest. Product tests and specification-named paths stay in `tests/`.

## Invariants

- Canon and tuner tests still run in their own processes.
- A moved test can use the fixtures defined in `tests/conftest.py`.

## Assumptions

- `helpers.py` under `tests/`, if a moved test imports it, stays at `tests/helpers.py`.
- No moved test depends on being the only test package on `sys.path`.

## Tradeoffs

- The orchestra pytest process grows the component tests it already ran, just from new paths. A separate process per component would isolate failures and would duplicate the canon/tuner setup.
- Files that import several components move by their primary subject. A cross-component test stays at `tests/` when no single root owns it.

## Risks

- `from conftest import ...` resolves to a local `conftest.py` if one is added later. The new directories must not add a conftest that shadows the root fixtures.
- A test left behind in `tests/test_*.py` with a component subject fails R1 to R5. The scan has to use the primary subject, not every imported package.
