## Architecture

Phase-end proof is a stored observation, skill discipline, and a dashboard read path. Contract adds project:proof-packet. settle-phase and plan-phase require ## Proof on structured phase bodies. execute-phase assembles the packet after the existing phase gate and before Landing merge or done language. Handoff gains latest-proof. Dashboard phase detail loads the latest packet for the phase and shows Look and Attention. Affidavit CLIs are optional inputs when a manifest exists.

## Interfaces

- adaptive-artifacts create (or replace) project:proof-packet with subject = phase slug
- handoff role latest-proof reads proof-packet
- execute-phase may invoke `aff trail` and `aff audit --base <base> --head <revision>`; stores pointers only
- Chat prints Look and Attention before declaring phase done
- dashboard.model.load_phase_detail lists project:proof-packet for the phase; PhaseDetail carries proof fields; phase_screen renders a Proof tab (structured) or overview block (simple) with Look and Attention; chip when packet present

## Decisions

proof-owner-orchestra, proof-packet-new-type, proof-gate-packet-not-signature, proof-dashboard-phase-detail

## Invariants

Machine holds ids and re-run commands only. Packet subject equals phase slug. Dashboard Proof displays record body sections, not agent paraphrase. Proof is never a blocking Needs-you kind.

## Assumptions

Handoff selection for observation types can filter by effort. Work repos with Landing have known base and phase-head SHA at gate time. Existing PhaseDetail tabs (Spec/Design/Evidence) are the right host for Proof.

## Tradeoffs

Dashboard work adds model/screen tests; without it the packet is stored but easy to ignore. A Needs-you proof item would force eyes but contradicts the no-mandatory-signature decision.

## Risks

Agents may write vague Look sections — skill examples and smoke must require concrete commands or paths. Soft-list failures if proof-packet is missing from older contracts — treat like other soft types.
