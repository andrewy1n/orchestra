## Architecture

Move `dashboard/web/ui` to `dashboard/frontend`. Under `src/lib`, put `state/*.svelte.ts` for polling, journal, and overlay state, `screens/` for Home, Journal, Overlay, and Side rail, and `components/ui/` for shadcn-svelte. `App.svelte` wires the router to the screens. The Tailwind build and the global CSS use the shadcn theme variables.

## Interfaces

- State modules export reactive values and actions, and screens import them.
- The router keeps its current route names and deep link format.
- `components.json` aliases: `$lib`, `$lib/components`, `$lib/components/ui`, `$lib/utils`, `$lib/hooks`.

## Decisions

- `app-split`: screens plus state modules.
- `shadcn-appearance`: adopt the shadcn default look.
- `backend-frontend-split`: the `dashboard/frontend` folder (recorded in phase `data-layer`).

## Invariants

- All routes and deep links resolve as before.
- The Vitest suite passes without edits to router and link tests.

## Assumptions

- The shadcn `init` can run non-interactively with the aliases set by flags.
- Vite resolves `$lib` through an alias in `vite.config.ts`.

## Tradeoffs

- One phase carries the move, the split, and the restyle. Review is easier per task than per phase.

## Risks

- The global CSS overwrite loses styles that tests rely on. Mitigation: run the Vitest suite after the init, before the restyle tasks.
- Biome flags generated components. Mitigation: a config exclusion for `components/ui`, decided at plan-phase.
