## Requirements

R2: `orchestra.conductor.suite` does not define `parse_failing_node_ids`.
R3: `orchestra.conductor.check` defines the helper that hashes command output.
R4: `orchestra.conductor.suite` does not define a helper that hashes command output.
R5: Python files under `orchestra/` and `dashboard/` start the `git` executable only in `orchestra/canon/git_backend.py`.
R6: `dashboard.landing.rev_parse_token` returns `None` when the git command fails.
R7: `orchestra.conductor.check.git_head` raises when `git rev-parse HEAD` fails.
R8: The text `ssh-keygen` appears under `orchestra/tuner/` in only one Python module.

R14: The FastAPI app registers those API paths by reading that table.
R15: `orchestra.views` does not define a record-payload getter.
R16: `orchestra.conductor.close_batch` does not define a record-payload getter.
R17: `dashboard.model` does not define a record-payload getter.
R18: `dashboard.approval` does not define a record-payload getter.

R23: `dashboard.approval` calls that function.

## Acceptance criteria

- R1 to R4: the existing failing-node tests pass, and a scan shows the definitions only in `orchestra.conductor.check`.
- R5 to R7: a scan of `git` invocations, plus tests for landing's `None` and `git_head`'s raise.
- R8 to R11: the tuner signature tests pass, and a scan shows one `ssh-keygen` module.
- R12 to R14: one test requests each listed path from the stdlib server and the FastAPI app on the same store.
- R15 to R23: a scan of the four callers and an import of the canon function.
- `orchestra check` and suite failing-node parsing pass through their real entry points.

## Constraints

- Callers keep their own failure behavior. The shared git helper returns the process result. It does not decide whether a failure raises or becomes `None`.
- Component import directions stay as `tests/test_boundaries.py` defines them. The git helper and the payload function live in `orchestra.canon`, so every component may call them.
- Signing stays inside `orchestra.tuner`. The route table stays inside `dashboard`.

## Non-goals

- A new `orchestra.support` package.
- Folding tuner worktree commands, reviewer diffs, or landing commits into canon as domain operations. Those callers pass argv to the shared runner.
- Changing the set of API paths.
- Unifying `_section` or other one-off body parsers.

## Invariants

- `orchestra.canon` imports no other orchestra component.
- `orchestra.tuner` does not import `orchestra.conductor`.
- A missing `git` or a failing git command still surfaces differently in `dashboard.landing` and in `orchestra.conductor.check`.

## Assumptions

- `wheel-contents` has landed, so `dashboard` imports from an installed package.
- Record payloads that reach the getter are JSON objects. A non-dict payload becomes `{}`.
