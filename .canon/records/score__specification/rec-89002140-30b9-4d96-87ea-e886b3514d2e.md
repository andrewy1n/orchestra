## Requirements

R1: `aff audit --base --head` splits the diff into blocks, skips test and prose blocks, reverts each remaining block, reruns frozen claim tests through `run_tests`, and labels each block noticed, not noticed, or inconclusive.

R2: `aff audit` never reports a test-file block as a finding target.

R3: On the `check-runner` range used in spikes, the audit reports the unnoticed `build_batch(request, cwd=args.cwd)` block.

R4: The audit plants mutants only in noticed blocks (LLM or tool proposals allowed; only test runs judge) and reports at least one surviving mutant documented in `spikes/llm-mutants/findings.md` for that range.

## Acceptance criteria

- Advisory JSON output for CI.
- R2–R4 covered by tests or a checked fixture run in verification.
- Claim tests are driven through `run_tests`, not ad-hoc pytest scraping.

## Constraints

- Advisory: does not by itself fail `aff verdict`.
- No store tokens under `affidavit/`.
- Mutant proposals are never self-judging.

## Non-goals

- Differential unclaimed-behavior probes (audit-differential).
- Blocking merge solely on survivors in this phase (orchestra may consume JSON later).

## Invariants

- Test/prose hunks are not mutant targets.
- Only a test run decides noticed vs survivor.

## Assumptions

- Spike ranges and findings remain available as fixtures or documented SHAs.
