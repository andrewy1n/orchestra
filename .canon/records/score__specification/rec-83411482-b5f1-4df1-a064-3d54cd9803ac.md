## Requirements

R1: `affidavit.observation` creates an evidence-observation by calling `Project.create`.
R2: `affidavit.observation` lists evidence-observations by calling `Project.list`.
R3: `affidavit.binding` creates an evidence-binding by calling `Project.create`.
R4: `affidavit.binding` lists evidence-bindings by calling `Project.list`.
R5: No module under `affidavit/` starts a process to run `adaptive-artifacts`.
R6: The evidence-layout test passes when affidavit source imports `adaptive_artifacts` and names `project:` record types.
R7: `aff assertion-red` exits 0 when `is_assertion_level_red` is true.
R8: `aff assertion-red` exits 1 when `is_assertion_level_red` is false.
R9: `aff verdict` calls `run_verdict` without opening an artifact store to decide the gate.
R10: `run_verdict` returns a verdict for a repository that has no artifact store.

## Acceptance criteria

R1–R5: tests in the affidavit repo spy on `Project.create` and `Project.list` and assert no artifact-store subprocess.
R6: `python3 -m pytest tests/test_evidence_layout.py -q` passes with those strings present in `affidavit/`.
R7–R8: tests run `aff assertion-red` on a passing and a failing check-run JSON document.
R9–R10: a test runs `run_verdict` in a temporary git repository that has a manifest and no `.artifacts` store.

## Constraints

Affidavit depends on adaptive-artifacts and does not import orchestra. Verdict stays store-free. The `aff` command stays a wrapper over the existing functions.

## Non-goals

Audit's git, mutant, and probe processes stay subprocesses. This phase does not change orchestra's close path.

## Invariants

Store writes from observation and binding go through `Project`. The verdict gate does not read the artifact store.

## Assumptions

`aa-library` is available to import as `adaptive_artifacts.project`. Record types remain `project:evidence-observation` and `project:evidence-binding`.
