## Requirements

R1: The UI lives in `dashboard/frontend`, and `dashboard/web` does not exist.
R2: The server serves `dashboard/frontend/dist`.
R3: `App.svelte` has fewer than 150 lines.
R4: Polling, journal, and overlay state live in `.svelte.ts` modules under `src/lib`.
R5: Home, Journal, Overlay, and Side rail are separate components under `src/lib`.
R6: `components.json` exists and its aliases point at `$lib`.
R7: The `$lib` alias resolves in `vite.config.ts` and in the tsconfig.
R8: The phase and task overlay tabs and dialogs use shadcn-svelte components.
R9: The global CSS defines the shadcn theme variables.
R10: `npm run lint` passes with the shadcn components present.
R11: `npm run check`, `npm test`, and `npm run build` pass.
R12: Every existing deep link still resolves to the same screen.

## Acceptance criteria

- R1, R2, R3, R4, R5, R6, R7, R9: a test checks the tree, the config files, and the line count.
- R8: a grep finds shadcn imports in the tab and dialog components.
- R10, R11: the three npm commands exit 0.
- R12: the existing `deepLinks`, `router`, and `links` Vitest files pass unchanged.

## Constraints

- The 150-line limit for `App.svelte` is a proposed target. Plan-phase may adjust it with the user.
- shadcn-svelte is initialized for Svelte 5, Tailwind 4, and plain Vite with a `$lib` alias.
- The look changes to the shadcn default theme. Behavior does not change.

## Non-goals

- New screens or data. Phase `areas-and-ideas` adds them.
- API changes.
- A custom palette on top of the shadcn theme.

## Invariants

- Every route and deep link keeps working.
- The lint gate stays at zero findings.

## Assumptions

- The `shadcn-svelte` init works in a Vite project that is not SvelteKit.
- Biome and shadcn-svelte can agree on formatting. If not, generated component paths are excluded from the formatter.

## Tradeoffs

- The restyle and the refactor happen in one phase. Visual diffs and structural diffs mix.
