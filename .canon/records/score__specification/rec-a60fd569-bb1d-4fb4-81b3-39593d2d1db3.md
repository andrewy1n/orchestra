## Requirements

R1: This repo keeps the `aff` commands `check`, `close-batch`, and `verdict`, and the modules that implement them. `affidavit.aa` does not import `dashboard`. With `skills/`, `dashboard/`, `scripts/`, and `agents/` removed, this repo's pytest suite passes.

R2: A new git repo at `~/orchestra` is the plugin `orchestra`. It holds the current skills under the same slugs (`engage`, `discuss`, `plan-phase`, `execute-phase`, `verify-work`, `init`, `analyze-sessions`), the dashboard, the session-analysis scripts, `agents/se-reviewer.md`, and the reviewer and suite modules. Those modules import as `orchestra.reviewer` and `orchestra.suite`. `affidavit/tier2.py` and the `tier2_*` aliases in `suite.py` are deleted. Orchestra has no `tier2` module. Gate answers come from `aff check`, `aff close-batch`, and `aff verdict`.

R3: The bundled contract's `"project"` is `orchestra`. When a work repo's `.artifacts/project-design.json` says `"project": "affidavit"`, ensure-store rewrites that field to `orchestra` and continues. When the field is any other value, ensure-store stops and does not replace the design.

R4: The orchestra store holds the records of efforts `dashboard`, `workflow-loop`, `packaging`, `session-analysis`, and `test-suite-speed`. This repo's store holds the `evidence-layer` records. Both stores pass `adaptive-artifacts validate`.

R5: A test in the orchestra repo fails when a skill file contains a `create` or `correct` of `project:check-run` whose method is `tdd` or `check`, or a `create` or `supersede` of `project:oracle-amendment`. An oracle hash or test-id change is a signed amendment in `.affidavit/manifest.json`. `aff verdict` is what accepts or rejects it.

R6: A skill that verifies or closes an acceptance whose claim is in the manifest runs `aff verdict` on that claim. A non-zero exit means the acceptance is not done.

R7: A commit the skills tell an agent to make uses the task slug, the phase slug, or `<phase-slug> store` as the subject, and a body of one or two sentences saying why the change was made. A subject with an empty body does not satisfy this.

## Acceptance criteria

- `bin/aff check --help`, `bin/aff close-batch --help`, and `bin/aff verdict --help` exit 0 here, and pytest passes with `skills/`, `dashboard/`, `scripts/`, and `agents/` absent.
- `~/orchestra` contains those skill directories and `dashboard/`.
- The orchestra boundary test fails on a fixture skill that creates a `tdd` check-run or a `project:oracle-amendment`, and passes on the migrated skills.
- A fixture store whose project is `affidavit` is rewritten to `orchestra`. A fixture whose project is some other name is left unchanged.
- Active goals in this store are `evidence-layer`. Active goals in the orchestra store are the five moved efforts.
- `execute-phase` shows a per-task commit, a phase-branch commit, and a store commit whose message is a subject line plus a body. The subject is the task slug, the phase slug, or `<phase-slug> store`.

## Constraints

- `evidence-kind` and `phase-end-evidence` stay later phases of this effort. This phase does not enforce `evidence_kind` and does not add a phase-end report.
- Check-runs with method `manual` or `review`, and the suite check-run the suite module records, stay writable from the orchestra skills.
- A record that stays in a store is not hand-edited. A move relocates that record's file, log, and history as a unit.
- `aff verdict` does not read the artifact store.

## Non-goals

- Renaming skill slugs.
- A separate CLI for `check` or `close-batch`.
- Pushing `orchestra` to a remote.
- Splitting this repo's git history. Orchestra's first commit is the moved tree. This repo keeps its history and drops the moved paths.
- Removing manual, review, or suite check-run writes.

## Invariants

- `aff verdict` is a function of the work repo and the revisions on the command. A stored check-run does not change it.
- A `tdd` or `check` result is written by `aff check`.
- The affidavit package does not import the dashboard or the orchestra package. The orchestra package may import affidavit.
- Neither repo defines a `tier2` module. The phase-level suite is `orchestra.suite`.

## Assumptions

- The orchestra checkout is `~/orchestra`, and `aff` resolves on `PATH` from that checkout's sessions. `~/affidavit` is the checkout that provides the `aff` binary.
- A record whose effort is entirely on one side of the cut, and which does not reference a record id on the other side, can move by relocating its files. A cross-reference is kept in both stores.
- This discussion is the approval for rewriting `"project": "affidavit"` to `"project": "orchestra"`. ensure-store does not ask again for that field.
