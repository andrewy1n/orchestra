## Requirements

R1: The installed package registers the `canon.schemas` entry point `composer = orchestra.composer.schemas`.
R2: The `composer` schema module has version `1.0.0`.
R3: The installed package ships `orchestra/composer/schemas/composer.json`.
R4: `canon init --schemas score,conductor,tuner,composer` creates a store that `canon validate` accepts.
R5: `canon create --type composer:area` with payload `title` and a `## Scope` body succeeds.
R6: `canon create --type composer:area` without a `## Scope` section is refused.
R7: `canon create --type composer:idea` with only `status` in the payload succeeds.
R8: A `composer:idea` `status` outside `open`, `promoted`, `dismissed` is refused.
R9: A `composer:idea` `area` that names no `composer:area` subject is refused.
R10: A `composer:idea` `effort` that names no `score:effort` subject is refused.
R11: A `composer:idea` `phase` that names no `score:phase` subject is refused.
R12: `canon supersede` on a `composer:idea` writes a successor with the same subject and the new `status`.
R13: `tests/test_boundaries.py` reports a module under `orchestra/composer/` that imports `orchestra.conductor`.
R14: `tests/test_boundaries.py` accepts a module under `orchestra/composer/` that imports `orchestra.canon` or `orchestra.score`.
R15: The live store's `.canon/config.json` lists `composer` at `1.0.0`.
R16: `canon validate` on the live store reports no errors after composer is added.

## Acceptance criteria

- R1, R3: the packaging test installs the package into a temporary prefix and discovers the `composer` module from that prefix.
- R4–R12: tests drive the `canon` CLI against a temporary store.
- R13, R14: unit tests on `boundary_violations` with fixture trees.
- R15, R16: `canon schemas add composer` then `canon validate` on the live store, captured as a manual check-run.

## Constraints

- `orchestra/score/schemas/score.json` does not change in this phase.
- Tests never write to the live `.canon/` store.

## Non-goals

- Converting `score:backlog-item` or `score:feedback` records (phase backlog-to-idea).
- Removing `score:backlog-item` or `score:feedback`.
- `orchestra idea`, a triage skill, or `orchestra view roadmap` (phase idea-triage).
- Changing the default schema list in `ensure-store` or `init`.
- Dashboard or `engage` changes.
- Docs ownership.

## Invariants

- A store without `composer` in `config.json` validates exactly as before.
- composer Python modules import only `orchestra.canon` and `orchestra.score`.

## Assumptions

- canon accepts a reference from one namespace to another installed namespace; `conductor` already refers to `score:effort`.
- An idea with no effort is valid; product-level ideas need not belong to an effort yet.
