## Requirements

R1: `.github/workflows/ci.yml` exists and `.github/workflows/tuner-verdict.yml` is unchanged.
R2: The workflow runs on push to `main`.
R3: The workflow runs on push to `phase/**` branches.
R4: The workflow runs on `pull_request`.
R5: The workflow runs on `workflow_dispatch`.
R6: The workflow sets a `concurrency` group with `cancel-in-progress: true`.
R7: Every job sets `timeout-minutes`.
R8: Every job runs on Python 3.10.
R9: The `checks` job runs `scripts/build_skills.py --check`.
R10: The `checks` job runs `scripts/check_orchestra_plugin_names.py`.
R11: The `checks` job runs `canon validate`.
R12: The `checks` job runs `ruff check` with a pinned ruff version.
R13: `pyproject.toml` configures ruff with rule set `F` only.
R14: `ruff check` exits 0 on the repository.
R15: A test job runs `uv run pytest -n auto --confcutdir=tests/canon tests/canon`.
R16: A test job runs `uv run pytest -n auto --confcutdir=tests/tuner tests/tuner`.
R17: A test job runs `uv run pytest -n auto tests --ignore=tests/canon --ignore=tests/tuner`.
R18: A `tmux` job installs tmux.
R19: The `tmux` job runs the `tmux` marker without `-n`.
R20: No test job lists another test job in `needs`.
R21: Every uv-based job enables the uv cache.
R22: A `types` job runs mypy with `continue-on-error: true`.
R23: A deliberate test failure turns the workflow run red.
R24: A deliberate ruff violation turns the workflow run red.
R25: A deliberate `canon validate` error turns the workflow run red.
R26: A deliberate skill-sync drift turns the workflow run red.
R27: Every blocking job passes on a pull request from the phase branch.
R28: `scripts/test.sh` exits 0 locally.

## Acceptance criteria

- The workflow file parses and shows the jobs, triggers, `concurrency` and `timeout-minutes` above (R1-R8, R20-R22; command).
- Each `checks` step exits 0 locally with the CI commands (R9-R14; command).
- The CI test commands exit 0 locally (R15-R19; command).
- An observed GitHub Actions run on the phase branch pull request is green for every blocking job (R27).
- A deliberate failure in each of test, ruff, `canon validate` and skill drift turns a run red (R23-R26; observed run or `act` dry run per job).
- `scripts/test.sh` exits 0 (R28; command).

## Constraints

- Execution starts after `wheel-contents` merges into `main`. CI installs with `uv sync --locked --group dev`.
- Use GitHub-hosted `ubuntu-latest` runners. Use no repository secrets.
- Do not edit `tuner-verdict.yml`.
- Keep the ruff autofix behavior-neutral. The test suite must pass after it.
- Add no comments that explain a change.

## Non-goals

- Branch protection and required status checks (`repo-hygiene` idea).
- A Python version matrix (`python-matrix` idea).
- A blocking mypy job and the 41 mypy fixes (`mypy-gate` phase).
- A wheel build or install smoke test (`wheel-smoke` phase).
- Dependabot and pre-commit hooks.
- Changes to `scripts/test.sh`.

## Invariants

- `scripts/test.sh` stays the local entry point and still passes.
- The CI test commands keep the same pytest selection as `scripts/test.sh`, plus `-n auto`.
- The `types` job never blocks a merge in this phase.

## Assumptions

- The repository stays public, so hosted runners have 4 vCPU and `-n auto` is useful.
- `wheel-contents` lands the `dev` dependency-group, project dependencies and `uv run pytest` form in `scripts/test.sh`.
- The suite passes on a clean checkout under Python 3.10.
- `tmux` installs from apt on `ubuntu-latest` and the tmux tests run without a TTY.
