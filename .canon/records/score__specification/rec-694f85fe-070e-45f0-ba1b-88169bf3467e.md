## Requirements

R1: `.canon/config.json` sets `"backend": "sqlite"`.
R2: `.canon/store-binding.json` is `{"store": "global"}`.
R3: `git ls-files .canon` lists only `config.json`, `store-binding.json`, files under `schemas/`.
R4: `.gitignore` ignores the `.canon/log`, `.canon/records`, `.canon/history` trees.
R5: Before the switch, an export of the file store exists at `~/.canon/<repo-name>/backups/pre-cutover.jsonl`.
R6: Right before the switch, `scripts/verify_import.py` reports 0 mismatches on the live store.
R7: After the switch, `canon list` counts every record type at least as high as before the switch.
R8: `canon validate` passes on the DB.
R9: A worktree of the repo reads the same records as the primary checkout.
R10: `orchestra handoff` prints the same effort list after the switch as before it.
R11: The dashboard server returns the effort list from the DB.
R12: The SessionStart hook runs `canon backup` when the newest backup is older than 24 hours.
R13: The SessionStart hook does not run `canon backup` when the newest backup is newer than 24 hours.
R14: `AGENTS.md` does not tell agents to commit store changes on the work branch.
R15: `AGENTS.md` does not tell agents to run `canon` from the primary checkout.
R16: `AGENTS.md` states the DB location.
R17: `AGENTS.md` names the backup command.
R18: `skills/ensure-store.md` describes the DB store.
R19: `scripts/build_skills.py --check` passes.
R20: `.github/workflows/ci.yml` has no step that reads the live store.
R21: No module imports `Store`, `record_file`, or the file-layout functions of `oplog`.
R22: The full CI workflow passes on the pushed branch.

## Constraints

- Work stays on `phase/cutover` until every other requirement passes.
- Nothing writes to the file store after the final export.
- The old record files stay in git history.
- No history rewrite and no force push.

## Non-goals

- Multi-machine sync.
- A committed export for CI.
- Changing the record types or schemas.

## Invariants

- Record ids and revision hashes are the same before and after the switch.
- The pre-cutover export is kept until the user deletes it.

## Assumptions

- The phase's own task records are written to the file store until the switch. The closing verification records go to the DB.
- This phase can split at plan-phase if the task count is large: switch, then cleanup.
