## Requirements

R1: `aff verdict` fails a claim when the commit that introduced its oracle paths is not an ancestor of the implementation under test (oracle after implementation).

R2: `aff verdict` fails a claim when the oracle-introducing commit touches paths outside the claim's oracle and frozen support set.

R3: `aff verdict` fails a claim when the oracle-introducing commit and the implementation commits share the same SSH commit signer principal, for histories where those commits are signed.

R4: `aff verdict` passes a fixture history that satisfies ordering, oracle-only paths, and different signers.

## Acceptance criteria

- Fixture: oracle commit after impl ⇒ fail.
- Fixture: oracle commit edits source ⇒ fail.
- Fixture: same signer on oracle and impl commits ⇒ fail.
- Fixture: ordered, oracle-only, different signers ⇒ pass (other verdict rules held constant).

## Constraints

- Do not trust agent-written provenance fields as authority; git is the authority.
- Builds on frozen support paths from frozen-environment.
- No store tokens under `affidavit/`.

## Non-goals

- Requiring every repo to use signed commits (unsigned histories skip or soften R3 per plan-phase rule, but fixtures for R3 are signed).
- Claim authoring UX.

## Invariants

- Provenance failure is a non-zero verdict.
- Verdict still does not read the artifact store.

## Assumptions

- "Implementation commits" can be defined as commits after the oracle commit on the path to `--at` (exact rule at plan-phase).
- Test and support paths are known from the manifest.
