## Requirements

R1: `ci.yml` has a job named `wheel`.
R2: The `wheel` job does not set `continue-on-error`.
R3: No step in the `wheel` job sets `continue-on-error`.
R4: The `wheel` job runs `python3 scripts/wheel_smoke.py`.
R5: `scripts/wheel_smoke.py` builds the wheel with `uv build --wheel` when `--wheel` is absent.
R6: `scripts/wheel_smoke.py` installs the wheel into a new virtual environment.
R7: `scripts/wheel_smoke.py` runs every check with a working directory outside the checkout.
R8: `orchestra --help` from the new environment exits 0.
R9: `canon --help` from the new environment exits 0.
R10: `canon init --schemas score,conductor,tuner` in a temporary git repository exits 0.
R11: `canon validate` in that repository exits 0.
R12: `orchestra install --list` exits 0.
R13: The `orchestra install --list` output names the `claude` host.
R14: The new environment imports `dashboard`.
R15: The new environment imports `dashboard.web`.
R16: The new environment imports `installer`.
R17: The new environment imports `installer.adapters`.
R18: `scripts/wheel_smoke.py --wheel <path>` installs that wheel and does not build one.
R19: `scripts/wheel_smoke.py` exits non-zero for a wheel that lacks `installer/providers.json`.
R20: `scripts/wheel_smoke.py` leaves the checkout unchanged.
R21: `README.md` names `python3 scripts/wheel_smoke.py` as the local wheel check.
R22: The `wheel` job passes on a pull request from the phase branch.

## Acceptance criteria

- `tests/test_ci_workflow.py` parses `ci.yml` and asserts the `wheel` job exists, is blocking, and runs the script (R1-R4; command).
- `tests/test_wheel_smoke.py` runs the script on a built wheel, and `git status --porcelain` is unchanged afterwards (R5-R17, R20; command).
- The same test passes `--wheel` with a wheel path and asserts no build runs (R18; command).
- The same test removes `installer/providers.json` from a copy of the wheel and asserts the script exits non-zero (R19; command).
- `README.md` contains `python3 scripts/wheel_smoke.py` (R21; command).
- An observed GitHub Actions run on the phase branch pull request shows `wheel` green (R22).

## Constraints

- Execution starts after `mypy-gate` merges into `main`. Both phases edit `ci.yml` and `tests/test_ci_workflow.py`.
- The job runs on Python 3.10 (`ci-python-version`).
- The script uses the standard library and `uv`. It adds no dependency.
- Add no comments that explain a change.

## Non-goals

- Shipping `dashboard/web/ui/dist` in the wheel. A backlog idea records it.
- Shipping `skills/`, `agents/`, or `hosts/` in the wheel.
- Removing the stale `orchestra = ["_scripts/*.py"]` package-data entry.
- Running the wheel on Python 3.11 to 3.13 (`python-matrix` idea).
- Publishing the wheel or uploading it as an artifact.
- Starting the TUI or web dashboard from the installed wheel.

## Invariants

- Every other blocking job in `ci.yml` is still blocking.
- The local command and the CI command are the same: `python3 scripts/wheel_smoke.py`.
- No check runs with the checkout on `sys.path` or as the working directory.
- The wheel is built from tracked files only.

## Assumptions

- `ci-workflow` and `wheel-contents` have merged. `ci.yml`, a tracked `uv.lock`, and the explicit package list exist on `main`.
- `uv build --wheel` and `uv venv` work on the runner after `astral-sh/setup-uv`.
- Today the wheel builds, and `orchestra --help`, `canon --help`, `canon init`, `canon validate`, `orchestra install --list`, and the four imports all succeed from a clean environment.
- `uv build` run in the checkout leaves an untracked `build/` directory behind. The script builds from a copy to avoid it.
