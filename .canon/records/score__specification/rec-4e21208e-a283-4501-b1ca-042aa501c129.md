## Requirements

R1: For a store whose full handoff exceeds 10,000 characters, the start hook context is at most 9,000 characters.
R2: The start hook context begins with the protocol text.
R3: The constraints block comes before the first effort section.
R4: The constraints block lists active constraints from every live effort.
R5: The constraints block omits constraints whose effort is closed.
R6: Each effort section shows only the Goal, Position, In Progress, Blocking Question, Needs Human and Unsigned Manual Check roles.
R7: The start hook context contains no record-id links.
R8: When the efforts do not fit the budget, the hook omits whole effort sections and never emits part of one.
R9: Each omitted effort is named by slug on one line that points to `orchestra handoff --effort <slug>`.
R10: Effort sections appear in order of their effort position's recorded_at, newest first.
R11: `orchestra handoff` output keeps its id links, Latest Proof and Backlog sections.
R12: The plain (Cursor) hook format applies the same budget and content as the Claude format.
R13: Run against this repo's store, the start hook returns additionalContext of at most 10,000 characters.

## Acceptance criteria

R1–R12 each have a test in tests/test_hooks.py or tests/test_views.py that seeds a temporary store. R13 is a check that pipes hook input for this repo to `orchestra hook-start --claude` and measures the additionalContext length.

## Constraints

claude-code-hook-context-cap: Claude Code caps each additionalContext string at 10,000 characters and shows only a 2,000-character preview above it.

## Non-goals

Changing `orchestra handoff`, `orchestra view`, or the stop hook. Raising or working around the Claude Code cap.

## Invariants

The hooks never write records. A hook failure still returns a one-line error context rather than crashing the session.

## Assumptions

The Cursor hook has no smaller limit than Claude Code. Live efforts are active score:effort records whose payload.status is not closed.
