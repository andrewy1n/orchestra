## Requirements

R1: The orchestra `verify-work` skill text names when to record an evidence-observation versus when to `aff bind` an observation to a claim.
R2: The orchestra `execute-phase` skill text names when bind or recheck is required before treating a manifest claim as earned.
R3: A verify-work or handoff path documented in those skills shows the linkage claim → evidence-binding → evidence-observation.
R4: No new `aff` work-kind, mode flag, or policy switch is added to encode record-versus-bind; policy lives in orchestra skills only.
R5: A check in the orchestra tree fails a fixture skill that invents an aff mode for record-versus-bind, and passes on the updated skills.

## Acceptance criteria

- Updated `verify-work` and `execute-phase` skill files state record vs bind rules in plain language.
- At least one skill section or example shows claim → binding → observation order.
- Aff CLI gains no mode/work-kind for this policy.
- Orchestra boundary or command tests cover the no-mode rule and pass.
- Phase verification commands in the orchestra checkout pass.

## Constraints

- Aff remains mode-free for record-versus-bind (prior product choice).
- Do not move claim authority into the store; claims stay in the git manifest.
- Code changes for bind/ingest stay in their phases; this phase is orchestra policy and tests.

## Non-goals

- New aff verbs beyond what bind/ingest already shipped.
- Dashboard UI for bindings in this phase.
- Replacing `orchestra check` / check-run close rules.

## Invariants

- Gate answers for frozen claims still go through `aff verdict` / bind / recheck as named by skills.
- Parent session remains the only store writer for workflow records.

## Assumptions

- `evidence-bind` and `evidence-technique-ingest` have landed (or their CLI surfaces are available) before this phase’s skill checks run against real verbs.
- Orchestra is the home for skills (`~/orchestra`).
