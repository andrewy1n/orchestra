## Requirements

R1: `canon export --out FILE` writes one JSON line per op.
R2: Export orders its lines by record type, record id, seq.
R3: Two exports of the same store are byte-identical.
R4: Each export line carries its op unchanged.
R5: Each export line names its record type, record id, seq.
R6: `canon import FILE` into an empty store appends every op in order.
R7: Import builds the `records` rows from the folded chains.
R8: Import builds the `revisions` rows from the folded chains.
R9: Import into a non-empty store is rejected.
R10: A rejected or failed import writes nothing.
R11: Import preserves every field of every op.
R12: After importing the real file store, the folded revision of each record equals the revision in `records/<type>/<id>.md`.
R13: After importing the real file store, every revision that has a file in `history/` has a row in `revisions` with the same hash.
R14: Exporting a DB store, importing it into an empty DB, then exporting again gives byte-identical files.
R15: Import of a chain with a gap fails with a message that names the record.
R16: Import of a chain with a hash mismatch fails with a message that names the record.
R17: A chain that starts at a checkpoint op imports with its seq numbers unchanged.
R18: `scripts/verify_import.py` exits 0 when the import has no mismatch.
R19: `scripts/verify_import.py` exits 1 when the import has a mismatch.
R20: `scripts/verify_import.py` prints the record count, the mismatch count.

## Acceptance criteria

- R1 to R11, R14 to R17: unit tests on small temporary stores, including a chain with a checkpoint op, a chain with a gap and a corrupted chain.
- R12, R13, R18, R20: `scripts/verify_import.py` against a copy of the real store prints `0 mismatches` and exits 0 (command run).
- R19: a seeded mismatch makes `scripts/verify_import.py` exit 1 (test).

## Constraints

- Export reads through the `Backend` interface, so it works for both backends until cutover.
- Import is one transaction.
- Export is plain JSONL and needs no tool other than `canon`.

## Non-goals

- Switching this repo to the DB.
- Merging an export into a non-empty store. `canon merge` covers store-to-store merges.
- Wiring a backup hook.

## Invariants

- Import never rewrites an op.
- An export contains no timestamp of the export itself.

## Assumptions

- The real store has about 9,100 records and 10,000 op files. Import fits in one transaction.
- Some chains start at a checkpoint op because `prune_before` removed older ops. The checkpoint holds the full state.
