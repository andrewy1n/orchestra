## Requirements

R1: Every test module whose primary import root is `orchestra.score` lives under `tests/score/`.
R2: Every test module whose primary import root is `orchestra.conductor` lives under `tests/conductor/`.
R3: Every test module whose primary import root is `orchestra.composer` lives under `tests/composer/`.
R4: Every test module whose primary import root is `orchestra.stage` lives under `tests/stage/`.
R5: Every test module whose primary import root is `installer` lives under `tests/installer/`.
R6: `tests/test_cli_packaging.py` remains directly under `tests/`.
R7: `tests/test_dashboard_model.py` remains directly under `tests/`.
R8: `tests/test_dashboard_app.py` remains directly under `tests/`.
R9: `tests/test_web_dashboard.py` remains directly under `tests/`.
R10: `scripts/test.sh` does not ignore `tests/score`.
R11: `scripts/test.sh` does not ignore `tests/conductor`.
R12: `scripts/test.sh` does not ignore `tests/composer`.
R13: `scripts/test.sh` does not ignore `tests/stage`.
R14: `scripts/test.sh` does not ignore `tests/installer`.
R15: `scripts/test.sh` exits 0.

## Acceptance criteria

- R1 to R5: a scan of test modules by primary import root, and pytest collection of each new directory.
- R6 to R9: those paths still exist.
- R10 to R14: a scan of `scripts/test.sh`.
- R15: `scripts/test.sh` exits 0.

## Constraints

- `tests/canon/` and `tests/tuner/` stay on their own `confcutdir` invocations.
- The new directories use the root `tests/conftest.py`. They do not get a separate `confcutdir`.
- Paths named by the `wheel-contents` and `dashboard-split` specifications stay where those specifications name them.
- Dashboard, CLI, session, view, skill, and repo-wide scan tests stay directly under `tests/`.

## Non-goals

- Moving `tests/canon/` or `tests/tuner/`.
- A new `tests/orchestra/` tree for product tests.
- Splitting one test module across two components.

## Invariants

- A moved test still sees the fixtures from `tests/conftest.py`.
- `tests/test_boundaries.py` and `tests/test_names.py` stay directly under `tests/`.

## Assumptions

- The primary import root is the component or top-level package the test is about, not every package it imports.
- `wheel-contents` may already have moved session modules. Session tests stay in `tests/` and import the new module paths.
