## Requirements

R1: Every phase overlay tab shows shared status chips including lifecycle state and task done/total (and awaiting sign-off when set).
R2: Every phase overlay tab shows a progress cue for the phase's tasks (done/total or equivalent).
R3: Every phase overlay tab shows a next-action line derived from existing dashboard next-step or position cues when available, otherwise a short fallback.
R4: When the phase has requirements/evidence, every phase overlay tab shows one clickable glyph or chip per requirement reflecting status.
R5: Activating a requirement control opens the requirement overlay for that id.
R6: Every phase overlay tab shows a compact per-wave summary of tasks in that phase (counts or glyphs by wave).
R7: Overview, Spec, Design, Decisions, Evidence, Tasks, and Proof keep distinct roles, but each tab's body uses structured UI blocks (cards, strips, lists, or matrices) rather than bare prose-only dumps.
R8: A phase with no specification still gets the shared structured chrome; missing blocks show empty states rather than raw JSON.
R9: Tab-specific content remains reachable under the shared chrome (e.g. Spec/Design prose in readable sections; Tasks as a structured list; Evidence/Proof as structured blocks).

## Acceptance criteria

- UI tests render shared chrome (chips, requirements strip when seeded, wave summary) on at least two tabs, not only Overview.
- Clicking a requirement chip opens the requirement overlay from a non-Overview tab as well as Overview.
- Spec/Design/Tasks (or equivalent) bodies are not sole raw markdown dumps of the tab payload.
- `npm test` passes for those cases.
- Manual: open an in-progress structured phase, switch tabs, and confirm chrome + improved content UI on each.

## Constraints

- Prefer data already on GET /api/phase (detail, evidence, tasks); avoid new endpoints unless a field is missing.
- Do not change Textual in this phase.
- Task dependency graph is out of scope (phase `task-graph`).
- Do not redesign the home/main left-rail layout in this phase (deferred by `phase-overview-home-layout-defer`).

## Non-goals

- Rethinking the home/main composition (everything stacked left).
- Journal or home-rail changes.
- Editing phase fields from the overlay.

## Invariants

- Phase tab set still comes from `tabs_for`.
- Esc closes the phase overlay.
- Deep-link hash routes for phase tabs remain valid.

## Assumptions

- Requirement status glyphs can follow the spike/TUI vocabulary already used in evidence views.
- Shared chrome can sit above tab content without duplicating API fetches.
