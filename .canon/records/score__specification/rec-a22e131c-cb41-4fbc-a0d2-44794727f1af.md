## Requirements

R1: Each live `score:backlog-item` becomes a `composer:idea` with the same id, subject, body and payload.
R2: Each history snapshot of a converted record has type `composer:idea`.
R3: The live store holds no `score:backlog-item` record.
R4: The live store holds no `score:feedback` record.
R5: The score module declares no `score:backlog-item` type.
R6: The score module declares no `score:feedback` type.
R7: `canon validate` reports no errors on the live store after the conversion.
R8: `orchestra handoff` lists each open `composer:idea` that carries an effort under that effort.
R9: The dashboard backlog panel lists each open `composer:idea` that carries an effort, grouped by effort.
R10: Dashboard promote supersedes an open `composer:idea` to status `promoted`.
R11: Dashboard dismiss supersedes an open `composer:idea` to status `dismissed`.
R12: The `engage` skill parks an item with `canon create --type composer:idea`.
R13: The `engage` skill promotes an item with `canon supersede --type composer:idea`.
R14: The `engage` skill dismisses an item with `canon supersede --type composer:idea`.
R15: The `engage` skill does not name `score:feedback`.
R16: No tracked file outside `docs/history/` names `score:backlog-item` or `score:feedback`.

## Acceptance criteria

- R1, R2, R3, R4, R7: a conversion test builds a temporary store with backlog records and history, runs the one-shot rename, and compares ids, subjects, bodies and payloads. `canon validate` on the live store passes after the store commit.
- R5, R6: a schema test loads the score module and finds neither type. `canon schemas sync` on the live store reports score as `updated` and the status as `synced`.
- R8: `tests/test_views.py` covers an open idea, a dismissed idea and an idea without effort.
- R9, R10, R11: the dashboard model and app tests create `composer:idea` records and drive the panel, promote and dismiss paths.
- R12 to R15: the skill contract test in `tests/test_assess_routing.py` accepts every `canon` invocation the new engage text documents and finds no `score:feedback`.
- R16: a scan test over `git ls-files` finds neither name outside `docs/history/`. The test builds the names from parts so it does not name them itself.

## Constraints

- No schema version changes. score and composer stay at 1.0.0.
- score does not import composer. The score module changes only by removing two types.
- The conversion runs once, on the primary checkout, while no other chat writes the store. The rename is committed before `canon schemas sync` runs.
- The conversion script is not shipped. A temporary-store test proves the rename logic.
- `docs/plans/monorepo-plan.md` and `design/canon/schema-modules.md` follow the new state. `README.md` follows it too.

## Non-goals

- Ideas without an effort in the dashboard. Phase `idea-triage` shows them on the roadmap view.
- `orchestra idea`, the triage skill and `orchestra view roadmap`.
- Teaching `engage` to start an effort from an idea. That is phase `engage-from-idea`.
- A replacement for `score:feedback`. It has no records and no writer.
- Assigning `composer:area` to converted ideas.

## Invariants

- A converted idea keeps its id, so links and history stay valid.
- A store with an open `composer:idea` and an effort ref passes `canon validate`.
- Promote and dismiss keep the `effort`, `source` and `phase` payload fields.

## Assumptions

- Phase `composer-schema` is merged to `main` first. This phase branches from `main` after the merge.
- `composer:idea` payload fields (`status`, `effort`, `phase`, `source`) match `score:backlog-item` one to one. Verified on a scratch copy: 41 files rewritten (21 live, 20 history), 21 ideas listed, `canon validate` valid after the commit.
- `canon schemas sync` without a version change copies the new score snapshot and does not run migrations.
- The primary checkout has uncommitted edits in many test files this phase touches. The phase branch does not see them.
