## Requirements

R1: A command can emit an SSH-signed attestation of a verdict whose canonical payload includes the judged commit, the manifest hash, the runner digest, and per-claim results.

R2: A verify command rejects an attestation whose signature does not verify under the allowlist.

R3: A verify command rejects a well-signed attestation bound to a different commit or a different manifest hash than the one presented.

R4: A CI action (or equivalent workflow file) runs verdict and produces a signed attestation on a fixture repository.

## Acceptance criteria

- Emit + verify succeeds on a fixture key and allowlist for a passing verdict.
- Tampered payload bytes fail verify.
- Attestation for commit A fails verify when checked against commit B (or a different manifest hash).
- A workflow file under the repo (or fixture repo) invokes the emit path.

## Constraints

- Reuse SSH signing primitives already used for amendments where practical.
- `claims-authority` and verdict-authority stay: the attestation mirrors a real verdict, it does not replace re-execution for authors who still run verdict.
- No store tokens under `affidavit/`.

## Non-goals

- Orchestra dashboard gate UI (may consume verify later).
- Oracle provenance checks.
- Making local unsigned verdict impossible.

## Invariants

- Verify never returns success for a bad signature or a bind mismatch.
- Attestation namespace is distinct from `affidavit-amendment`.

## Assumptions

- CI can hold a signing key listed in the fixture allowlist.
- Runner digest exists after frozen-environment (or attestation includes the runner argv bytes equivalently).
