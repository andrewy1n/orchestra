## Description

R8: The phase and task overlay tabs and dialogs use shadcn-svelte components.
R11: `npm run check`, `npm test`, and `npm run build` pass.
Context: the web UI (Vite + Svelte 5 + TypeScript + Tailwind 4, Biome lint, Vitest) lives at `dashboard/web/ui` with a 1,264-line `src/App.svelte` (613 lines of script). The FastAPI server lives in `dashboard/backend/server/` and serves `dashboard/web/ui/dist`. This phase moves the UI to `dashboard/frontend`, adds the `$lib` alias and shadcn-svelte, splits `App.svelte` into state modules and screens, and adopts the shadcn default look. Behavior, routes, and deep links do not change. The lint gate stays at zero findings. The CI `web` job runs `npm ci`, `npm run lint`, `npm run check`, `npm test`, `npm run build` in the UI folder. `npm run check` also runs `api-types:check`.

## Approach

Replace the hand-built tab strips and confirm/note dialogs in the phase and task overlays (and the Needs-you confirm dialog) with the shadcn-svelte `Tabs` and `Dialog` components (`$lib/components/ui/tabs`, `$lib/components/ui/dialog`), plus `Button` and `Badge` where they replace hand-built equivalents. Adopt the shadcn default look (decision `shadcn-appearance`): do not rebuild the previous palette on top of it. Behavior stays: tab selection, deep links, keyboard dismissal, and the confirm flow keep working. Update tests only where a selector depended on the removed markup (keep assertions); the `deepLinks` and `links` Vitest files stay byte-identical. Run `npm run lint`, `npm run check`, `npm test`, `npm run build`, and start `dashboard/bin/web` against a seeded store to confirm the built UI is served (`uv run pytest tests/dashboard/test_web_dashboard_launch.py -q`).
