## Description

R6: The Home screen has an Areas section that lists each area with its open idea count.
R7: An area detail screen shows the scope text and the idea list, open ideas first.
R8: Promoted ideas show collapsed on the area screen and link to their effort or phase.
R9: The area screen has no promote or dismiss action.
R10: An area screen has a deep link that reloads to the same screen.
Context: `dashboard/backend` has loaders (`snapshot.py`, `task.py`, `phase.py`, `journal.py`, `records.py`) that read the store only through `store.py`; `dashboard/backend/server/schemas.py` holds the Pydantic response models and `app.py` the FastAPI routes; `scripts/api_schema.py` writes `dashboard/frontend/openapi.json` and `npm run api-types` generates `dashboard/frontend/src/api-types.ts`; `tests/dashboard/test_endpoint_shapes.py` pins every route with a fixture and fails when a route has no case. The UI is in `dashboard/frontend` (Svelte 5, state modules in `src/lib/state`, screens in `src/lib/screens`, shadcn-svelte components in `src/lib/components/ui`, router in `src/router.ts`, regex-based Vitest files read UI source through `src/appSource.ts`). `composer:area` has a `title` and a `## Scope` section; `composer:idea` has `status` (open, promoted, dismissed) and optional `area`, `effort`, `phase`, `source`. The effort backlog (open ideas, with promote and dismiss) must not change. The lint gate stays at zero findings.

## Approach

Add `src/lib/state/areas.svelte.ts` (fetch `/api/areas` with the existing api helpers and the poll cycle; the generated `AreasResponse`/`Area` types come from `./api-types`), an `Areas` section on `src/lib/screens/Home.svelte` (heading `Areas`, one row per area: title, open idea count, link `#/area/<subject>`; hidden when the list is empty), and `src/lib/screens/Area.svelte`, the area detail screen (title, scope text rendered with the existing markdown helper, open ideas first, promoted ideas in a shadcn-svelte collapsed block (add `collapsible` via `npx shadcn-svelte@latest add collapsible` or use native `<details>`), each promoted idea linking to its effort or phase through the existing link helpers; no promote and no dismiss action, and none of those words in the screen's files). Extend `src/router.ts` with the route `#/area/<subject>` in the style of the existing routes, wire it in `App.svelte` (keep App.svelte under 150 lines) and list new files in `src/appSource.ts`. Reload on the deep link must show the same screen. Write Vitest tests in `src/lib/screens/areas.test.ts` whose test names start with `R6`, `R7`, `R8`, `R9`, `R10` (mount with a seeded snapshot and a stubbed fetch like `dialogs.test.ts`). Do not edit `deepLinks.test.ts` or `links.test.ts`. Use shadcn-svelte components (Badge, Button, Collapsible) for the new markup. Run `cd dashboard/frontend && npm run lint && npm run check && npm test && npm run build`.
