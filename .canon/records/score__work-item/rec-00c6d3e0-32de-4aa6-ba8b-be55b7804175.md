## Description

Add `run_tests`, which starts the manifest argv in a worktree and returns one JUnit outcome per requested id.

## Approach

Work in `/home/andrewyin/affidavit--runner-adapter` on branch `phase/runner-adapter`. Add `affidavit/runner.py` and `tests/test_runner.py`. Do not edit `affidavit/manifest.py` or `affidavit/verdict.py`.

1. `run_tests(worktree, test_ids, runner) -> dict[str, str]`. Expand the element that is exactly `{tests}` into one argument per id, in order. Replace `{report}` inside an element with a temporary XML path. Start that argument list with `subprocess` in `worktree`. Copy the environment and drop `PYTHONPATH` and `PYTEST_ADDOPTS`.
2. Parse the XML with `xml.etree`. A case with a `failure` child is `assertion_failed`. A case with an `error` child is `errored`. Both is `errored`. A `skipped` child is `not_run`. A case with none of those is `passed`. A requested id with no case, or a missing report, is `not_run`.
3. Match a case to an id when `name` equals the id. Otherwise, when `file` is present, take the dotted stem of `file`, drop that prefix from `classname`, and join `file`, the remaining classname segments, and `name` with `::`. Two cases for one id collapse to `errored` if any is an error, else `assertion_failed` if any is a failure, else `not_run` if any is skipped, else `passed`.
4. Tests, driven by a local command that writes JUnit, not by pytest's own runner: `test_run_tests_returns_id_outcomes`, `test_run_tests_maps_failure_error_skipped`, `test_run_tests_joins_name_or_file`. The join test covers a `name` equal to the id and a class id built from `file` plus classname. One test shows the child process does not see `PYTHONPATH`.
