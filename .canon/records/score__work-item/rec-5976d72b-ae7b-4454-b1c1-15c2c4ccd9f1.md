## Description

R3: `App.svelte` has fewer than 150 lines.
R5: Home, Journal, Overlay, and Side rail are separate components under `src/lib`.
Context: the web UI (Vite + Svelte 5 + TypeScript + Tailwind 4, Biome lint, Vitest) lives at `dashboard/web/ui` with a 1,264-line `src/App.svelte` (613 lines of script). The FastAPI server lives in `dashboard/backend/server/` and serves `dashboard/web/ui/dist`. This phase moves the UI to `dashboard/frontend`, adds the `$lib` alias and shadcn-svelte, splits `App.svelte` into state modules and screens, and adopts the shadcn default look. Behavior, routes, and deep links do not change. The lint gate stays at zero findings. The CI `web` job runs `npm ci`, `npm run lint`, `npm run check`, `npm test`, `npm run build` in the UI folder. `npm run check` also runs `api-types:check`.

## Approach

Move the markup and the remaining script of `src/App.svelte` into `src/lib/screens/Home.svelte`, `Journal.svelte`, `Overlay.svelte`, and `SideRail.svelte`, one component per file; split further (for example `PhaseOverlay.svelte`, `TaskOverlay.svelte`) when a screen is large. `App.svelte` only wires the router to the screens and mounts the state modules, and stays under 150 lines. Keep markup, classes, and behavior identical; move code, do not redesign. The existing `.svelte` components `TaskFlowNode.svelte` and `TaskGraphBoard.svelte` may stay in `src/` or move under `src/lib/screens`; update imports either way. All Vitest tests pass unchanged. Run `npm run lint`, `npm run check`, `npm test`, `npm run build`.
