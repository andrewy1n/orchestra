## Description

R1: `#/` shows the product index with one card for each area.
R15: The area page shows one Needs-you list that merges the items of the efforts in the area.
R18: `#/effort/<name>` shows the Home screen of that effort.

## Approach

Fix three review findings. Frontend commands run in `dashboard/frontend`. Write each test first and see it fail on an assertion. Name each vitest test so it starts with the requirement id and a space. Do not edit `src/deepLinks.test.ts`, `src/detail.test.ts`, `src/detailNav.test.ts` or the frozen `tests/dashboard/test_areas_promoted.py`. Do not add comments that explain a change.

1. R15, finding `review-area-levels-sidebar-levels`. `src/App.svelte` always renders `<SideRail />`. On `#/` and `#/area/<subject>` it shows the Backlog, Needs-you and journal panels of an arbitrary first effort. Render `SideRail` only when the rail level is `effort` (the `railLevel` value that `App.svelte` already derives), and set the layout class so the grid has no side column on the product index and the area page (see the existing `no-rail` class in `src/app.css`). The area page keeps its own Needs-you list. Write `src/lib/screens/sidePanels.test.ts` with tests named `R15 ...`: on `#/` and on `#/area/<subject>` the whole document has no `[data-side-needs]`, no `[data-side-backlog]` and no `[data-side-journal-teaser]`, and on the area page exactly one Needs-you list exists in the document; on `#/effort/<name>` the side panels still render.
2. R18, finding `review-area-levels-leave-effort`. `leaveHref()` in `src/lib/state/polling.svelte.ts` reads `selectedEffort`. Make it resolve the effort from the open route first, with the same logic the breadcrumb uses (`routeEffort` in `src/lib/state/areas.ts`; export it; for `#/task/<id>` it resolves the effort through the task id), and fall back to `selectedEffort`, then to `""`. Keep `src/lib/state/areas.ts` free of Svelte imports.
3. R18, finding `review-area-levels-fallback-tests`. Write `src/lib/screens/leaveRoute.test.ts` with tests named `R18 ...`: a fresh load of `#/phase/<effort-b>/<phase>` where effort B is not the first effort, closed with the overlay Back button (`[data-act="close-detail"]`), ends on `#/effort/<effort-b>`; the same for a `#/task/<id>` deep link of effort B; the confirm-write close (approve a needs item, as the tests in `src/lib/screens/dialogs.test.ts` do) ends on the effort page of the open route's effort.
4. R1. Check that `#/` still shows the product index and no side panels, and keep the existing product index tests passing. Update an existing test only if it asserted the old side rail on those two screens; say so in the evidence.

Run before you finish: `npm run lint`, `npm run check`, `npm test` in `dashboard/frontend`; `uv run pytest tests/dashboard/test_areas.py tests/dashboard/test_ui_structure.py -q`.
