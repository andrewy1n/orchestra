## Description

R1: A manifest claim may declare `evidence_kind` as one of `unit`, `integration`, or `interaction`.
R2: `aff verdict` fails a claim declared `interaction` whose witness runs under the default unit pytest runner template.
R3: `aff verdict` passes a claim declared `interaction` whose witness runs under an interaction runner template that produces JUnit outcomes `run_tests` understands.

## Approach

1. Add `affidavit/evidence_kind.py`: `KINDS = ("unit", "integration", "interaction")`, `DEFAULT_KIND = "unit"`, a `TEMPLATES` map with `unit` (the default runner argv from `affidavit/manifest.py`) and `interaction` (`env AFF_EVIDENCE_KIND=interaction python3 -m pytest -o junit_family=xunit1 {tests} --junitxml={report}`), and a `kind_allows_runner(kind, runner)` helper. Only `interaction` restricts the runner.
2. `affidavit/manifest.py`: `Claim` gains `evidence_kind: str = "unit"`; `_parse_claim` reads the optional field and raises `ManifestError` naming `evidence_kind` for any other value.
3. `affidavit/verdict.py`: for each claim, before judging, fail with `evidence_kind: interaction requires an interaction runner template` when the head claim is `interaction` and the base or head manifest runner is not the interaction template. Unit and integration claims are unaffected.
4. `affidavit/cli.py`: add `aff runner-template {unit,interaction}` printing the argv as a compact JSON list (exit 0). Catch `ManifestError` in the verdict command, print the message to stderr, and exit 2.
5. Do not edit `tests/test_evidence_kind.py` (frozen oracle) or any existing test.
