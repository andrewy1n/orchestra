## Description

R1: `#/phase/<effort>/<phase>` renders the phase in the main pane, not in a dialog.
R4: The phase page header shows the phase title.
R5: The phase page header shows the phase state.
R6: The phase page shows the chips of the phase.
R7: The phase page shows the next action of the phase.
R8: The phase page shows one button for each requirement of the phase.
R10: The phase page shows the tabs of the phase.
R11: `#/phase/<effort>/<phase>/tab/<tab>` opens the page on that tab.
R12: The phase page shows the task graph on the tab that carries it.
R13: The phase page shows the evidence board on the tab that carries it.
R14: The phase page shows the sections of the phase detail.
R29: The phase page writes nothing to the store.

## Approach

Read the frozen tests in `dashboard/frontend/src/lib/screens/phasePage.test.ts` first. They mount `App`, read the DOM, and fix the selectors.

- Create `src/lib/screens/PhasePage.svelte` from the body of `PhaseOverlay.svelte`: tabs, chrome (chips, next action, requirement buttons), task graph, task board, evidence board, and the detail sections rendered with `phase.md`. Keep the attributes the existing tests read: `data-phase-tab`, `data-phase-chrome`, `data-phase-chips`, `data-phase-next`, `data-phase-req`, and the `data-detail-payload` probe. Add a header with the phase title and the phase state.
- The page root has `data-detail="phase"`, so `deepLinks.test.ts` and `detail.test.ts` keep passing unchanged. Loading and error notes go in the page.
- Mount `PhasePage` in `App.svelte` for the `phase` route, before the `effort` branches. Pass `theme`. Keep `App.svelte` under 150 lines; if the route switch does not fit, move it to one new `Main.svelte` component.
- Delete `PhaseOverlay.svelte`. Remove the phase branches from `Overlay.svelte` and the `phase.target` fallback added by `split-overlay-state`, so the dialog handles the leaf kinds only. Update `FILES` in `src/appSource.ts`.
- In `src/lib/state/keys.ts` use `leafTarget` in place of `detailTarget`, so `t` and Esc behave on the phase page as on any page.
- The page issues no POST. A tab press changes the hash only.
- Update `phaseOverview.test.ts` and any other test that breaks because the phase is a page. Do not edit `detail.test.ts`, `deepLinks.test.ts`, `detailNav.test.ts`, `detailView.test.ts` or `dialogs.test.ts`.
- Close with `npm run lint`, `npm run check`, `npm test` and `uv run pytest tests/dashboard/test_ui_structure.py -q`.
