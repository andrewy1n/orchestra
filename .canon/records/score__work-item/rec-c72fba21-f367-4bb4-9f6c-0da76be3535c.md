## Description

Fix re-review finding `rec-265b5127` (behavior-bug, R12) and the actionable part of `rec-e64256f8` (behavior-bug, R13). The OpenCode plugin is installed at `<root>/plugin.js`, which OpenCode does not auto-load; the generated agent also emits an inert `write: deny` alongside the correct `edit: deny`.

Apply decision `npx-list-clause`: the specification no longer requires `npx skills add --list`, so no `--list` test is added.

## Approach

- Change the OpenCode adapter destination for `hosts/opencode/plugin.js` from `<root>/plugin.js` to `<root>/plugins/plugin.js` for both project and global installs. Keep the source path and the existing opt-in/unsupported-host behavior.
- Update README hook paths and the installer/integration tests to the documented `plugins/` path; assert the old root `plugin.js` is absent.
- In `installer/agents.py` OpenCode rendering, drop `write`/`apply_patch` from the emitted permission map (or map them to `edit`); keep `permissions:` plural, `edit: deny`, and the read-only allow list. Update tests to assert the plural key, `edit: deny`, and no `write` action.
- Do not add an `npx --list` test; the specification amendment is recorded separately.
