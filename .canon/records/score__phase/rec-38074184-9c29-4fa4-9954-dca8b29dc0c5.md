## Problem

The phase opens as a modal over the effort page, with its own tabs. It sits outside the drill-down that `area-levels` adds, so the breadcrumb ends at the effort. The effort page also selects a phase to filter its task table, and a second press opens the modal, which is a two-step click.

## Approach

Build on `area-levels`. The phase becomes the fourth level, a routed page in the main pane. Settled by the user. Decisions: `phase-page-main-pane`, `leaf-views-stay-modals`, `effort-tasks-move-to-phase`, `phase-target-kept`.

- `#/phase/<effort>/<phase>[/tab/<tab>]` renders a page: breadcrumb `Product › Area › Effort › Phase`, header with title and state, chips, next action, requirement buttons, tabs, task graph, status tabs, task list, evidence board and sections.
- The effort page lists phases as rows with progress bars. A row opens the phase page. The effort page drops its task table and status tabs.
- The left rail on the phase page lists the phases of the effort, marks the current one and folds done phases.
- The task, requirement, needs, backlog and record views stay modals. Their write buttons do not move. A task or requirement modal sits over the phase page of its own phase.
- Esc on the phase page opens the effort page. Existing `#/phase/...` deep links keep working.
- `detailTarget` keeps returning the phase target. A new `leafTarget` returns null for the phase, and the dialog uses it. The phase page root keeps `data-detail="phase"`, the phase tab buttons keep `data-phase-tab`, and the page keeps the `data-detail-payload` probe. These keep `detail.test.ts` and `deepLinks.test.ts` unchanged, and `test_ui_structure.py` pins the hash of `deepLinks.test.ts`.
- The status tabs and the filtered task list sit on the overview tab under the task graph. The `tasks` tab keeps its wave board.

Rejected: a full-screen dialog, pages for the leaf views, keeping the task table on the effort page, and changing `detailTarget` to return null for the phase.

Plan: seven tasks, then the closing verification task.

1. `split-overlay-state` moves the phase state out of `overlay.svelte.ts` into `phase.svelte.ts`. The phase modal still renders from it. No test file changes.
2. `phase-page` adds `PhasePage.svelte`, mounts it for the phase route and removes the phase dialog.
3. `phase-nav` and `phase-tasks` run together. `phase-nav` adds the phase level to the breadcrumb and the rail, and Esc. `phase-tasks` adds the status tabs and the filtered task list.
4. `leaf-over-page` keeps the phase page behind a task or requirement modal and returns to it on close.
5. `effort-phase-rows` turns the effort page phases into linked rows with progress bars, removes its task table and status tabs, and removes the unused phase and tab state from `polling.svelte.ts`.
6. `e2e-phase-page` adds the Playwright test.

New frontend acceptances are `tdd` checks, one per requirement. The test name starts with the requirement id. An oracle author writes them from the requirement text, and the parent freezes each after an assertion-level red. The tests mount `App` and read the DOM, so the executor takes selectors from the frozen tests.
