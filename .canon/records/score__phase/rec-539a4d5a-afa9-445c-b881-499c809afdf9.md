## Problem

About 6,900 lines of Textual UI, the tmux plugin, and their tests duplicate the web UI. Keeping both costs too much. `journal.py` mixes Textual screens with loaders that the web server imports.

## Approach

Extract the Textual-free logic from `journal.py` and the other modules the web server imports. Delete the Textual modules, the tmux plugin (`orchestra.tmux`), `dashboard/bin/dashboard`, `dashboard/bin/dashboard-status`, the tmux tests, the CI tmux job, and the README tmux sections. Drop `textual`, and drop `rich` if nothing else uses it. Move the surviving modules to `dashboard/backend/` and the web server to `dashboard/backend/server/` with `git mv` and no content change other than imports (decision `backend-move-timing`). Add `orchestra status` and `orchestra status --count` (decision `status-cli`). The UI stays at `dashboard/web/ui`. Task order: extract, delete, move, status, verify.

## Exit criteria

Requirement ids come from the phase specification.

- R1 to R5, R11: No file imports `textual`, `pyproject.toml` does not list it, `rich` is listed only if imported, and the tmux files, job, marker, and README sections are gone (tests that check the tree).
- R6, R7: No module sits directly under `dashboard/` except `__init__.py`; the survivors live under `dashboard/backend/` and the server under `dashboard/backend/server/` (tests).
- R8, R13: The server serves `dashboard/web/ui/dist`, and the web API tests pass (`tests/test_web_dashboard.py`, `tests/test_web_dashboard_launch.py::test_r30_serves_build`).
- R9, R10: `orchestra status` and `orchestra status --count` print the expected output against a seeded store (integration tests).
- R12: `uv run basedpyright` passes, and its baseline names no deleted file.
- Integration: `dashboard/bin/web` serves a snapshot (launch tests).
