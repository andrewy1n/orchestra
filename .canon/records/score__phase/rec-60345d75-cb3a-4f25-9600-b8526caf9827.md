## Problem

The `types` job from `ci-workflow` runs mypy with `continue-on-error: true`, so a type error never blocks a merge. mypy also skips unannotated function bodies by default, and much of this code is lightly annotated.

## Approach

Chosen: replace mypy with basedpyright in `standard` mode (`types-checker`). Configure it in `pyproject.toml` over `orchestra`, `dashboard` and `installer` (`types-scope`), Python 3.10, pinned in the `dev` group. Run it as `uv run basedpyright` locally and in CI.

Fix the 26 errors under `orchestra/`. Commit a baseline of the remaining `dashboard/` and `installer/` errors, and make the `types` job blocking (`types-baseline`). Update `tests/test_ci_workflow.py` so it asserts the job runs basedpyright and is blocking. Name the command in `README.md`.

The slug stays `mypy-gate` because other records name it.

Task order: `types-config` and `types-job-blocking` run first. `fix-orchestra-types` follows `types-config`. `write-types-baseline` follows the fixes. `verify-mypy-gate` closes the phase.

## Exit criteria

- `uv run basedpyright` exits 0 on the repository (command).
- The baseline has no `orchestra/` entry (command).
- A new error outside the baseline fails the command (command).
- The `types` job is blocking and passes on a pull request (observed GitHub Actions run).
