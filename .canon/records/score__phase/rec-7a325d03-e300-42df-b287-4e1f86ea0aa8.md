## Problem

`dashboard/model.py` is 1899 lines and `dashboard/app.py` is 1859 lines. Both files stay in the `dashboard` package.

## Approach

Split the model along the screens that already exist, and keep `dashboard.model` as a facade (`dashboard-feature-modules`). `dashboard/model.py` becomes the package `dashboard/model/`, with modules for store access, the snapshot, task detail, phase detail, and requirement detail. Screen classes other than `DashboardApp` leave `dashboard/app.py`. The model package does not import Textual or Rich.

## Exit criteria

- Names imported from `dashboard.model` today still resolve, and the loaders are defined outside the facade.
- `NeedsYouDetailScreen`, `BacklogDetailScreen`, `PhasePickerScreen`, `KeyHelpScreen`, and `NeedsConfirmModal` are defined outside `dashboard/app.py`. `DashboardApp` stays there.
- No module under `dashboard/model/` imports Textual or Rich.
- The dashboard, web, and proof-dashboard test modules pass.
- Every acceptance passes.

## Proof

kind: claims. A human reads the check-runs for the dashboard and web tests and confirms the screens still come from the same public model names.
