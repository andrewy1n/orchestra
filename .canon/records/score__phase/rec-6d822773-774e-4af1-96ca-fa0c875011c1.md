## Problem

The `affidavit-verdict` GitHub Actions workflow fails on every push: it runs `git` and `aff verdict` against `tests/fixtures/verdict-repo`, but that path was never created. Signed-verdict R4 only asserted the workflow YAML mentions verdict/attest, so CI never actually passed.

## Approach

Adopt `ci-fixture-supply`: track fixture source templates under `tests/fixtures/verdict-repo/` (no nested `.git`), add a `tests/fixtures/build_verdict_repo.sh` (or `.py`) builder that `git init`s and commits a green `claim-widget` subject there, call that builder from a workflow step before `Run aff verdict`, keep attest emit/verify as-is, and tighten `test_ci_workflow_runs_verdict_and_attest` so it requires the build step and templates. Phase-end reviewer skipped.

## Exit criteria

- Local dry-run of builder → `bin/aff verdict` → `bin/aff attest` → `bin/aff attest verify` succeeds for the fixture (Actions-equivalent without depending on live secrets in the verify command).
- Builder + templates are in-tree; `tests/fixtures/build_verdict_repo.sh` (or the chosen builder) leaves a git repo at `tests/fixtures/verdict-repo` and verdict for `claim-widget` passes.
- Strengthened `tests/test_attestation.py::test_ci_workflow_runs_verdict_and_attest` fails if the build step or templates are removed.
