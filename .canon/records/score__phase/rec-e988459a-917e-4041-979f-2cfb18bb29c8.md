## Problem

Claims and oracle bindings live as acceptance records in a store any agent can write. A verdict is only as trustworthy as the records it reads, and `runner: aff` on a check-run is just a payload field.

## Approach

Committed manifest and a re-executing verdict (decisions: `claims-authority`, `verdict-authority`, `amendment-approval`). Spec/design: `claims-manifest`.

`.affidavit/manifest.json` committed in the work repo holds claim id, text, pytest node ids, and oracle file hashes. `.affidavit/allowed_signers` is the OpenSSH allowlist. `bin/aff verdict --at <rev> [--base <rev>] [--cwd <dir>] <claim-ids>` re-executes those tests at `--at` and at `--base` in a temporary worktree. It exits 0 only when the oracle bytes match the manifest, the tests fail at base on an assertion, and they pass at head. A test-id or hash change between the two manifests passes only when an amendment entry verifies under the allowlist at `--base`, and that allowlist is unchanged at `--at`. The command does not read or write the artifact store. A stored check-run cannot change the result.

`evidence-effort-order` keeps this phase first. `evidence_kind` enforcement and the phase-end report stay later phases of this effort. Skill and dashboard migration stays in `orchestration-split`.

Tasks, in dependency order:

1. `verdict-manifest` and `amendment-sign` have no dependency on each other.
2. `verdict-command` depends on both. It adds `affidavit/verdict.py` and the `verdict` subcommand in `affidavit/cli.py`.
3. `verify-claims-manifest` depends on all three. It runs the exit-criterion commands through `bin/aff` tests in `tests/test_verdict.py`.

**Session shape:** more than one
**Executor:** subagent
**Human stops:** plan review; Landing merge into `main` (no push)
**Collision notes:** `verdict-manifest` owns `affidavit/manifest.py` and `tests/test_manifest.py`. `amendment-sign` owns `affidavit/amendment.py` and `tests/test_amendment.py`. Those two do not edit each other, `affidavit/cli.py`, `affidavit/verdict.py`, or `affidavit/oracle_red.py`. `verdict-command` owns `affidavit/verdict.py`, the `verdict` subcommand in `affidavit/cli.py`, and `tests/test_verdict.py`. It imports the first two modules and does not change their behavior. `verify-claims-manifest` runs the named pytest filters; a missing test is added only in `tests/test_verdict.py`.

## Exit criteria

- `aff verdict` exits 0 only when manifest hashes match the tree at `--at`, the oracle tests fail at `--base` on an assertion, and they pass at `--at`.
- CLI subprocess tests cover that pass, a hash mismatch, a missing or invalid amendment signature, an allowlist change, and a `--cwd` pointed at a phase worktree other than the store checkout.
- A forged stored check-run does not change the verdict.
