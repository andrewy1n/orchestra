## Problem

A packaging break in the wheel does not show up in the source-tree tests. `--help` loads only the argument parsers, so a lost `schemas/*.json`, entry point, or `providers.json` passes it. No CI job installs the wheel and runs it outside the checkout.

## Approach

Chosen: a behavioral smoke (`wheel-smoke-depth`). `scripts/wheel_smoke.py` builds the wheel from a copy of the tracked files, installs it into a clean venv, and runs every check from a temporary directory. The checks are `orchestra --help`, `canon --help`, `canon init` and `canon validate` in a temporary git repository, `orchestra install --list`, and imports of `dashboard`, `dashboard.web`, `installer` and `installer.adapters`. A blocking `wheel` job in `ci.yml` runs the script. `README.md` names it as the local check.

The missing `dashboard/web/ui/dist` in the wheel is out of scope (`wheel-smoke-ui-dist`). A backlog idea records it.

## Exit criteria

- `python3 scripts/wheel_smoke.py` exits 0 on the repository (command).
- The script exits non-zero for a wheel without `installer/providers.json` (command).
- The script leaves the checkout unchanged (command).
- The `wheel` job is blocking and passes on a pull request (observed GitHub Actions run).

## Proof

kind: commands. A human reads the `python3 scripts/wheel_smoke.py` output, the failing run on a broken wheel, and the green `wheel` job on the phase pull request.
