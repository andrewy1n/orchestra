## Problem

The SessionStart hook in orchestra/stage/hooks.py emits the protocol, the handoff (capped at 16,384 bytes), and active constraints as one additionalContext string. On this repo it is about 16,700 characters. Claude Code caps each additionalContext string at 10,000 characters. Above the cap it passes a 2,000-character preview and a file path, and does not ask the agent to read the file. Agents see the protocol and the first two efforts only. The constraints, placed last, never reach them.

## Approach

Per hook-context-shape: the hook renders its own compact view. Protocol first, then constraints, then one section per live effort with only Goal, Position, In Progress, Blocking Question, Needs Human and Unsigned Manual Check, without id links, newest position first. A 9,000-character budget omits whole efforts and names them with a pointer to `orchestra handoff --effort <slug>`. Per hook-constraints-scope: constraints come from every live effort. `orchestra handoff` is unchanged.

Tasks: compact-hook-view (views.py), then hook-budget (hooks.py), then verify-hook-context-budget.

Size: one sitting. Executor: inline for every wave.

Human stops: plan review; merge to main; push.

Collision notes: phase/shared-helpers replaces `_payload` with `record_payload` across orchestra/views.py. Whichever phase merges second resolves a mechanical conflict in the new hook-view code.

## Exit criteria

- Each of R1–R12 passes as a test against a temporary store (`uv run pytest tests/test_hooks.py tests/test_views.py`).
- R13: the start hook run against this repo's store returns additionalContext of at most 10,000 characters (command check).

## Proof

kind: commands. A human runs the start hook against this repo and sees every live effort or a pointer line, with constraints near the top, in under 10,000 characters.
