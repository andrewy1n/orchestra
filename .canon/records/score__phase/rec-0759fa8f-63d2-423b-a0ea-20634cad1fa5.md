## Problem

`dashboard/model.py` has 1,914 lines. It mixes store reads, derivation helpers, view types, and loaders. It parses argv-style strings through `_run` to mimic the canon CLI. Two web servers share one Reader. `service.py` maps dataclasses to JSON by hand, and `types.ts` repeats the shapes by hand.

## Approach

Split `model.py` by loader into `snapshot.py`, `task.py`, `phase.py`, and `journal.py`, with shared helpers in `records.py` (decision `loader-module-cut`). Read the store only in `store.py`, with typed filters over `Project.list` (decision `typed-store-reads`). Keep one FastAPI server and delete the stdlib server (decision `one-fastapi-server`). Define the responses as Pydantic models (decision `pydantic-api-contract`). Generate and commit `api-types.ts`, and check sync in Python CI (decision `api-types-codegen`). Move the dashboard tests to `tests/dashboard/`. The OpenAPI schema is committed as `dashboard/web/ui/openapi.json`; `scripts/api_schema.py [--check] [--schema PATH]` writes or checks it, and `npm run check` also regenerates `api-types.ts` and fails on a diff, so the `web` CI job covers the TypeScript half.

## Exit criteria

Requirement ids come from the phase specification.

- R1 to R5: Only `store.py` reads the store, no `_run(` under `dashboard/backend`, no `http.server` import under `dashboard`, `model.py` is gone, and the four loaders live in their own modules (tests that grep the tree).
- R6: Pydantic models define every `/api/*` response (test on the OpenAPI schema).
- R7, R8: `api-types.ts` is generated from the committed OpenAPI schema; the sync check passes on a clean tree and fails when the schema is stale (tests).
- R9: The UI imports its API types from `api-types.ts` and `types.ts` holds no API shape (test; `npm run lint` and `npm run check`).
- R10: The dashboard tests live under `tests/dashboard/` (test).
- R11: A characterization test shows each endpoint keeps its JSON shape for a seeded store.
- R12: `uv run basedpyright` passes.
- Integration: `dashboard/bin/web` serves a snapshot and the UI from a seeded store (launch tests).
