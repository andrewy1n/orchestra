## Approach

Tests: write the test file named below. Start every test name with the requirement id and a space, for example `R5 an area card shows the open idea count`. Write one test for each requirement and no other test name starts with an id. Run the test first and see it fail on an assertion, then implement. Files: `dashboard/frontend/src/effortRoute.test.ts` (R18) and `dashboard/frontend/src/lib/state/areas.test.ts` (unit tests for the pure functions below).

1. `src/router.ts`: add the `effort` route name to `RouteName` and `NAMES`. Add `effortName(route)` that returns `route.parts[1]` for an `effort` route, else an empty string.
2. `src/detail.ts`: add `effortHref(name)` that returns `#/effort/<encoded name>`, next to `areaHref`.
3. New `src/lib/state/areas.ts` with pure functions and no Svelte imports. Types come from `src/types.ts` and `src/api-types.ts`.
   - `groupByArea(efforts, areas)` returns `{ groups: Array<{ area: AreaView; efforts: EffortView[] }>, unplaced: EffortView[] }`. Groups follow the order of `areas`. An effort whose `area` matches no area goes to `unplaced`. An effort with an empty `area` goes to `unplaced`.
   - `areaRollup(efforts, area)` returns `{ efforts: number; openIdeas: number; needs: number }`.
   - `railItems(route, snapshot, areas)` returns `{ level: "product" | "area" | "effort"; items: Array<{ key; label; href; current; finished; needs }> }`. `product`: no items. `area`: the areas, current one marked. `effort`: efforts of the current effort's area, or the efforts with no area when it has none. A route that is not home, area or effort and that shows an effort (task, phase, requirement, needs, backlog, record, milestone) counts as the `effort` level for the selected effort.
   - `breadcrumbParts(route, snapshot, areas)` returns `Array<{ label; href? }>`: `Product` (href `#/`), the area title (href `#/area/<subject>`) when the effort has an area, the effort name (href `effortHref`). The last part has no href. Area route: `Product`, area title. Home route: `Product` only. Journal and other routes: reuse the effort level.
4. `src/lib/state/polling.svelte.ts`: when the route is `effort`, `selectedEffort` follows the route name (the URL is the source of truth). Keep `selectEffort` for the other callers.
5. `src/App.svelte`: for the `effort` route render `Home` for that effort. Do not change the home route yet. That is the `product-index` task.

Run `npm run lint`, `npm run check` and `npm test` in `dashboard/frontend` before you finish. Do not add comments that explain a change.

### Design / decisions (quote)

Invariants:
- Hash routing only. One served document.
- The product index and the area page write nothing.
- An idea never renders among the efforts.
- The URL decides the selected effort.

Assumptions:
- Phase `effort-area-link` is merged, so `area` is on every snapshot effort.
- The Home screen needs no change other than the chip.
- The Playwright seed store can hold an area and a placement.

Decisions:
- landing-product-index: #/ shows the product index, one card for each area; the effort Home moves to #/effort/<name>
- area-join-client-side: Group efforts in the browser from the snapshot; the backend adds promoted ideas to the area of their effort's placement
