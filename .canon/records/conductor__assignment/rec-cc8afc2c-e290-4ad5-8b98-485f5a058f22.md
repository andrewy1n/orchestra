## Approach

Tests: write the test file named below. Start every test name with the requirement id and a space, for example `R5 an area card shows the open idea count`. Write one test for each requirement and no other test name starts with an id. Run the test first and see it fail on an assertion, then implement. File: `dashboard/frontend/src/lib/screens/breadcrumbRail.test.ts`. Mount the real `App` as the existing tests do (`src/lib/screens/areas.test.ts` shows the stub of `/api/snapshot` and `/api/areas`).

1. New `src/lib/screens/Breadcrumb.svelte`: `<nav class="breadcrumb" data-breadcrumb aria-label="Breadcrumb">`. Render `breadcrumbParts(...)` from `lib/state/areas.ts`. Every part except the last is an `<a>`. The last part is a `<span aria-current="page">`. Parts are separated by `›`. The text of the nav reads `Product › <area title>` and the other forms in the requirements.
2. `src/App.svelte`: replace the top-bar `crumbs` text (`routeLabel`) with `<Breadcrumb />`. Remove `routeLabel` from `router.ts` only if nothing else uses it.
3. New `src/lib/screens/Rail.svelte` replaces `EffortRail.svelte` (delete the old file). `<nav class="rail" data-rail-level={level}>`. It renders `railItems(...)`: items are `<a>` links (`data-rail-item`, `href`), with `class:on` for the current one. Level `product`: render no rail element at all, and `App.svelte` drops the layout column, so the product index has no left rail (R9). Level `area`: heading "Areas". Level `effort`: heading is the area title, or "Efforts".
4. The show-finished toggle (`data-act="show-finished"`) stays on the effort level only, with the same `polling.showFinished` state and the same text. Finished efforts with Needs-you items stay visible, as `visibleEfforts` does today.
5. Move the dot, name and sub-line markup from `EffortRail.svelte` into the effort-level rail items. Update the existing tests that click `button.effort[data-effort]` so they follow the new link markup. Use `git grep -n "data-effort\|EffortRail\|routeLabel"` to find them.

Run `npm run lint`, `npm run check` and `npm test` in `dashboard/frontend` before you finish. Do not add comments that explain a change.

- The product index and the area page write nothing.
- An idea never renders among the efforts.
- The URL decides the selected effort.

Assumptions:
- Phase `effort-area-link` is merged, so `area` is on every snapshot effort.
- The Home screen needs no change other than the chip.
- The Playwright seed store can hold an area and a placement.

Decisions:
- rail-siblings: The left rail lists the siblings of the current level
- landing-product-index: #/ shows the product index, one card for each area; the effort Home moves to #/effort/<name>
