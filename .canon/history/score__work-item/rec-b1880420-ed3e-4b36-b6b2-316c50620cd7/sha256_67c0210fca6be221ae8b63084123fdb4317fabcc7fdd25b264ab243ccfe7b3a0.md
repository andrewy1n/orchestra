## Description

Close the phase-end review findings on `aff verdict`: a non-zero pytest at `--at` must not pass a claim, and the CLI tests must cover a valid signed amendment, a failing head run, and a hash or test-id change with no covering amendment.

## Approach

Edit `affidavit/verdict.py` and `tests/test_verdict.py` only. Do not change `affidavit/manifest.py` or `affidavit/amendment.py` behavior.

1. `_head_passed` must not return true when the pytest process at `--at` exits non-zero. A claim passes at head only when that pytest exit code is 0. Keep the assertion-level check for the base run.

2. Add these subprocess tests in `tests/test_verdict.py`, each invoking `bin/aff verdict`:
   - `test_verdict_accepts_signed_amendment`: a test-id or oracle-hash change between `--base` and `--at` exits 0 when the `--at` manifest has an amendment whose signature verifies under the base allowlist and the allowlist bytes match.
   - `test_verdict_refuses_head_failure`: oracle tests fail at `--at` (assertion) after a valid base, and the command exits non-zero with reason `tests failed`.
   - `test_verdict_refuses_missing_amendment`: test ids or hashes differ and the `--at` manifest has no covering amendment chain; the command exits non-zero (`missing step` or the equivalent authorize failure).
