## Description

Prove the phase exit criteria hold together. Run each CI command locally exactly as the workflow runs it, run the broken-input proxy for each blocking job, then check the Actions run on the phase branch.

R9: The `checks` job runs `scripts/build_skills.py --check`.
R10: The `checks` job runs `scripts/check_orchestra_plugin_names.py`.
R11: The `checks` job runs `canon validate`.
R14: `ruff check` exits 0 on the repository.
R15: A test job runs `uv run pytest -n auto --confcutdir=tests/canon tests/canon`.
R16: A test job runs `uv run pytest -n auto --confcutdir=tests/tuner tests/tuner`.
R17: A test job runs `uv run pytest -n auto tests --ignore=tests/canon --ignore=tests/tuner`.
R19: The `tmux` job runs the `tmux` marker without `-n`.
R23: A deliberate test failure turns the workflow run red.
R24: A deliberate ruff violation turns the workflow run red.
R25: A deliberate `canon validate` error turns the workflow run red.
R26: A deliberate skill-sync drift turns the workflow run red.
R27: Every blocking job passes on a pull request from the phase branch.
R28: `scripts/test.sh` exits 0 locally.

## Approach

Run every acceptance with `orchestra check`. The R27 acceptance needs a pushed `phase/ci-workflow` branch and a pull request. That push is a human stop; ask before it. Do not push without approval.
