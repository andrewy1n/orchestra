## Description

R1: When a usable artifact store is present, `aff audit` creates at least one `project:evidence-observation` whose technique identifies the audit run.
R2: When a usable artifact store is present and probes run as part of `aff audit`, each probe run that produces a reported outcome is covered by an evidence-observation whose technique identifies probes.
R3: Each audit or probe evidence-observation includes replay metadata sufficient to re-invoke that technique against the same revisions.
R4: The audit and probe recording paths create no `project:evidence-binding`.
R5: `aff trail --technique` can restrict the listed observations to the audit and probe technique ids used above.
R6: When no usable store is present, `aff audit` keeps its pre-phase advisory JSON on stdout and exit semantics.

## Approach

1. Extend the shared observation recorder to accept technique, revs, result, and optional replay; keep no-import / no store-token rules.
2. After `aff audit` finishes (with or without probes), when a store is usable, record unbound evidence-observation(s) for the audit run and for probe outcomes; never create evidence-binding.
3. Put enough replay metadata (argv/revs/technique) in the observation payload or body for re-invoke.
4. Preserve advisory JSON stdout and exit codes when no store is present.
5. Use stable technique id strings (e.g. `audit` and `probes`) that `aff trail --technique` can filter.
6. Do not edit frozen oracle test files; do not change bind verbs.
