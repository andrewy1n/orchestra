## Description

Give executors the specification and design they need, and record semantic integration after parallel work.

## Approach

In `skills/execute-phase/SKILL.md`, the assignment Orientation quotes the requirement texts for the work-item's `requirements`, the design Invariants and Assumptions, and the named decisions. Subagents still return evidence and do not call `adaptive-artifacts`.

After the last implementation wave and before dispatching the verification task, create `project:integration-report` for the phase. `result` is `pass` only after interfaces, shared assumptions, cross-task invariants, and integration behavior have been checked. A clean git merge does not by itself write `pass`. On `fail` or `blocked`, do not dispatch the verification task.

Skip the report when incidental, or when no implementation wave has more than one task.

Add `tests/test_integrate_rules.py`. It asserts the skill creates `project:integration-report` with `result` constrained to the contract enum, states that a git merge is not a pass, and states the skip. Check the invocation with `skill_extraction.check_skill_text`.

Do not edit `verify-work` or `discuss`.
