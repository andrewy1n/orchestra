## Description

R10: The dashboard tests live under `tests/dashboard/`.
Context: `dashboard/backend/model.py` (1,914 lines) mixes store reads, derivation helpers, view types, and loaders, and parses argv-style strings through `_run(` to mimic the canon CLI. `dashboard/backend/server/service.py` has a stdlib HTTP server (`http.server`) beside the FastAPI app in `app.py`. `dashboard/web/ui/src/types.ts` repeats the API shapes by hand. The canon library (`orchestra/canon`) must not change. Every endpoint keeps its JSON shape through the phase. The web server must start and serve a snapshot after every task.

## Approach

`git mv` every dashboard test (`tests/test_dashboard_*.py`, `tests/test_web_dashboard*.py`, `tests/test_web_fastapi_writes.py`, `tests/test_idea_dashboard.py`, `tests/test_proof_dashboard.py`, `tests/test_orchestra_status.py`'s dashboard-facing siblings only if they target `dashboard/`) into `tests/dashboard/`. Keep `tests/test_orchestra_status.py` and `tests/test_remove_textual.py` where they are (CLI and repo-layout tests). Fix paths and imports (`Path(__file__).resolve().parents[N]`, fixtures, `conftest.py` helpers, `tests/helpers.py` imports), the CI test commands that name moved files, the README Testing section if it names them, and any `verify_command` text in docs. Run `uv run pytest tests/dashboard -q` and `uv run pytest tests/test_ci_workflow.py tests/test_tiered_verification.py -q`.
