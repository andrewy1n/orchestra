## Description

R8: The phase and task overlay tabs and dialogs use shadcn-svelte components. The swap must keep the layout and the dismissal behavior.

Review findings: (1) `src/lib/screens/Overlay.svelte` gives `Dialog.Content` the class `flex ...` without `flex-col`, so the header, body, and footer lay out in a row (the old `.overlay` was a column with a top bar, a scrolling body, and a bottom key footer); (2) `src/lib/state/polling.svelte.ts` defines `openPhase()` and an identical unused `_openPhase()`; (3) no test covers Escape, focus restore, or stacked-dialog dismissal after the bits-ui swap.

## Approach

(1) Add `flex-col` (and make the body scroll: `min-h-0 flex-1 overflow-y-auto` on the body wrapper) so the dialog is a column; check the other `Dialog.Content` uses (ConfirmModal) for the same class conflict. (2) Delete the duplicate `_openPhase`; keep `openPhase` and the regex the tests match. (3) Add `src/lib/screens/dialogs.test.ts` (a new Vitest file; do not edit deepLinks.test.ts or links.test.ts) that mounts the App with a seeded snapshot and checks, in jsdom: Escape on the detail overlay closes it; Escape with the confirm dialog open over the detail overlay closes only the confirm dialog; focus returns to the opener after close; Enter in the confirm note input submits; the detail dialog content has the `flex-col` class. Follow the mounting helpers other tests use (see `phaseOverview.test.ts`, `deepLinks.test.ts`). Run `npm run lint`, `npm run check`, `npm test`, `npm run build`.
