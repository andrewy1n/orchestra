## Description

R1: `aff verdict` fails a claim when the commit that introduced its oracle paths is not an ancestor of the implementation under test (oracle after implementation).
R2: `aff verdict` fails a claim when the oracle-introducing commit touches paths outside the claim's oracle and frozen support set.
R3: `aff verdict` fails a claim when the oracle-introducing commit and the implementation commits share the same SSH commit signer principal, for histories where those commits are signed.
R4: `aff verdict` passes a fixture history that satisfies ordering, oracle-only paths, and different signers.

## Approach

1. Add `affidavit/provenance.py` with a function that, for a claim, resolves the oracle commit O with `git log --diff-filter=A` per oracle path (newest of the first-adding commits reachable from `--at`), checks ordering, diffs O (`git diff-tree --root -r --name-only`) against the allowed path set, and compares SSH commit signer principals.
2. Principals: run `git -c gpg.ssh.allowedSignersFile=<temp copy of .affidavit/allowed_signers at --at> log --format=%G?%x09%GS` for O and for each commit in `base..at`; only status `G` counts as signed. Same principal on O and any implementation commit fails; if either side has no signed commit the signer rule is skipped.
3. Add `--provenance` to `aff verdict` in `affidavit/cli.py` and thread it through `run_verdict` in `affidavit/verdict.py`. With the flag, provenance runs per claim before the red/green judging and its failure reason takes precedence. Reasons are exactly `provenance: oracle after implementation`, `provenance: oracle commit touches non-oracle paths`, and `provenance: shared signer`. Without the flag nothing changes.
4. Do not edit `tests/test_provenance.py` (frozen oracle) or any existing test. Do not import the store; git is the only authority.
