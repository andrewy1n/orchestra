## Description

`bin/aff verdict` re-executes the frozen pytest oracles at two revisions and applies the manifest and amendment checks. It does not read the artifact store.

## Approach

Add `affidavit/verdict.py` with `run_verdict(cwd, at, base, claim_ids)`. When `base` is omitted, use `merge_base(cwd, at)`.

- Resolve both revisions with `resolve_commit`. Load both manifests and both allowlist blobs with `load_manifest` and `load_allowlist`. Do not read the worktree copies.
- If the allowlist blobs differ, every named claim fails with reason `allowlist changed`.
- For each claim id, require the claim in both manifests. Call `authorize` from `affidavit.amendment`. Hash the claim's oracle files at each revision with `hash_oracle_files` and require the digests to equal that revision's `oracle_hashes`.
- For each revision, `git -C cwd worktree add --detach <temp> <commit>`, then run `python3 -m pytest <node ids>` with that worktree as cwd. Capture combined output. At `--base`, parse `FAILED <node>` lines and require `is_assertion_level_failure` from `affidavit.oracle_red`. At `--at`, require pytest exit 0. In a `finally`, `git worktree remove --force` the temp path. The temp path must be unique.
- Do not call adaptive-artifacts and do not read `.artifacts`.

Wire `verdict` in `affidavit/cli.py`: `--cwd` (default process cwd), `--at` required, `--base` optional, claim ids `nargs='+'`. Print `{"result":"pass"|"fail","claims":[{"id","result","reason"}]}` on stdout. Include `reason` only when that claim fails. Exit 0 when `result` is `pass`, exit 1 when it is `fail`.

Tests live in `tests/test_verdict.py`. Build a temporary git repo, not this repo's history. Commit a base where the oracle test fails on `assert`, with matching manifest hashes and an allowlist. Commit a head where that test passes and the hashes still match. Invoke `bin/aff verdict` as a subprocess. Use these test names:

- `test_verdict_pass_when_hashes_match_and_red_then_green`
- `test_verdict_refuses_hash_mismatch`
- `test_verdict_refuses_not_assertion`
- `test_verdict_refuses_bad_signature`
- `test_verdict_refuses_allowlist_change`
- `test_verdict_cwd_phase_worktree` — `--cwd` is a second worktree; process cwd is a different directory
- `test_verdict_forged_check_run` — a fake `project:check-run` under `.artifacts` leaves both a passing and a failing verdict unchanged

Import `affidavit.manifest` and `affidavit.amendment`. Do not change their behavior. Do not edit `affidavit/oracle_red.py` except to call it.
