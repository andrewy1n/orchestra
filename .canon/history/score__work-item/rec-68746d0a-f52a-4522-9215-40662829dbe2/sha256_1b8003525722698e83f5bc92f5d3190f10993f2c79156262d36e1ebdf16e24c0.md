## Description

R4: `dashboard/backend/model.py` does not exist.
R5: Each of the snapshot, task, phase, and journal loaders lives in its own module with its view types.
Context: `dashboard/backend/model.py` (1,914 lines) mixes store reads, derivation helpers, view types, and loaders, and parses argv-style strings through `_run(` to mimic the canon CLI. `dashboard/backend/server/service.py` has a stdlib HTTP server (`http.server`) beside the FastAPI app in `app.py`. `dashboard/web/ui/src/types.ts` repeats the API shapes by hand. The canon library (`orchestra/canon`) must not change. Every endpoint keeps its JSON shape through the phase. The web server must start and serve a snapshot after every task.

## Approach

Split `model.py` by loader (decision `loader-module-cut`): `snapshot.py`, `task.py`, `phase.py`, and `journal.py` (the existing `journal.py` journal loaders merge into the journal module; keep one module). Each module holds its `load_*` functions and its view types. Shared helpers go in `dashboard/backend/records.py` only when two loaders use them. Imports point one way (store -> records -> task -> phase -> snapshot; journal beside them) with no cycles. Move code with `git mv`/cut-and-paste and change nothing except imports and the placement; rewrite imports in `gates.py`, `approval.py`, `backlog.py`, `dismiss.py`, `server/`, `orchestra/status_cli.py`, and the tests. Delete `model.py` at the end. After each loader moves run `uv run pytest tests/dashboard/test_endpoint_shapes.py tests/test_web_dashboard.py tests/test_web_dashboard_launch.py tests/test_dashboard_model.py tests/test_dashboard_journal.py tests/test_dashboard_gates.py tests/test_orchestra_status.py -q`. Run `uv run basedpyright` (update the baseline paths if the baseline names moved files).
