## Description

Decide whether an amendment chain authorizes a claim's test-id and hash change under the base allowlist. No checkout and no pytest.

## Approach

Add `affidavit/amendment.py`. Inputs are plain dicts. Do not import `affidavit.manifest`.

- `canonical_payload(amendment)` is UTF-8 bytes of: a line `affidavit-amendment v1`, `claim: <id>`, `old_tests:` and `new_tests:` as comma-separated ids in list order, then `old_hashes:` and `new_hashes:` blocks whose lines are `<relpath> <sha256:hex>` sorted by relpath. The signature field is not included.
- `verify_signature(payload, signature, allowlist_bytes)` writes the allowlist to a temp file and runs `ssh-keygen -Y verify -f <file> -n affidavit-amendment -s <sigfile>` with the payload on stdin. Try each principal (first token of each non-comment, non-empty allowlist line) as `-I`. Accept when any principal verifies.
- `authorize(base_claim, head_claim, amendments, base_allowlist, head_allowlist)` returns `(ok, reason)`. If the allowlist blobs differ, ok is false and reason is `allowlist changed`. If test ids and hashes are equal, ok is true. If they differ, walk `amendments` in list order, skipping other claim ids. Each step's `old_tests` and `old_hashes` must equal the current state, the signature must verify against `base_allowlist`, and the current state becomes `new_tests` and `new_hashes`. The walk must end equal to the head claim. A gap, a bad signature, or a key absent from the base allowlist returns ok false.

Tests in `tests/test_amendment.py` generate an ed25519 key with `ssh-keygen -t ed25519 -N ''`, write an allowed_signers line with namespace `affidavit-amendment`, and sign with `ssh-keygen -Y sign -n affidavit-amendment`. Cover a one-step chain, a two-step chain, a broken middle, a bad signature, a key that is not on the allowlist, differing allowlist bytes, and an unchanged claim with no amendment.

Do not edit `affidavit/cli.py`, `affidavit/verdict.py`, `affidavit/manifest.py`, or `affidavit/oracle_red.py`.
