## Description

Prove through the adaptive-artifacts CLI that a seeded store can create, list, promote, and dismiss backlog items without treating them as feedback.

## Approach

Add `tests/test_backlog_item.py` (name flexible) that builds a fresh git-backed store from the bundled contract the same way other contract/CLI tests do (`helpers` / `conftest`).

Drive the real CLI entry point (`tools/artifacts.py` via the test helpers):
1. Create a goal/effort subject, then create `project:backlog-item` with `status=open` and required `effort`.
2. List with `--where payload.status=open` and see the item; confirm `project:feedback` create/list path is unchanged and distinct.
3. Supersede to `promoted` (optional `phase`) and confirm it no longer appears in open lists; supersede another item to `dismissed` similarly.
4. Assert create without `effort` fails.

Do not edit skills or the contract in this task. Prove with `uv run --with textual --with pytest python -m pytest tests/test_backlog_item.py -q` (adjust path to the file you add).
