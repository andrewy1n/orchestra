## Description

R1: `dashboard/backend/store.py` is the only module that calls `Project.list` or `Project.get`.
R2: No module under `dashboard/backend` contains `_run(`.
Context: `dashboard/backend/model.py` (1,914 lines) mixes store reads, derivation helpers, view types, and loaders, and parses argv-style strings through `_run(` to mimic the canon CLI. `dashboard/backend/server/service.py` has a stdlib HTTP server (`http.server`) beside the FastAPI app in `app.py`. `dashboard/web/ui/src/types.ts` repeats the API shapes by hand. The canon library (`orchestra/canon`) must not change. Every endpoint keeps its JSON shape through the phase. The web server must start and serve a snapshot after every task.

## Approach

Create `dashboard/backend/store.py` with typed read functions (list records by type, state, and payload filters; get one record; the change token the server already uses). It calls `Project.list` and filters by state and payload in typed Python (decision `typed-store-reads`; do not change canon). Replace every `Project.list`/`Project.get` call and every `_run(` argv-string call in `model.py`, `journal.py`, `gates.py`, `approval.py`, `backlog.py`, `dismiss.py`, and `server/` with calls to `store.py`. Keep behavior identical; the endpoint shape tests and the dashboard tests must pass after each step: `uv run pytest tests/dashboard/test_endpoint_shapes.py tests/test_web_dashboard.py tests/test_web_dashboard_launch.py tests/test_dashboard_model.py tests/test_dashboard_journal.py tests/test_dashboard_gates.py -q`. Write actions (dismiss, approve) keep their canon CLI or API calls in their modules; only reads go through `store.py`. Run `uv run basedpyright`.
