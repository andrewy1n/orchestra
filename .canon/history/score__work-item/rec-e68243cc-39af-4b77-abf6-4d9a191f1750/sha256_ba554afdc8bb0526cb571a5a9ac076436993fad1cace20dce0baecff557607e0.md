## Description

R4: The audit plants mutants only in noticed blocks (LLM or tool proposals allowed; only test runs judge) and reports at least one surviving mutant documented in `spikes/llm-mutants/findings.md` for that range.

## Approach

1. In `affidavit/audit.py`, load the `--mutants FILE` proposals (`mutants[].patch.old` and `patch.new`, with `id` and `file`), cap them at `--max-mutants` (default 20), and plant each only in a noticed block of the same file whose added text contains `patch.old`; every other mutant is reported `skipped`.
2. Plant a mutant by replacing the first occurrence of `patch.old` with `patch.new` in a fresh detached worktree at `head`, run the claim tests with `run_tests`, and report `killed` when a claim test that passed at head is `assertion_failed`, `survived` when all still pass, and `invalid` on errors or no applicable text. Only test outcomes decide.
3. Fill the `mutants` and `survivors` lists of the audit JSON, and extend `aff audit` in `affidavit/cli.py` with `--mutants` and `--max-mutants`.
4. Do not edit `tests/test_audit.py` (frozen oracle) or any existing test.
