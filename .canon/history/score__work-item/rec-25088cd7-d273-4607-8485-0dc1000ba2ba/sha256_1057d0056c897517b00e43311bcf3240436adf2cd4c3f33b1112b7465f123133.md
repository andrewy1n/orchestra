## Description

R15: The phase page has the same status tabs that the effort page has today.
R16: The phase page lists the tasks of the phase that match the selected status tab.
R17: A task row on the phase page opens the task view as a modal.

## Approach

Read the frozen tests in `dashboard/frontend/src/lib/screens/phaseTasks.test.ts` first. They mount `App` and fix the selectors.

- `PhaseState` gains `statusTab` (default `"active"`), `counts` from `tabCounts`, `tasks` from `filteredTasks`, and `chooseTab`. The inputs are the snapshot `EffortView` of the route effort and the route phase subject. Reset `statusTab` when the route phase changes.
- Copy the default-tab fallback effect from `bindPolling` into `bindPhase`: when the effort has Needs you rows and the active tab is empty, select the first non-empty tab. Leave the polling copy in place. `effort-phase-rows` removes it.
- Render in `PhasePage.svelte`, on the overview tab under the task graph: a `[data-status-tabs]` strip of `button.tab[data-tab]` with counts, then a `[data-task-table]` list of `button.trow.task[data-task]` rows that open `taskHref(id)`. Reuse the markup and class names of `Home.svelte` so the styles apply.
- Close with `npm run lint`, `npm run check`, `npm test`.
