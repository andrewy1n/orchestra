## Evidence

Run: timeout 300 python3 scripts/session_report.py --records. 247 sessions, 8 with records, 553 records attached, 386 ambiguous. Tests pass; the join works as specified. The overlap comes from long session windows: a session spans first to last event, including idle gaps, and several sessions in one project run at once.

## Consequence

The decision to join by time window named this as the trigger for adding a session id. Counts for a single session are inflated wherever windows overlap. Counts for effort and task across all sessions are less affected, because the overlap is mostly within one effort.

## Follow-up

Choose one: (a) add a session id to records in the contract, in both plugins; (b) narrow windows to active spans, for example split at idle gaps longer than N minutes; (c) accept the ambiguity and report only per-effort aggregates.
