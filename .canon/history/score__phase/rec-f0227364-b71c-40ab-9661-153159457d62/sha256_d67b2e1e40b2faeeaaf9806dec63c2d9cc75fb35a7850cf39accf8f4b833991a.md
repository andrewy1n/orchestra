## Problem

The file store has no cross-record transaction, relies on a file lock, and enforces immutability through a git check. Parallel writers need atomic writes and a store that every worktree shares.

## Approach

Add `SqliteBackend` behind the `Backend` protocol, with `ops`, `records`, `revisions` and `meta` tables, WAL mode and `BEGIN IMMEDIATE` writes. The DB lives at `~/.canon/<repo-name>/canon.db`. Config and schemas stay files in the repo. `canon backup` writes consistent copies. Settled by the user. Decisions: `canon-store-engine`, `canon-store-topology`, `canon-db-location`, `canon-config-in-git`, `canon-backup-command`.

## Exit criteria

- R1 to R14 of the specification pass. Verified by the unit tests, the multiprocess stress test and the parametrized suite.
- The `tests/canon` suite passes on both backends. Verified by running it.
- `canon validate` passes on a temporary DB store. Verified by running it.

## Proof

kind: commands. A human runs the stress test with several writer processes and sees every write land and one winner per contested update.
