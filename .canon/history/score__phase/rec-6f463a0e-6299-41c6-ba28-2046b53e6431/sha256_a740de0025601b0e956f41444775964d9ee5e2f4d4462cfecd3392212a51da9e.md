## Problem

`score:backlog-item` (41 records, 21 live) and `score:feedback` (0 records) carry idea-shaped intent inside work planning. The dashboard backlog panel, `orchestra/views.py` and the `engage` skill read them.

## Approach

Chosen: rename in place, no version bump (`backlog-conversion-method`). Switch the dashboard, the handoff view, `engage`, the docs and the tests to `composer:idea` first. Remove `backlog-item` and `feedback` from the score module. Then, on the primary checkout, run a one-shot script that renames every backlog record and history snapshot to `composer:idea` with `apply_steps`, commit the store, run `canon schemas sync`, and commit again. The dashboard panel keeps its shape: open ideas that carry an effort, grouped by effort (`idea-panel-scope`). The phase starts after `composer-schema` merges to `main`.

## Exit criteria

- Every acceptance passes.
- `canon validate` reports no errors on the live store after the conversion.
- The live store holds 21 `composer:idea` records with the ids of the old backlog items, and no `score:backlog-item` or `score:feedback`.
- No tracked file outside `docs/history/` names `score:backlog-item` or `score:feedback`.
- `scripts/test.sh` passes.

## Proof

kind: claims. A human reads the check-runs for the conversion, panel and skill-contract tests, and the live-store validate output.
