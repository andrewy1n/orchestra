## Problem

The store is visible as a product only through the Textual dashboard in tmux. The browser spike under `spikes/web-dashboard` already reads `dashboard.model`, but it is a stdlib server and hand-built DOM, and it cannot change the store.

## Approach

Ship a localhost web dashboard beside the Textual app. FastAPI serves the spike's JSON API and a Vite production build of a Svelte app styled with Tailwind. The page opens light, and a control switches the whole page to dark and back for that visit. The page polls the change token. Needs you approve, reject, sign, and accept, and backlog dismiss and promote, call the same Python functions as the terminal. Decisions: `web-dashboard-shape`, `web-dashboard-toolchain`, `web-dashboard-writes`, `web-dashboard-server`, `web-dashboard-freshness`, `web-dashboard-styling`, `web-dashboard-theme`.

## Exit criteria

- `dashboard/bin/web` serves the built app on 127.0.0.1 for the store the Textual launcher would open (launcher test against this repo).
- TestClient tests pass for the snapshot, the token, each write, a stale Needs you revision, and a refused kind.
- `npm run build` in `dashboard/web/ui` succeeds, and GET / returns that build.
