## Problem

adaptive-artifacts can store records, but it has no public function other packages can call. Orchestra and the dashboard each decide whether the store is in the repo or under the home directory. Affidavit only passes `--root`, so a project pinned to the home store is invisible to it. `SE_WORKFLOW_STORE` is a leftover name for a one-shot `local` or `global` switch.

## Approach

Settle the module layout in settle-phase. The behavior is already chosen: adaptive-artifacts exposes `open_store`, get, list, create, and apply. The `adaptive-artifacts` command calls those functions. Resolution order is an explicit path (`--store` or `ARTIFACTS_STORE`), then `store-binding.local.json`, then `store-binding.json`, then the repo store if it has `meta.json`, otherwise the home store if that one does. A binding that names a store with no `meta.json` fails. `SE_WORKFLOW_STORE` is removed.

## Exit criteria

Tests in the adaptive-artifacts repo show `open_store` follows that order, and the command still creates and reads a record when `--store` is omitted. Nothing reads `SE_WORKFLOW_STORE`. Verified by that repo's test suite.
