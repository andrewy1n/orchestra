## Problem

Efforts have no area. The only link between an area and an effort is an idea, and promotion drops the idea's area. The dashboard cannot group efforts under areas.

## Approach

Add a `composer:placement` record: one per effort, subject = effort slug, payload `area` (decision `placement-record-link`). Add `orchestra place <effort> <area>`, which creates or moves the placement. Add `area` to each effort row of the snapshot. The `engage` skill names `orchestra place` for new efforts. The agent proposes a mapping for the 12 existing efforts and the user confirms it before the backfill (decision `backfill-confirm`). This phase builds no page. Phase `area-pages` does (decision `area-phase-split`).

## Exit criteria

- R1 to R9 of the specification pass. Verified by `tests/test_composer_placement.py`, the endpoint shape test, `npm run api-types:check` and the skill text test.
- The user confirmed a mapping, and every effort in it has a placement. Verified by `canon list --type composer:placement` and `canon validate`.
- `.canon/schemas/composer.json` matches the shipped schema. Verified by `canon schemas sync` leaving no diff.
- Full CI passes on a pushed branch. Verified by a CI run observation.

## Proof

kind: commands. A human runs `orchestra place` on one effort, reads that effort's `area` in `GET /api/snapshot`, and runs `canon validate`.
