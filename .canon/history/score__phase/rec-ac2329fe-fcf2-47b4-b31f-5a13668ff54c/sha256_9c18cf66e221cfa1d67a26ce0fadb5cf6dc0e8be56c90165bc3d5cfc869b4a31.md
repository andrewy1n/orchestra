## Problem

Efforts have no area. The only link between an area and an effort is an idea, and promotion drops the idea's area. The dashboard cannot group efforts under areas.

## Approach

Add a `composer:placement` record: one per effort, subject = effort slug, payload `area` (decision `placement-record-link`). Add `orchestra place <effort> <area>`, which creates or moves the placement. Add `area` to each effort row of the snapshot. The `engage` skill names `orchestra place` for new efforts. The agent proposes a mapping for the existing efforts and the user confirms it before the backfill (decision `backfill-confirm`). This phase builds no page. Phases `area-levels` and `phase-level` do (decision `area-phase-split`).

Task order: `placement-schema` and `engage-place-step` first. Then `place-command` and `snapshot-area`. Then `backfill-placements` (a human stop). Then `verify-effort-area-link`.

Session shape: more than one sitting. The backfill waits for the user's confirmation.

Human stops: the backfill mapping confirmation, the manual sign of R10, and the push and merge.

Collision notes: the `package-layout` effort has phases in progress that may touch `orchestra/cli.py`. Rebase on `main` before landing.

## Exit criteria

- R1 to R10 of the specification pass. Verified by `tests/test_composer_placement.py`, the endpoint shape test, `tests/test_composer_schema.py`, `npm run api-types:check`, the engage skill test, and the signed manual check for R10.
- `.canon/schemas/composer.json` matches the shipped schema. Verified by `canon schemas sync` leaving no diff.
- `canon validate` passes with the placements in the store.
- Full CI passes on a pushed branch. Verified by a CI run observation.

## Proof

kind: commands. A human runs `orchestra place` on one effort, reads that effort's `area` in `GET /api/snapshot`, and runs `canon validate`.
