## Problem

The wheel does not ship the built UI. An installed wheel reports "No web build". Nothing tests the real UI against the real server.

## Approach

Run this phase after `wheel-smoke` of the `ci` effort (decision `wheel-smoke-ownership`; it is merged). The repo has no release workflow, so the CI `wheel` job is the build that runs `npm run build` before the wheel. The release build runs `npm run build`, and package data ships `dashboard/frontend/dist` (decision `dist-packaging`). Extend the wheel smoke to request `GET /`. Add one Playwright test that starts the server on a seeded store and checks that a seeded effort shows in headless Chromium (decision `e2e-browser-tool`). A source checkout without `dist` shows a message that names the build command.

## Exit criteria

Requirement ids come from the phase specification.

- R1, R2, R3: The built wheel contains `dashboard/frontend/dist/index.html`; the CI `wheel` job runs `npm run build` before the wheel is built (the repo has no separate release workflow); `dist` stays gitignored and untracked (tests).
- R4, R5: With the wheel installed in a clean environment, `GET /` returns the UI index, and `scripts/wheel_smoke.py` (the `wheel` job) asserts it (tests).
- R6, R7, R8: A Playwright test starts the server on a seeded store, loads the page in headless Chromium, and sees a seeded effort name; a CI job installs the browser and runs it (tests, local run, CI job).
- R9: A source checkout without `dist` shows a message that names the build command (test).
- R10: Full CI passes on a pushed branch (observed run).
- Integration: the installed wheel serves the dashboard (wheel smoke).
