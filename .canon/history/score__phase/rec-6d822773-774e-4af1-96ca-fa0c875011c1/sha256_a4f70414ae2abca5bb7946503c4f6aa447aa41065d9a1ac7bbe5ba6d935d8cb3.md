## Problem

The `affidavit-verdict` GitHub Actions workflow fails on every push: it runs `git` and `aff verdict` against `tests/fixtures/verdict-repo`, but that path was never created. Signed-verdict R4 only asserted the workflow YAML mentions verdict/attest, so CI never actually passed.

## Approach

Adopt `ci-fixture-supply`: track fixture source templates under `tests/fixtures/verdict-repo/` (no nested `.git`), add a workflow step that builds a git repo there before `aff verdict`, keep attest emit/verify as-is, and tighten the R4 pytest so it requires the build step and templates. Phase-end reviewer skipped.

## Exit criteria

- Push/PR workflow `affidavit-verdict` completes verdict → attest → verify when fixture secrets are present (Actions green).
- Builder + templates are in-tree; local `builder && aff verdict --cwd tests/fixtures/verdict-repo --at HEAD claim-widget` passes.
- Strengthened attestation CI pytest fails if the build step or templates are removed.
