## Problem

The dashboard and CLI prefer `~/.artifacts/<repo>` whenever that path has `meta.json`, so an empty or contract-drifted home store can shadow the real repo store and break every list/view.

## Approach

Exclusive store binding: `local` (repo `.artifacts`) or `global` (`~/.artifacts/<name>`). Resolution: `SE_WORKFLOW_STORE` → `.artifacts/store-binding.local.json` → `.artifacts/store-binding.json` → default (repo meta else home meta). Committed default + local override. This repo pins `local`. Shared resolve used by dashboard and `se_workflow.aa`. No dual-store merge. Decisions: store-modes, binding-layers, se-workflow-binding.

## Exit criteria

Binding resolution picks exactly one store; this repo's committed binding is local; dashboard `--once` and `se_workflow.aa.run_aa` use the bound store; tests for precedence and exclusive failure pass; README and ensure-store document the binding.
