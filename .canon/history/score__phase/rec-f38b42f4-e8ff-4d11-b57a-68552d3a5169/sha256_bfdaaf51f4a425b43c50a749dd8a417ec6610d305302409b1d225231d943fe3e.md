## Problem

A rendered view is a static file. It goes stale while execute-phase changes records, and the markdown carries ids and banners that clutter a terminal.

## Approach

1. terminal-view-format (adaptive-artifacts): a pure formatter turns a rendered view into terminal text. It drops the derived-view banner and `_(id: ...)_` suffixes, bolds headings unless colour is off, truncates lines to the terminal width, and prints an empty-state line when nothing matches.
2. watch-command (adaptive-artifacts, depends on 1): `watch --id <view> [--interval S] [--once]`. It re-renders every interval and redraws in place only when the formatted text changes. It shows a header with the store and the last change time. Ctrl-C exits 0. A render error shows in place and the loop keeps trying.
3. verify-watch-renderer-phase (depends on 1 and 2): integration test that runs the real `watch` in a pty against a temp store, plus both full suites.

## Exit criteria

- `watch` redraws within 3 s after a record write: verified by the pty integration test.
- `watch` emits no redraw while nothing changes: verified by the same test counting redraw frames over an idle second.
- Ctrl-C exits 0: verified by the same test sending SIGINT.
- Both full suites pass: verified by running them.
