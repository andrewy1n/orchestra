## Problem

aff is not a standalone evidence tool. `aff check` and `aff close-batch` load and write workflow records (`project:acceptance`, `project:check-run`, `project:work-item`, `project:finding`, `project:oracle-amendment`). `affidavit/aa_resolve.py` still resolves the se-workflow store binding: `SE_WORKFLOW_STORE`, `store-binding.json`, and the switch between this repo's `.artifacts` and `~/.artifacts/<repo>`. `affidavit.tmux` still launches `dashboard/bin`.

## Approach

Affidavit audits a code change from git alone (decision `affidavit-product`): claims with a frozen witness, changed code no test notices, and behavior changes no claim asked for, shipped as a CLI and a CI check. This phase is the first step: affidavit keeps `manifest.py`, `amendment.py`, `verdict.py`, and `oracle_red.py`, and `check.py`, `close_batch.py`, `aa.py`, `aa_resolve.py`, `policy.py`, `affidavit.tmux`, and their tests move to orchestra (decision `store-commands-home`). Orchestra calls `aff verdict` for the gate answer. The audit commands built from the spikes, and runners other than pytest, are later phases.

## Exit criteria

A checkout of this repo, with no orchestra tree, no adaptive-artifacts on PATH, and no se-workflow store binding, still produces a verdict from the committed manifest. A test fails while any module under `affidavit/` names a `project:` record type, `SE_WORKFLOW_STORE`, `store-binding.json`, or invokes `adaptive-artifacts`.
