## Problem

aff is not a standalone evidence tool. `aff check` and `aff close-batch` load and write workflow records (`project:acceptance`, `project:check-run`, `project:work-item`, `project:finding`, `project:oracle-amendment`). `affidavit/aa_resolve.py` still resolves the se-workflow store binding: `SE_WORKFLOW_STORE`, `store-binding.json`, and the switch between this repo's `.artifacts` and `~/.artifacts/<repo>`. `affidavit.tmux` still launches `dashboard/bin`.

## Approach

Affidavit audits a code change from git (`affidavit-product`): claims with a frozen witness, changed code no test notices, and behavior changes no claim asked for, shipped as a CLI and a CI check. This phase is the first step (`store-commands-home`, `aff-orchestra-seam`). `aff` has one command, `verdict`. `manifest.py`, `amendment.py`, `verdict.py`, and `oracle_red.py` stay. `check.py`, `close_batch.py`, `aa.py`, `aa_resolve.py`, `policy.py`, `affidavit.tmux`, and their tests move into orchestra. The store commands are `orchestra check` and `orchestra close-batch`. The moved close path imports `is_assertion_level_red` from `affidavit.oracle_red` and does not import `run_verdict`. A gate answer is the exit of `aff verdict`. The audit commands built from the spikes, and runners other than pytest, are later phases.

## Exit criteria

1. A checkout of this repo, with no orchestra tree, no adaptive-artifacts on PATH, and no se-workflow store binding, still produces a verdict from the committed manifest.
2. `aff check` and `aff close-batch` are not commands.
3. A test fails while any module under `affidavit/` contains `project:`, `SE_WORKFLOW_STORE`, `store-binding.json`, or `adaptive-artifacts`.
4. `orchestra check` and `orchestra close-batch` run from `~/orchestra`, and the moved check, close-batch, and store-client tests pass there.
5. The close path imports `affidavit.oracle_red`, and no orchestra module imports `affidavit.aa`, `affidavit.aa_resolve`, `affidavit.check`, `affidavit.policy`, or `affidavit.verdict`.
6. Orchestra skills run `orchestra check` and `orchestra close-batch` for those steps, and `aff verdict` for a manifest claim.

## Run

One sitting. No human stops. Every task is `subagent`.

Wave 1 is `move-store-client` (30 minutes). Wave 2 is `skill-command-names` (14) and `strip-aff-verbs` (18), so 18 minutes. Wave 3 is `verify-standalone-aff` (8). Phase elapsed is 56 minutes.

Wave 1 writes only `~/orchestra`. Wave 2 writes disjoint trees: `skill-command-names` edits `~/orchestra` skills, README, and command-string tests; `strip-aff-verbs` edits the affidavit worktree. `skill-command-names` may touch `tests/test_verify_authority.py` after `move-store-client` has changed its imports, and it leaves those `orchestra.*` imports in place. `strip-aff-verbs` does not delete modules from the live `~/affidavit` checkout; that checkout changes when the affidavit branch merges.
