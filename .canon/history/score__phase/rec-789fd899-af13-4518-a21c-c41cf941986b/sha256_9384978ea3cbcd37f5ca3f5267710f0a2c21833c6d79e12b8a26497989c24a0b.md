## Problem

aff is not a standalone evidence tool. `aff check` and `aff close-batch` load and write workflow records (`project:acceptance`, `project:check-run`, `project:work-item`, `project:finding`, `project:oracle-amendment`). `affidavit/aa_resolve.py` still resolves the se-workflow store binding: `SE_WORKFLOW_STORE`, `store-binding.json`, and the switch between this repo's `.artifacts` and `~/.artifacts/<repo>`. `affidavit.tmux` still launches `dashboard/bin`.

The goal is that claims and oracles live in a committed manifest, a verdict is a re-run of those tests, and an orchestration layer gets a gate answer only by calling `aff`.

## Approach

Decide in this discussion. The product has to run without the workflow store and without the orchestration surfaces.

## Exit criteria

A checkout of this repo, with no orchestra tree and no se-workflow store binding, still produces a verdict from the committed manifest. The command that proves the workflow types and the store switch are gone is set when the approach is chosen.
