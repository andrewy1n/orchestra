## Problem

Claims and oracle bindings live as acceptance records in a store any agent can write. A verdict is only as trustworthy as the records it reads, and `runner: aff` on a check-run is just a payload field.

## Approach

not yet scoped — discuss when this phase is current. Direction: a committed manifest (claim ids, text, evidence_kind, test ids, file hashes, approved amendments) is the authority. `aff verdict <claims> --at <rev>` re-executes the frozen tests at that revision (and at base in a temporary worktree for the red) and checks hashes. Stored runs are a log. Close accepts only the verdict.

## Exit criteria

Decide at plan-phase. At minimum: `aff verdict` returns pass only when the manifest hashes match and the oracle tests fail at base and pass at head, verified by CLI subprocess tests that include a phase-worktree `--cwd` case; a forged stored check-run does not change the verdict (test).
