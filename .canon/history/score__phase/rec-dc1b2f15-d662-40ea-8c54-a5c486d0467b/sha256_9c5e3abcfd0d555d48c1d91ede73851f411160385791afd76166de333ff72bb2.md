## Problem

Nothing checks that a phase's specification, work-items, and acceptances line up. Plan review relies on a prose rule in plan-phase, so an uncovered or phantom requirement id can reach execution. A specification also has no way to mark an unknown, so an agent guesses.

## Approach

**Skill-gated `orchestra analyze` with a clarification marker** (`analyze-gate-strength`, `marker-scope`, `analyze-stage-flag`).

- Add a pure analysis function in `orchestra/score/analyze.py` and an `orchestra analyze <phase> [--stage plan|close] [--json]` subcommand. It checks requirement coverage across specification, work-items, and acceptances, spec hygiene, and (close stage) check-run results. Exit 1 on errors; warnings never change the exit code.
- Define the `[NEEDS CLARIFICATION: <question>]` marker. `analyze` reports it as an error in the specification and the design, except inside inline code spans.
- Edit three skills: settle-phase documents the marker, plan-phase refuses plan review while the plan stage exits 1, execute-phase refuses to close while the close stage exits 1.

Session size: one.
Human stops: plan review.
Collision notes: this phase owns `orchestra/cli.py` (new subcommand), `orchestra/score/analyze.py`, and the three skill files named above. Phase 2 (effort brief sections) touches `orchestra/score/schemas`, the `init` skill, and must not start before this phase merges.
