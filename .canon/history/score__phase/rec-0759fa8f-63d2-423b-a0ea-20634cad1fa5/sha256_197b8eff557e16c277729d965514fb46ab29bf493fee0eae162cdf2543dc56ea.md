## Problem

`dashboard/model.py` has 1,914 lines. It mixes store reads, derivation helpers, view types, and loaders. It parses argv-style strings through `_run` to mimic the canon CLI. Two web servers share one Reader. `service.py` maps dataclasses to JSON by hand, and `types.ts` repeats the shapes by hand.

## Approach

Move the Python code to `dashboard/backend/`: `store.py` (typed reads only), `snapshot.py`, `task.py`, `phase.py`, `journal.py`, `status.py`, `actions/`, and `server/`. Call `Project.list` with typed arguments. Keep one FastAPI server, after checking how the check runner starts the dashboard. Define response models in Pydantic and generate the frontend TypeScript types from the OpenAPI schema. Add a CI check that the generated types are in sync. Move the tests to `tests/dashboard/`. Decide the module cut lines at plan-phase.

## Exit criteria

- `grep -rn "_run(" dashboard/backend` and `grep -rn "http.server" dashboard` print nothing (command).
- The generated-types sync check passes (command named at plan-phase).
- The web API tests pass under `tests/dashboard/`, and `uv run basedpyright` passes.
- Every acceptance passes, and `dashboard/bin/web` serves a snapshot and the UI from this repo's store (integration check through the real entry point).
