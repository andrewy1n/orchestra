## Problem

`dashboard/model.py` has 1,914 lines. It mixes store reads, derivation helpers, view types, and loaders. It parses argv-style strings through `_run` to mimic the canon CLI. Two web servers share one Reader. `service.py` maps dataclasses to JSON by hand, and `types.ts` repeats the shapes by hand.

## Approach

Split `model.py` by loader into `snapshot.py`, `task.py`, `phase.py`, and `journal.py`, with shared helpers in `records.py` (decision `loader-module-cut`). Read the store only in `store.py`, with typed filters over `Project.list` (decision `typed-store-reads`). Keep one FastAPI server and delete the stdlib server (decision `one-fastapi-server`). Define the responses as Pydantic models (decision `pydantic-api-contract`). Generate and commit `api-types.ts`, and check sync in Python CI (decision `api-types-codegen`). Move the dashboard tests to `tests/dashboard/`.

## Exit criteria

- No `_run(` under `dashboard/backend`, no `http.server` import under `dashboard`, and `model.py` is gone (test that greps the tree).
- The sync check passes on a clean tree and fails after a model change without regeneration (command).
- A characterization test shows each endpoint keeps its JSON shape for a seeded store.
- `npm run check` and `npm run lint` pass, and `uv run basedpyright` passes.
- Every acceptance passes, and `dashboard/bin/web` serves a snapshot and the UI from this repo's store (integration check through the real entry point).

## Proof

kind: commands. A human looks at the new module tree, the sync check run, and the dashboard running against this repo's store.
