## Problem

About 6,900 lines of Textual UI, the tmux plugin, and their tests duplicate the web UI. Keeping both costs too much. `journal.py` mixes Textual screens with loaders that the web server imports.

## Approach

Extract the Textual-free logic from `journal.py`. Delete the Textual modules, `orchestra.tmux`, `dashboard/bin/dashboard`, `dashboard/bin/dashboard-status`, the tmux tests, the CI tmux job, and the README tmux sections. Drop `textual`, and drop `rich` if nothing else uses it. Move the surviving modules to `dashboard/backend/` with `git mv` and no content change (decision `backend-move-timing`). Add `orchestra status` and `orchestra status --count` (decision `status-cli`). The UI stays at `dashboard/web/ui`.

## Exit criteria

- No file imports `textual`, `pyproject.toml` does not list it, and the tmux files, job, and marker are gone (test that checks the tree).
- The surviving modules live under `dashboard/backend/` and the server serves `dashboard/web/ui/dist` (`tests/test_web_dashboard_launch.py::test_r30_serves_build`).
- `orchestra status` and `orchestra status --count` print the expected output against a seeded store (integration test).
- The web API tests pass, and `uv run basedpyright` passes.
- Every acceptance passes, and `dashboard/bin/web` serves a snapshot from this repo's store (integration check through the real entry point).

## Proof

kind: commands. A human looks at the removed tree, the `orchestra status` output, and the web dashboard running from `dashboard/bin/web`.
