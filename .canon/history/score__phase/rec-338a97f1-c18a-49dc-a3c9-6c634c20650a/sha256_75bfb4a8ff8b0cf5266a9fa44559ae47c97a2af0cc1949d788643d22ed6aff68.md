## Problem

The evidence layer and the orchestration loop share one repo and one contract, so a skill can write a `tdd` or `check` result, or an oracle amendment, without going through `aff`.

## Approach

Verbs stay in this repo; the orchestration surfaces move to `~/orchestra` (decisions: `repo-split`, `verb-home`, `orchestra-name`, `contract-project`, `effort-records`, `commit-message`). Spec/design: `orchestration-split`.

This repo keeps `aff check`, `aff close-batch`, and `aff verdict`. Reviewer and suite move into an `orchestra` package. `affidavit/tier2.py` and the `tier2_*` aliases are deleted. Skill slugs stay. The bundled contract's `"project"` becomes `orchestra`, and ensure-store rewrites an existing `affidavit` project field to that. Records for `dashboard`, `workflow-loop`, `packaging`, `session-analysis`, and `test-suite-speed` move to the orchestra store. This store keeps `evidence-layer`.

Skills call `aff check` for `tdd` and `check` results and `aff verdict` for a claim in the manifest. They do not create those check-runs or a `project:oracle-amendment`. Task, phase, and store commits use a Conventional Commits subject, `type(scope): summary`, and a one- or two-sentence body on why. A task commit names the task slug in the body.

Tasks, in dependency order:

1. `extract-store-binding` copies store binding into `affidavit/aa_resolve.py` so `affidavit.aa` no longer imports `dashboard`.
2. `scaffold-orchestra` creates `~/orchestra` and commits the moved tree there. It depends on 1 so it copies `tests/` only after `affidavit.aa` no longer imports `dashboard`. `dashboard/artifact_store.py` stays the dashboard's own copy.
3. `strip-affidavit`, `rewrite-project-field`, and `skill-evidence-boundary` depend on 2. They share no files: deletions stay in this repo, the project-field rewrite owns `contract/project-design.json` and `skills/ensure-store.md` in orchestra, and the boundary edits own `skills/execute-phase` and `skills/verify-work` there.
4. `conventional-commits` depends on 3's skill and ensure-store edits. It rewrites the commit snippets in those two files.
5. `move-effort-records` depends on the project-field rewrite and on the strip. It is inline: it relocates store files, which only this session writes.
6. `verify-orchestration-split` depends on every other task.

**Session shape:** more than one
**Elapsed estimate:** 100 minutes (wave 1: 10, wave 2: 25, wave 3: 20, wave 4: 10, wave 5: 20, wave 6: 15)
**Executor:** subagent, except wave 5 (`move-effort-records`), which is inline
**Human stops:** plan review; Landing merge into `main` (no push)
**Collision notes:** Wave 3 splits three ways. `strip-affidavit` deletes `skills/`, `dashboard/`, `scripts/`, `agents/`, `affidavit/reviewer.py`, `affidavit/suite.py`, `affidavit/tier2.py`, and the tests that moved, all under this repo. `rewrite-project-field` edits only `~/orchestra/contract/project-design.json`, `~/orchestra/skills/ensure-store.md`, and `~/orchestra/tests/test_ensure_store_project.py`. `skill-evidence-boundary` edits only `~/orchestra/skills/execute-phase/SKILL.md`, `~/orchestra/skills/verify-work/SKILL.md`, and `~/orchestra/tests/test_skill_evidence_boundary.py`. Wave 4 edits the commit snippets in the two skill files wave 3 already finished. Wave 5 moves record directories under `.artifacts` and does not edit those skill files. Orchestra's own commits land in `~/orchestra`. This repo's code commits land on the phase branch below.

## Exit criteria

- `bin/aff check --help`, `bin/aff close-batch --help`, and `bin/aff verdict --help` exit 0, and this repo's remaining pytest files pass with `skills/`, `dashboard/`, `scripts/`, and `agents/` absent.
- `~/orchestra` contains `skills/engage`, `skills/discuss`, `skills/plan-phase`, `skills/execute-phase`, `skills/verify-work`, `skills/init`, `skills/analyze-sessions`, and `dashboard/`. `orchestra.reviewer` and `orchestra.suite` import. Neither repo defines a `tier2` module.
- A test in the orchestra repo fails when a skill file creates or corrects a `project:check-run` with method `tdd` or `check`, or creates or supersedes a `project:oracle-amendment`, and passes on the migrated skills.
- `execute-phase` and `verify-work` run `aff verdict` for a claim in `.affidavit/manifest.json` and treat a non-zero exit as not done.
- A fixture store whose `"project"` is `affidavit` is rewritten to `orchestra`. A fixture whose project is any other name is left unchanged.
- `adaptive-artifacts validate` passes in both stores. The active goal in this store is `evidence-layer`. The active goals in the orchestra store are `dashboard`, `workflow-loop`, `packaging`, `session-analysis`, and `test-suite-speed`.
- `execute-phase` shows a per-task commit, a phase-branch commit, and a store commit whose subject matches `type(scope): summary` and whose body is one or two sentences. A task commit's body names the task slug.
