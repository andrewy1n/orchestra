## Interfaces

ci.yml gains a blocking wheel job (checkout, setup-uv on Python 3.10, python3 scripts/wheel_smoke.py). scripts/wheel_smoke.py [--wheel PATH] builds the wheel from git archive HEAD in a temp dir with uv build --wheel (unless --wheel is given), installs it into a new venv, and runs orchestra --help, canon --help, canon init and canon validate in a temp git repo, orchestra install --list (must name claude), and the imports dashboard, dashboard.backend.server, installer and installer.adapters, always from a working directory outside the checkout. It exits non-zero for a wheel without installer/providers.json and leaves the checkout unchanged. README.md has a Wheel check section naming the command.

## Assumptions

R15 named dashboard.web, which no longer exists on main; the script and tests import dashboard.backend.server (the test id test_wheel_smoke_r15_import_dashboard_web is kept). The script builds from committed content, so a dirty tree is not smoke-tested locally.

## Invariants

Every other ci.yml job stays blocking. The local and CI command are the same string. No check runs with the checkout as cwd or on sys.path. The script adds no dependency.
