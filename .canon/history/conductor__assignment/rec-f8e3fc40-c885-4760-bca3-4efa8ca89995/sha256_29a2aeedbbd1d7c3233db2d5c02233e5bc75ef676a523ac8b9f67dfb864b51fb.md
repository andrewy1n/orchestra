### Work-item (quote)

## Description

R1: `GET /api/areas` returns every active `composer:area` with its subject, title, and scope text.
R2: Each area in the response lists the ideas whose `payload.area` equals the area subject.
R3: The idea list includes ideas with status `open` or `promoted` and excludes `dismissed` and superseded ideas.
R4: An idea with both an effort and an area appears in the area's list and in the effort's backlog.
R5: Each idea in the response carries its area and its effort.
R11: A store with no `composer:area` records returns an empty list from the endpoint.
Context: `dashboard/backend` has loaders (`snapshot.py`, `task.py`, `phase.py`, `journal.py`, `records.py`) that read the store only through `store.py`; `dashboard/backend/server/schemas.py` holds the Pydantic response models and `app.py` the FastAPI routes; `scripts/api_schema.py` writes `dashboard/frontend/openapi.json` and `npm run api-types` generates `dashboard/frontend/src/api-types.ts`; `tests/dashboard/test_endpoint_shapes.py` pins every route with a fixture and fails when a route has no case. The UI is in `dashboard/frontend` (Svelte 5, state modules in `src/lib/state`, screens in `src/lib/screens`, shadcn-svelte components in `src/lib/components/ui`, router in `src/router.ts`, regex-based Vitest files read UI source through `src/appSource.ts`). `composer:area` has a `title` and a `## Scope` section; `composer:idea` has `status` (open, promoted, dismissed) and optional `area`, `effort`, `phase`, `source`. The effort backlog (open ideas, with promote and dismiss) must not change. The lint gate stays at zero findings.

## Approach

Add `dashboard/backend/areas.py` with `load_areas(target)`: read `composer:area` and `composer:idea` through `store.py` (soft types: a store without `composer:area` returns an empty list), group ideas by `payload.area`, and return area views (`subject`, `title`, `scope`, `open_count`, `ideas`; each idea: `subject`, `text`, `status`, `area`, `effort`, `phase`). `scope` is the body's `## Scope` section (use `records._section`). Add Pydantic models to `server/schemas.py` and the route `GET /api/areas` to `app.py` with a `response_model`; wire it through the server's `Reader`/cache like the other routes. Open ideas sort before promoted ones, then by recorded time. Do not change the effort backlog in `snapshot.py`. Regenerate `openapi.json` (`uv run python scripts/api_schema.py`) and `src/api-types.ts` (`cd dashboard/frontend && npm run api-types`). Add a case and fixture for `/api/areas` to `tests/dashboard/test_endpoint_shapes.py` (rich store: seed one area with scope text and ideas in each state, plus an idea with both effort and area; minimal store: none) using `UPDATE_FIXTURES=1` only for the new fixtures; existing fixtures stay byte-identical. Run `uv run pytest tests/dashboard -q -n 4`, `uv run python scripts/api_schema.py --check`, `cd dashboard/frontend && npm run lint && npm run check && npm test`, `uv run basedpyright`.
