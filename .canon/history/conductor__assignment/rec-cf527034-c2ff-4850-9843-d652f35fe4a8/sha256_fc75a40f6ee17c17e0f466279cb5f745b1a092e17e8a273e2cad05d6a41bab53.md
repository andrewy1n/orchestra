## Approach

1. Add `affidavit/audit.py`: split `git diff -U0 base head` into hunks, drop `.artifacts/**`, test files, and prose per decision `audit-interface`, and keep for each block the file, new-file start/end lines, and added text.
2. For each block, create a detached worktree at `head` (like `affidavit/verdict.py` does), reverse-apply that single hunk with `git apply -R`, run the claim tests with `affidavit.runner.run_tests` and the manifest runner, and label the block: `noticed` when any claim test that passed at head is `assertion_failed` after the revert, `not_noticed` when all still pass, `inconclusive` when the patch does not apply, errors dominate, or no claim test passes at head. Remove the worktrees after use.
3. Claim tests: union of the head manifest's claim tests (`affidavit.manifest.load_manifest`, absent manifest means none) and each `--test` id.
4. `affidavit/cli.py`: add `aff audit` printing the JSON object `{"advisory": true, "base", "head", "blocks": [...], "mutants": [], "survivors": []}`; exit 0, or 2 on usage or git errors.
5. The audit does not change `aff verdict`. Do not edit `tests/test_audit.py` (frozen oracle) or any existing test.

### Design / decisions (quote)

#### Invariants
- Never target test-file blocks.
- Advisory only for verdict.

#### Assumptions
- frozen claims and runner path are stable.

- `audit-hunk-mutants`: productize spikes/hunk-revert and capped mutants into advisory aff audit --base --head that judges with frozen claim tests via run_tests; never report test-file blocks
- `audit-interface`: aff audit --cwd DIR --base REV --head REV [--test NODE ...] [--mutants FILE] [--max-mutants N] prints one advisory JSON object and exits 0 (2 on usage or git errors). Claim tests are the tests of every claim in the head manifest plus any --test ids; the runner is the head manifest runner or the default. Blocks are the hunks of git diff -U0 base head, excluding .artifacts/**, test files (a path component tests or test, basename test_*.py, *_test.py, conftest.py) and prose (.md .rst .txt or under docs/). Each block is {file,start,end,label,text} with new-file lines and the added text; label is noticed when reverting the block makes a claim test fail an assertion, not_noticed when every claim test still passes, inconclusive otherwise. Only claim tests that pass at head can notice. Mutants come from a JSON file {mutants:[{id,file,patch:{old,new}}]}; a mutant is planted only when patch.old occurs in a noticed block of that file, and is reported as {id,file,status} with status killed, survived, invalid, or skipped. The output lists blocks, mutants, and survivors (ids); verdict is unaffected
