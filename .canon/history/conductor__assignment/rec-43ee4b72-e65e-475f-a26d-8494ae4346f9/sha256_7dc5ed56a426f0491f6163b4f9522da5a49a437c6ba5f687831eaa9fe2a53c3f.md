`run_tests` is already in `affidavit/runner.py`. `Manifest.runner` is already loaded in `affidavit/manifest.py`. `pytest.ini` skips tests marked `tmux`. Run pytest from the worktree.

R1: `aff verdict` judges witness tests through `run_tests`. Each requested id comes back as `passed`, `assertion_failed`, `errored`, or `not_run`, read from the JUnit XML the runner wrote. Verdict does not parse pytest's stdout.

R3: A `<failure>` element makes the case `assertion_failed`. An `<error>` element makes it `errored`. A `<skipped>` element, or a requested id with no matching case, is `not_run`. A case with no failure, error, or skipped child is `passed`. A case that has both a failure and an error is `errored`. A claim's base is an assertion red only when every witness id is `assertion_failed`. The head passes only when every witness id is `passed`. Allowlist, amendment, missing-claim, and hash-mismatch failures stay as they are.

R4: After the first run, each claim whose witnesses are all `assertion_failed` at base and all `passed` at head is confirmed. One more run at that revision, in the same worktree, covers the ids that confirmation needs. A witness whose second outcome differs makes its claim `unstable`. The verdict result is `fail` when any claim failed, `unstable` when any claim is `unstable` and none failed, and `pass` otherwise. The process exits 0 only for `pass`.

R5: A JUnit case matches a witness id when its `name` equals the id, or when its `file` attribute is present and `file`, the classname segments after the dotted file stem, and `name` join with `::` to the id. A command that emits matching JUnit is judged with no change under `affidavit/`.
