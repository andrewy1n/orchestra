### Work-item (quote)

R2: The `composer` schema module has version `1.0.0`.
R5: `canon create --type composer:area` with payload `title` and a `## Scope` body succeeds.
R6: `canon create --type composer:area` without a `## Scope` section is refused.
R7: `canon create --type composer:idea` with only `status` in the payload succeeds.
R8: A `composer:idea` `status` outside `open`, `promoted`, `dismissed` is refused.
R9: A `composer:idea` `area` that names no `composer:area` subject is refused.
R10: A `composer:idea` `effort` that names no `score:effort` subject is refused.
R11: A `composer:idea` `phase` that names no `score:phase` subject is refused.
R12: `canon supersede` on a `composer:idea` writes a successor with the same subject and the new `status`.

Approach: Create `orchestra/composer/` with `__init__.py`, `AGENTS.md` (composer imports only canon and score) and `schemas/__init__.py`. Write `schemas/composer.json` at version 1.0.0 with `composer:area` (lifecycle `current`, field `title`, section `Scope`) and `composer:idea` (lifecycle `current`; `status` enum open|promoted|dismissed; optional `area`, `effort`, `phase` refs and `source` string). Model the JSON on `orchestra/score/schemas/score.json`. In `pyproject.toml` add `orchestra.composer` and `orchestra.composer.schemas` to `packages`, `"orchestra.composer" = ["schemas/*.json"]` to package data, and `composer = "orchestra.composer.schemas"` to the `canon.schemas` entry points. Run the oracle tests in `tests/test_composer_schema.py` with `CANON_SCHEMA_PATH` including `composer.json`.
