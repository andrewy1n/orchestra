### Work-item (quote)

## Description

R4: `aff verdict` accepts a claim witnessed by a valid allowlist signature (human-signed claim) when the signature verifies.
R5: `aff verdict` rejects a human-signed claim witness that is missing or does not verify.

## Approach

1. Add `affidavit/human_claim.py` with the canonical bytes `affidavit-claim v1\nclaim: <id>\ntext: <text>\n` and a verify function that uses `ssh-keygen -Y verify` in namespace `affidavit-claim` against the allowlist bytes (principal discovery like `affidavit/amendment.py`).
2. `affidavit/manifest.py`: `Claim` gains optional `witness` (default `tests`, or `human`) and `signature` (string). A human claim needs no tests or oracle hashes.
3. `affidavit/verdict.py`: a claim whose head manifest entry has `witness` `human` passes only when its signature verifies against `.affidavit/allowed_signers` at `--at`. Absent or empty signature fails with reason `human signature missing`; a signature that does not verify fails with `human signature invalid`. Such a claim skips red/green test execution. Automated claims are unchanged.
4. Do not edit `affidavit/cli.py`, `affidavit/lint.py`, `affidavit/authoring.py` (claim-cli owns them), `tests/test_claim_authoring.py` (frozen oracle), or any existing test.
