## Approach

Read the frozen tests in `dashboard/frontend/src/lib/screens/phaseNav.test.ts` first. They mount `App` and fix the selectors.

- In `src/lib/state/areas.ts` add `routePhase(route, efforts)`. It returns the effort and the phase row for a `phase` route (`parts[1]` effort, `parts[2]` phase subject), or null. Extend `Rail.level` with `"phase"`. `railItems` returns, for a phase route, the phases of the effort in `ordinal` order: label is the title or the subject, href is `phaseHref`, `current` marks the route phase, `finished` is true for state `done`.
- `breadcrumbParts` for a phase route returns the effort crumb as a link, then the phase title (or subject) as the last, unlinked crumb. The area crumb is present only when the effort has an area.
- `Rail.svelte`: for level `phase` the heading is the effort name. Fold the done phases other than the current one behind a button, as the effort level folds finished efforts. Keep the button state local to the component.
- `App.svelte`: the side rail stays effort-level only. The rail toggle label reads `Phases` at the phase level.
- `src/lib/state/keys.ts`: Esc on a `phase` route, with no leaf modal and no pending write, calls `openHash(effortHref(<route effort>))`.
- Update any `area-levels` test that asserts the effort-level rail or breadcrumb on a phase route.
- Close with `npm run lint`, `npm run check`, `npm test`.
