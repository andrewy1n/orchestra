## Requirements

R1: Every advertised skill directory contains all files its instructions reference; no referenced path leaves the directory.
R2: The shared `ensure-store.md` and `kinds-and-focus.md` text is generated into each skill's `references/` from one source.
R3: A drift check fails when a generated `references/` copy differs from its source.
R4: Every `SKILL.md` passes Agent Skills frontmatter validation: `name` equals its directory and `description` is non-empty.
R5: `orchestra` installs as a console script and runs from PATH in an unrelated working directory.
R6: No skill body names a checkout path or `<plugin>` root for a runtime call.
R7: `orchestra` provides `contract`, `project-field`, and `sessions` subcommands covering what skills currently reach for by file path.
R8: One installer accepts `--only`, `--all`, `--global`, `--copy`, `--dry-run`, and `--uninstall`.
R9: Re-running the installer leaves exactly one registration per selected host.
R10: The installer installs native payloads for Claude Code, Cursor, and OpenCode.
R11: The installer delegates at least one non-native host to `npx skills add` and reports the profile used.
R12: Claude, Cursor, and OpenCode hook adapters are installed when supported, and installation still succeeds when they are absent.
R13: The reviewer agent is generated per host from one canonical prompt and restriction set.
R14: The installer never copies `.artifacts/`, `.worktrees/`, or dashboard/store state.

## Acceptance criteria

- `tests/test_skill_portability.py` proves R1-R4 and R6, including a planted `../` reference that must fail.
- `tests/test_cli_packaging.py` installs the package into a temporary prefix, then runs `orchestra contract`, `orchestra project-field`, and `orchestra sessions` from an unrelated cwd (R5, R7).
- `tests/test_installer.py` covers every flag, idempotency, native payloads, tail delegation, and the copy allowlist (R8-R11, R14).
- `tests/test_agent_generation.py` proves one canonical prompt produces host-correct frontmatter (R13).
- A temporary-HOME install for Claude and OpenCode loads the generated skill dirs, and `npx skills add --list` resolves a generic profile (R11, R12).
- README documents the host matrix, the install commands, and the CLI install (R5, R11).

## Constraints

- `bin/orchestra` stays as a shim so checkout and plugin installs keep working.
- Skill workflow logic does not change; only paths, packaging, and generated copies do.
- `uv` is the documented CLI installer; PyPI publishing stays deferred.
- The installer must be safe to re-run on an existing install.
- The parent session remains the only store writer.
- Current Claude and Cursor manifests keep their shape and remain valid.

## Non-goals

- Publishing `orchestra` to PyPI.
- A version-compatibility gate or release tagging (parked by decision).
- Dashboard, tmux, or Textual changes.
- A native adapter for every harness.
- Rewriting the skills' process or record vocabulary.

## Invariants

- Generated `references/` files are copies of one source and are never edited in place.
- The `orchestra` CLI is the only runtime surface the skills assume.
- `adaptive-artifacts` is the only store writer; subagents never write records.
- Existing checkout and plugin installs keep working unchanged.

## Assumptions

- `npx skills add` remains available with the profile ids named in the installer.
- Each host discovers `SKILL.md` at its documented skills path.
- `uv` is available for the CLI install.
- OpenCode supports a `skills` source entry and `agents/*.md`.
- The Claude and Cursor plugin manifests keep their current schema.
