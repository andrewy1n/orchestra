## Requirements

R1: `orchestra/canon/backend.py` defines a `Backend` protocol that declares every storage operation used by `Project`, `validation`, `merge`, `sync`, `migrate` and the `canon` CLI.
R2: `Store` implements `Backend` with its on-disk layout unchanged.
R3: `open_store` and `Project` obtain a backend from the store config and call only `Backend` methods.
R4: `validation.py`, `merge.py`, `sync.py`, `migrate.py` and `cli.py` call only `Backend` methods and build no path under the store root.
R5: `orchestra init` creates the store through the backend factory, not through `Store(...)` directly.
R6: `dashboard/backend/store.py` lists records through the `Project` API, not `os.scandir`.
R7: A record reference in a derived view shows the record id and links to no file path.
R8: A test fails when a module outside `orchestra/canon/` imports `Store` or builds a path under the store root.
R9: `canon list --full` on the real store prints the same output before and after the phase.
R10: `canon validate` passes on the real store.
R11: A store config with no `backend` key selects the file backend.

## Acceptance criteria

- R1, R2, R3, R4, R5, R6, R11: unit tests in `tests/canon` for the protocol conformance, the factory and each caller.
- R7: `tests/test_views.py` asserts the view output has no `.canon/` link.
- R8: the boundary test passes on the final tree and fails on a seeded violation.
- R9: a script captures `canon list --full` before and after and diffs the two files (command run).
- R10: `canon validate` exits 0 (command run).

## Constraints

- The file backend's behaviour and on-disk format do not change.
- The protocol carries only operations that a caller uses today. No speculative methods.
- No new dependency.

## Non-goals

- Any SQLite code.
- Changing the file format or the op-log semantics.
- `orchestra/sessions/*` use of `~/.canon`, which looks unrelated to the repo store. Plan-phase confirms this.
- `orchestra/tuner/audit.py` path rule for `.canon/`.

## Invariants

- No method signature in `Backend` takes or returns a file path.
- Output of `canon list --full` on the real store is unchanged.

## Assumptions

- Most of the 35 importers already use `Project`. Plan-phase counts the exact `Store` users first.
- The existing 18 test files that assume the file layout keep passing against the file backend.
