## Requirements

R1: The composer schema defines a `placement` type with a required `area` field that refs `composer:area`.
R2: `orchestra place <effort> <area>` creates an active `composer:placement` whose subject is the effort slug.
R3: `orchestra place` on an effort that already has a placement supersedes it and leaves one active placement.
R4: `orchestra place` exits nonzero and writes nothing when the effort does not exist.
R5: `orchestra place` exits nonzero and writes nothing when the area does not exist.
R6: Each effort row of `GET /api/snapshot` carries `area`: the placed area subject, or an empty string when the effort has no placement.
R7: The committed `dashboard/frontend/src/api-types.ts` matches the generated API schema, including `area` on the effort row.
R8: The `engage` skill names `orchestra place` as the step that gives a new effort its area.
R9: `canon validate` passes on a store that holds placements.
R10: After the backfill, every effort in the user-confirmed mapping has an active placement that names its mapped area.

## Acceptance criteria

- R1, R2, R3, R4, R5, R9: tests in `tests/test_composer_placement.py` build a temporary store, run `orchestra place`, and read the records.
- R6: a test in `tests/dashboard/test_endpoint_shapes.py` seeds a placement and reads the snapshot.
- R7: `npm run api-types:check` passes.
- R8: a skill text test finds `orchestra place` in `skills/engage/SKILL.md`.
- R10: a manual check. The user confirms the mapping, the backfill runs, and the user signs that `canon list --type composer:placement` matches the mapping.

## Constraints

- `orchestra/composer` imports only `canon` and `score`.
- The dashboard does not write placements. Writes go through the CLI. Active constraint `dashboard-human-gate-writes` still limits dashboard writes.
- Tests build temporary stores. They never write the real `.canon/` store.
- The committed store snapshot of the composer schema is refreshed with `canon schemas sync`.

## Non-goals

- Any dashboard page, card, chip or breadcrumb. Phase `area-pages` builds them.
- A command that removes a placement.
- More than one area per effort.
- Changing how ideas are captured, triaged or promoted.
- Creating new areas for the unassigned efforts.

## Invariants

- An effort has at most one active placement.
- The placement subject equals the effort slug.
- `area` in the snapshot is an empty string for an unplaced effort. It is never missing.

## Assumptions

- Canon rejects a second active record with the same type and subject.
- `orchestra place` checks that the effort and the area exist itself, and does not rely on ref validation alone.
