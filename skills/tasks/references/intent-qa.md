# Intent Q&A

Use this guide during specification and design work. Read relevant context
before you ask the user for information.

## Read

- Read the active phase, its prerequisites, and current effort context.
- Read the approved specification before design work.
- Read relevant code and system constraints before technical questions.
- Read existing decisions, constraints, and assessments that affect the phase.

Do not ask the user to repeat information already present in the current
records or code.

## Reflect

State the user's goal in plain terms. Separate known facts from assumptions.
Name the decisions that can change behavior, cost, scope, or recovery.

Ask an open question when a necessary fact is unknown. Offer concrete options
only when the user must choose between real alternatives.

## Ask

Ask one focused question at a time. Say why the answer changes the result.
Keep choices distinct and include the practical trade-off for each.

Do not ask about implementation details before you check the code or current
technical facts. Research unstable or unfamiliar facts before asking the user
to choose a preference.

## Test answers

Check each answer against the goal, current records, constraints, and earlier
answers. Name conflicts and ask about the smallest unresolved choice.
Preserve settled choices unless the user changes them.

Do not infer approval from silence, a partial answer, or a request to continue.
Ask for approval of the complete specification or design before recording it.

## Present once

After the open choices are settled, present the complete proposed artifact.
State its scope, assumptions, invariants, risks, and unresolved items. Ask for
approval or explicit delegation to record it.

After the user approves, write only the artifact owned by the current step.
Record the matching workflow review only when the user explicitly approves or
delegates. Do not create work-items from either discussion step.
